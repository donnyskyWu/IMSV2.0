# IMSV2.0 开发 + 验证方法：垂直切片与左移门禁

> 适用：IMSV2.0（及同类多模块、强门禁的 AI 协作研发）  
> 版本：2026-10-13  
> 状态：暂停开发期间定稿，恢复开发后生效  
> 目的：一次交付可演示的完整路径；把门禁前移，减少「半成品 → 打回」轮次；验证保留但变薄。

---

## 0. 为什么换方法

本批实证反复出现的问题：

1. **先逻辑、后界面**：API 先通，原型文案/按钮/Tab/抽屉后补。  
2. **种子欠账**：菜单、字典只在单测夹具，真库 `/me` 无入口或 `require_dict`→1503。  
3. **鉴权未对齐 main**：1002/1216、session、perm_ver 多轮才补。  
4. **业务边角半成品**：交互错误分支写错、DEPT 口径冲突、空壳/弱断言用例。  
5. **工程债**：Vite `optimizeDeps`、列长与截断不一致、合 main 冲突拖死 CI。  
6. **流程放大慢**：代理多轮自修甚至自合入；并行过多导致冲突。

结论：问题不在「要不要 E2E」，而在 **半成品出了门、用打回当质检**。  
验证仍然需要——用来压契约漏网与集成风险，不是用来发现「还没做界面」。

---

## 1. 原则（五条）

1. **垂直切片**：数据 → 逻辑 → 页面 → UI → 交互 同一切片一次做完，可演示。  
2. **左移门禁**：实现理解与首推就必须完整；禁止「逻辑先合再补皮」。  
3. **契约优于感觉**：勾选清单是硬门，不是参考。  
4. **开发自测做满**：提审前本地/CI 自测绿；外部验证变薄。  
5. **验证不取消**：技术 / 产品 / 小红 / 小蓝 / CI 仍在，但不应反复发现「没种子、没 UI」。

---

## 2. 角色

| 角色 | 职责 |
|------|------|
| 产品经理 | 工作包、Q 裁决草稿、实现理解产品复核、原型口径 |
| 云端编码代理 | 单模块一 PR：理解 → 全栈 → 自测；**禁止自合入** |
| Grok Bot（协调） | 契约审核、技术复审、合入、在途节奏（≤2 个编码 PR） |
| 测试小蓝 | 自动化、覆盖率、CI |
| 测试小红 | 真起服务功能验收 + UI/原型硬门禁 |
| who kong | PRD 冲突裁决、批次效果审、暂停/恢复 |

默认模型：`grok-4.7`。

---

## 3. 端到端阶段

### 阶段 A：工作包与裁决

1. 产品输出工作包 00/01/02 + 待决 Q。  
2. 不与 PRD 冲突的，由产品经理 + Grok Bot 直接裁定并落文档。  
3. 与 PRD 冲突的，升级 who kong。  
4. **未决 Q 不准开工。**

### 阶段 B：实现理解（硬门，最多 2 轮）

实现理解必须覆盖下列维度，**缺一即 FAIL，不准写业务代码**：

| # | 维度 | 最低要求 |
|---|------|----------|
| 1 | 数据 | 表/迁移/软删/字段约束（含列长） |
| 2 | 逻辑 | 用例、状态、错误码、与上下游模块边界 |
| 3 | 页面 | 路由、菜单树、权限码、入口 |
| 4 | UI | 对照原型：结构、组件、文案、多屏 |
| 5 | 交互 | 主路径 + 失败路径（含业务错误码如 1504） |
| 6 | 种子 | menus + dicts **进入 seed runner**；授权后 `/me` 可见入口 |
| 7 | 对齐 | 鉴权中间件、perm_ver、session；框架组件复用清单 |
| 8 | 自测计划 | 单测 / Playwright / live-proxy 各覆盖什么 |

文档评审规则：

- 原则问题（行为错、安全、缺测试门禁）→ 打回文档。  
- 小项可带进代码 PR，但必须有测试托底。  
- 最多 2 轮；通过后立即编码。

### 阶段 C：编码（同一 PR、固定顺序）

**强制顺序（反「先逻辑」）：**

1. 迁移 + **种子（菜单 / 字典 / 授权）**  
2. 页面骨架 + 路由（对照原型，先能看见）  
3. API + 领域逻辑（前端只走 API 层，禁止直连 `/admin-api`）  
4. 交互与异常路径  
5. 单测 / 组件测 / E2E（禁止新增 skip；禁止空壳 assert）  
6. live-proxy 绿；新增 Element Plus 样式写入 Vite `optimizeDeps.include`

**禁止：**

- 只交后端或「逻辑先过」  
- 字典/菜单仅存在于 UT 夹具  
- 空壳 pass / 名存实亡用例  
- 云端代理自行合入  

### 阶段 D：开发自测（提审前必绿）

| 层 | 要求 |
|----|------|
| 快 | 单测含鉴权 1002/1216、截断与真实列长、关键边界 |
| 中 | P0 分支覆盖达标；组件/API 契约无空壳 |
| 慢 | Playwright（功能 + UI/原型硬门，至少 desktop-chromium）；真库 seed 后登录可见菜单并走通主路径 |
| 工程 | 与 main 无冲突；live-proxy 不因 Vite reloading 失败 |

**自测不过 = 不提审。**

### 阶段 E：外部验证（变薄、可并行）

1. **技术复审**：diff ↔ 实现理解 / AGENTS；种子、UI、鉴权缺失直接 FAIL。  
2. **产品复核**：原型 + Q 项。  
3. **小红 / 小蓝**：真起服务 + 自动化；CI 全绿。  
4. **合入**：仅 Grok Bot；条件 = 技术过 + 产品过 + 双方验收过 + CI 全绿。  

**打回纪律：** 同一类 UI/种子问题第二次出现 → **停该模块复盘**，不无限打回。

### 阶段 F：批次节奏

- 同时在途**编码 PR ≤ 2**。  
- 约定批次（如 B1+B2+B3+B5+B18+B21）全部合完 → 暂停 → who kong 看效果 → 再开下批。  
- 暂停期间不新开模块、不停已合入的 main。

## 4. 模块 Definition of Done

- [ ] 实现理解已通过（含上表 8 维）  
- [ ] 数据 + 逻辑 + 页面 + UI + 交互在同一 PR  
- [ ] 种子进 runner；真库 `/me` 有入口  
- [ ] 鉴权对齐 main  
- [ ] 无新 skip；无空壳用例  
- [ ] live-proxy 与 lint/test 全绿  
- [ ] 技术 + 产品 + 小红 + 小蓝通过  
- [ ] 已由协调人合入（非代理自合）

## 6. 与「外面常见 AI 开发」的差别

| | 常见 AI demo | 本方法 |
|--|-------------|--------|
| 完成标准 | 能跑 / 有 diff | 垂直切片可演示 + DoD |
| 测试 | 常无 E2E | 自测含 E2E；外部验收保留 |
| UI | 后补 | 首推必须有 |
| 合入 | 代理或作者随意 | 协调人按门禁合 |
| 速度来源 | 少验证 | 少返工（门禁前移） |

对 IMSV2.0 这类要鉴权、种子、真库的系统，应采用本方法，而不是「能跑就行」。

## 7. 落地建议

1. 将本文纳入仓库 `docs/`（或 `AGENTS.md` 引用），恢复开发后强制执行。  
2. 每个新模块实现理解 PR 附带第 5 节勾选表。  
3. 云端代理启动提示词中粘贴：编码顺序、禁止自合、自测清单。  
4. 协调人周更：在途 PR 数、打回原因分类（UI/种子/鉴权/CI），用于复盘。
