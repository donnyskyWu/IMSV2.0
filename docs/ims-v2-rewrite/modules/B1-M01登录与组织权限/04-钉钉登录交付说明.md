# B1 PR3 钉钉登录

> 数据库连接见环境变量。本文不记录主机或库名。

## 本 PR 做了
- FP-B1-LG-01：`GET /admin-api/ims/auth/login-options`（匿名）。返回是否启用钉钉、corpId、clientId，不返回密钥。
- FP-B1-LG-04：`GET /admin-api/ims/auth/sso/dingtalk/authorize-params`，以及既有跳转接口的 32 位一次性 state（5 分钟）。
- FP-B1-LG-05：回调成功 302 到 `/sso-callback#accessToken&refreshToken&redirect`；失败 302 到 `/login?ssoError=<码>`。取消或拒绝授权回到 `/login`，不带错误码。授权码参数认 `authCode`、`auth_code` 和 OAuth 的 `code`。
- FP-B1-LG-06：`POST /admin-api/ims/auth/sso/dingtalk/h5-login`。匹配、租户停用、冻结/离职与扫码相同。
- FP-B1-LG-09：登录日志仍用 `login_method`、`result`。渠道为 `DINGTALK_QR` / `DINGTALK_H5`，失败时 `result` 写入错误码。不加列，不做迁移。

未映射时先按钉钉企业 userid，再按手机号。扫码换票拿到的 unionId / openId 不直接当 userid，要再调钉钉接口解析出企业 userid，再对 `dingtalk_user_id`。解析失败 1006，超时 5003。手机号为空、没有命中、命中多个、或该用户已绑定别的钉钉号，都是 1217。账号密码的锁定计数不读不写。

## 本 PR 不做
- 组织同步、岗位与角色供给，以及其它模块。
- 登录页、扫码组件、H5 过渡页、`ssoError` 文案。接口已给出，页面仍是 B0b 占位。

## 阻塞
FP-B1-LG-07 新员工首登即时同步。规格要求映射和手机号都未命中时，先按人员同步规则建本地用户、写同步事件，并触发岗位供给。建用户和岗位供给属于后面的组织同步、岗位供给 PR。本 PR 在这里停住：不创建用户，直接 1217。

## 错误码
| 情况 | 码 |
|---|---|
| state 无效、过期或重放 | 1002 |
| 钉钉接口错误、身份缺少 userid | 1006 |
| 钉钉未启用；租户停用；须改密名单外的接口 | 1008 |
| 冻结或离职 | 1216 |
| 未映射、空手机号、手机号命中多个 | 1217 |
| 映射与用户不在同一租户 | 1504 |
| 钉钉超时 | 5003 |
