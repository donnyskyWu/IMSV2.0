## 2. API 契约

### 2.1 新增接口（14 个）

#### 2.1.1 组织同步概览

```
GET /admin-api/ims/auth/org/sync-metrics
```

**权限**：`ims:system:org-sync:query`

**响应**：
```json
{
  "code": 0,
  "data": {
    "userTotal": 1234,
    "yesterdayEventCount": 56,
    "pendingEventCount": 3,
    "deadEventCount": 1,
    "avgDelayMinutes": 2.5,
    "p95DelayMinutes": 4.8,
    "successRate24h": 0.98,
    "dingtalkUnavailable": false,
    "reconcileFailedTwice": false
  }
}
```

**规则**：
- `userTotal`：状态为在职（ACTIVE）或冻结（FROZEN）的用户数，不含离职
- `avgDelayMinutes`：最近 24 小时成功事件的 `(processed_time - event_time)` 平均值，保留 1 位小数
- `dingtalkUnavailable`：最近 10 分钟内有钉钉调用超时（5003）记录
- `reconcileFailedTwice`：最近两个对账批次均失败

#### 2.1.2 同步差异汇总

```
GET /admin-api/ims/auth/org/diffs/summary
```

**权限**：`ims:system:org-sync:query`

**响应**：
```json
{
  "code": 0,
  "data": {
    "overrideCount": 5,
    "pendingAssignCount": 2,
    "localOrphanCount": 1,
    "sameNameCount": 0,
    "unboundCount": 10
  }
}
```

#### 2.1.3 同步差异列表

```
GET /admin-api/ims/auth/org/diffs?category=OVERRIDE|PENDING_ASSIGN|LOCAL_ORPHAN|SAME_NAME|UNBOUND&keyword=&startTime=&endTime=&pageNo=1&pageSize=10
```

**权限**：`ims:system:org-sync:query`

**参数**：
- `category`（必填）：差异类别
- `keyword`：姓名/工号/部门名模糊搜索
- `startTime`/`endTime`：时间范围（仅 OVERRIDE、SAME_NAME 类型）
- `pageNo`/`pageSize`：分页

**响应**：分页列表，字段根据 category 不同而不同

#### 2.1.4 同步事件列表

```
GET /admin-api/ims/auth/org/events?keyword=&deptId=&eventTypes=&statuses=&startTime=&endTime=&pageNo=1&pageSize=10&sortBy=eventTime&sortOrder=desc
```

**权限**：`ims:system:org-sync:query`

**参数**：
- `keyword`：姓名/工号/事件ID 模糊搜索（≤50 字）
- `deptId`：部门过滤（不含下级）
- `eventTypes`：事件类型多选（逗号分隔）
- `statuses`：同步状态多选（逗号分隔）
- `startTime`/`endTime`：事件时间范围，默认最近 7 天，跨度 ≤90 天
- `sortBy`：`eventTime` 或 `processedTime`
- `sortOrder`：`asc` 或 `desc`

**响应**：
```json
{
  "code": 0,
  "data": {
    "total": 100,
    "list": [
      {
        "id": "123456789012345678",
        "eventType": "HIRE",
        "eventId": "event_xxx",
        "subjectName": "张三",
        "empNo": "E1001",
        "beforeDeptNames": null,
        "afterDeptNames": "市场一部",
        "status": "SUCCESS",
        "retryCount": 0,
        "eventTime": "2026-10-12T10:00:00+08:00",
        "processedTime": "2026-10-12T10:00:05+08:00"
      }
    ],
    "pageNo": 1,
    "pageSize": 10
  }
}
```

**错误码**：
- `1001`：时间范围超过 90 天

#### 2.1.5 事件详情

```
GET /admin-api/ims/auth/org/events/{id}
```

**权限**：`ims:system:org-sync:query`

**响应**：包含事件基本信息、脱敏后的原文 JSON、处理时间线（attempts）

**错误码**：
- `1504`：事件不存在或超出数据范围

#### 2.1.6 单条重试

```
POST /admin-api/ims/auth/org/events/{id}/retry
```

**权限**：`ims:system:org-sync:run`

**请求头**：`X-Client-Token`（幂等）

**规则**：
- 事件状态为 `SUCCESS` 或 `PENDING`（处理中）时不能重试 → `1286`
- 同一事件 10 秒内重复点击只处理一次

**错误码**：
- `1286`：事件状态已变化，请刷新后重试
- `1504`：事件不存在或超出数据范围

#### 2.1.7 重放预览

```
GET /admin-api/ims/auth/org/events/replay-preview?startTime=&endTime=&statuses=DEAD,RETRYING
```

**权限**：`ims:system:org-sync:run`

**响应**：
```json
{
  "code": 0,
  "data": {
    "count": 15
  }
}
```

**错误码**：
- `1001`：时间跨度超过 7 天 / 未选状态 / 超过 1000 条

#### 2.1.8 批量重放

```

```

**权限**：`ims:system:org-sync:run`

**规则**：

**错误码**：
- `1001`：时间跨度超过 7 天 / 未选状态 / 超过 1000 条

## 4. 同步规则

### 4.1 全量对账（手动/定时）

**触发条件**：
- 手动：R1 点击「手动对账」按钮
- 定时：每日 02:00

**处理流程**：
1. 检查是否有正在进行的对账 → 有则 `1001`
2. 创建 `OrgSyncBatch`，状态 `RUNNING`
3. 调用钉钉接口拉取全量部门和人员
4. 钉钉超时 → 批次失败，组织数据不变（V1-A6）
5. 对比 IMS 与钉钉数据：
   - 部门：新增/更新/停用
   - 人员：新增/更新/离职/移入待分配
   - 岗位：归档（BG-04）
6. 写 `OrgSyncBatchItem` 明细
7. 更新批次状态和统计数字

**本地修改覆盖规则**（A-21）：
- 钉钉来源的部门/人员，本地修改会被钉钉值覆盖
- 覆盖时写 `ChangeLog`（`reason=DINGTALK_OVERRIDE`）
- 在「同步差异」Tab 显示

### 4.2 增量同步（钉钉事件推送）

**事件类型映射**（BG-01）：

| 钉钉事件 | IMS biz_type |
|---------|-------------|
| user_add_org | HIRE |
| user_modify_org | USER_UPDATE（处理时若主部门或岗位变化 → TRANSFER） |
| user_leave_org | RESIGN |
| org_dept_create | DEPT_CREATE |
| org_dept_modify | DEPT_UPDATE |
| org_dept_remove | DEPT_DELETE |

**处理流程**：
1. 接收钉钉回调，写 `OrgSyncEvent`（`status=PENDING`）
2. Worker 按时间顺序处理
3. 处理成功 → `status=SUCCESS`
4. 处理失败 → 退避重试（1/5/15/60 分钟），第 5 次失败进死信

**重试规则**：
- 自动重试：退避间隔 1/5/15/60 分钟
- 手动重试：立即投递，`retry_count` 不清零
- 批量重放：死信 `retry_count` 清零

### 4.3 首登即时同步（LG-07）

**触发条件**：钉钉扫码/免登回调时，映射和手机号都未命中

**处理流程**：
1. 用钉钉 userid 调钉钉接口获取人员详情
2. 在职且属于本企业 → 按 FP-D07-03 建本地用户和映射
3. 写 `OrgSyncEvent`（`biz_type=HIRE`，`event_id=login-sync:<钉钉userid>:<日期>`）
4. 触发岗位供给
5. 签发令牌
6. 钉钉返回不在本企业/已离职 → `1217`
7. 钉钉超时 → `5003`

**幂等规则**：同一钉钉 userid 当天已有成功的即时同步事件则不重复处理

### 4.4 数据范围过滤

- 事件：按 `dept_id` 过滤
- 人员：按主部门和所属部门过滤
- 对账明细：按 `dept_id` 过滤
- **统计卡和对账汇总数字为全公司口径**

数据范围规则（Q10 已核实）：
- R2 `data_scope=DEPT`：本部门，不含下级
- R4 `data_scope=IP_GROUP`：按 IP 组
