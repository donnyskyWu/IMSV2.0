## 2. API 契约

### 2.1 新增接口（14 个，含回调）

#### 2.1.1 组织同步概览

```
GET /admin-api/ims/auth/org/sync-metrics
```

**权限**：`ims:system:org-sync:query`

**响应**：
```json
{
  "code": 0,
  "data": {
    "userTotal": 1234,
    "yesterdayEventCount": 56,
    "pendingEventCount": 3,
    "deadEventCount": 1,
    "avgDelayMinutes": 2.5,
    "p95DelayMinutes": 4.8,
    "successRate24h": 0.98,
    "dingtalkUnavailable": false,
    "reconcileFailedTwice": false
  }
}
```

**规则**：
- `userTotal`：状态为在职（ACTIVE）或冻结（FROZEN）的用户数，不含离职
- `avgDelayMinutes`：最近 24 小时成功事件的 `(processed_time - event_time)` 平均值，保留 1 位小数
- `dingtalkUnavailable`：最近 10 分钟内有钉钉调用超时（5003）记录
- `reconcileFailedTwice`：最近两个对账批次均失败

- `startTime`/`endTime`：事件时间范围，默认最近 7 天，跨度 ≤90 天
- `sortBy`：`eventTime` 或 `processedTime`
- `sortOrder`：`asc` 或 `desc`

## 4. 同步规则

### 4.1 全量对账（手动/定时）

**触发条件**：
- 手动：R1 点击「手动对账」按钮
- 定时：每日 02:00

**处理流程**（先完整拉取校验、在内存比对、再分段写入）：

1. 检查是否有正在进行的对账 → 有则 `1001`
2. 创建 `OrgSyncBatch`，状态 `RUNNING`
3. **第一阶段：完整拉取**
   - 调用钉钉接口分页拉取全量部门和人员
   - 每一页拉取后校验数据完整性
   - 钉钉超时或 API 错误 → 批次失败，组织数据不变（V1-A6）
   - **分页中断** → 批次失败，**丢弃已拉取数据**，组织数据不变
4. **第二阶段：内存比对**
   - 所有数据拉取完成后，在内存中与 IMS 现有数据比对
   - 生成变更计划（新增、更新、删除）
5. **第三阶段：分段写入**
   - 按批次写入数据库
   - **单条失败记 `FAILED`，不整体回滚**
   - 批次状态和统计数字记录成功数与失败数
6. 对比结果处理：
   - 部门新增：写 `OrgSyncBatchItem`（action=DEPT_CREATE）

   - 人员更新：更新字段，若部门/岗位变化触发供给
   - 人员离职：`status=RESIGNED`，`token_version+1`

**钉钉部门删除规则**（A-22）：

当钉钉删除某个部门时：
1. **IMS 部门停用并逻辑删除**（`status=DISABLED`，`deleted=1`）
2. **钉钉成员按钉钉最新归属更新**：
   - 该成员在钉钉里仍有其他部门 → 按钉钉最新归属更新其部门列表
3. **只有以下人员移入「待分配」并设为主部门**：
   - 在钉钉里已经没有任何部门的人（钉钉返回部门列表为空）
   - 未绑定钉钉的本地用户（`source=LOCAL` 或无 `dingtalk_user_id`）
4. **给持有 `ims:system:user:update` 权限的用户发待办**（一个部门一条，列出移入待分配的人数）

### 4.2 增量同步（钉钉事件推送）

**事件类型映射**（BG-01）：

| 钉钉事件 | IMS biz_type |
|---------|-------------|
| user_add_org | HIRE |
| user_modify_org | USER_UPDATE（处理时若主部门或岗位变化 → TRANSFER） |
| user_leave_org | RESIGN |
| org_dept_create | DEPT_CREATE |
| org_dept_modify | DEPT_UPDATE |
| org_dept_remove | DEPT_DELETE |

**回调接口**（本 PR 新建，含 SHA1 验签逻辑）：

- 路径：`POST /admin-api/ims/callback/dingtalk/event`
- 权限：匿名（通过验签认证）

**服务端配置**（`DingTalkSettings`，前缀 `IMS_DINGTALK_`）：

```python
callback_token: str = Field(default="")      # 钉钉回调 token
callback_aes_key: str = Field(default="")    # 钉钉回调 AES key（43 字符 Base64）
```

**验签算法**（钉钉官方规范，本 PR 新建实现）：

1. 从 query 取 `signature`、`timestamp`、`nonce`
2. 从 body 取 `encrypt`
3. 将 `callback_token`、`timestamp`、`nonce`、`encrypt` **排序后拼接**
4. 对拼接结果做 **SHA1** 哈希
5. 与 `signature` 比对

```python
def verify_callback_signature(
    token: str,          # 服务端配置的 callback_token
    timestamp: str,      # query 参数
    nonce: str,          # query 参数
    encrypt: str,        # body 中的 encrypt 字段
    signature: str,      # query 参数
) -> bool:
    to_sign = "".join(sorted([token, timestamp, nonce, encrypt]))
    expected = hashlib.sha1(to_sign.encode()).hexdigest()
    return hmac.compare_digest(expected, signature)
```

**处理流程**（验签 → 解密 → receiveid 校验 → 租户匹配）：

1. **验签**：校验 signature，失败 → HTTP 200 + 1008，不写事件，记日志
2. **防重放**：
   - `timestamp` 超过 5 分钟 → HTTP 200 + 1008
   - `nonce` 在 Redis 已存在（TTL 10 分钟） → HTTP 200 + 1008
3. **AES 解密**：解密 `encrypt` 字段，失败 → HTTP 200 + 1008
4. **receiveid 校验**：校验明文尾部 `receiveid == settings.dingtalk.corp_id`，不匹配 → HTTP 200 + 1008
5. **租户匹配**：按事件中的 `CorpId` 查找 IMS 租户
   - 未知租户 → HTTP 200 + `{"code": 0}`，不写事件，记日志
6. **幂等**：按 `event_id` 去重，已存在则返回成功
7. **写事件**：写 `OrgSyncEvent`（`status=PENDING`）
8. **返回加密 success**

**AES 解密**（钉钉官方规范）：

```python
def decrypt_callback(aes_key: str, encrypt: str, expected_corp_id: str) -> str:
    """
    AES-256-CBC 解密。
    - key = Base64Decode(aes_key + '=')（补等号后解码，得 32 字节）
    - IV = key 前 16 字节
    - 解密后去 PKCS#7 填充
    - 校验明文尾部 receiveid == expected_corp_id
    """
    key = base64.b64decode(aes_key + "=")
    iv = key[:16]
    cipher = AES.new(key, AES.MODE_CBC, iv)
    decrypted = unpad(cipher.decrypt(base64.b64decode(encrypt)), AES.block_size)
    # 解析：4字节长度 + 消息体 + receiveid
    msg_len = struct.unpack(">I", decrypted[:4])[0]
    msg = decrypted[4:4 + msg_len].decode()
    receiveid = decrypted[4 + msg_len:].decode()
    if receiveid != expected_corp_id:
        raise ValueError("receiveid mismatch")
    return msg
```

**成功应答**（必须返回加密的 success）：

```python
def encrypt_response(token: str, aes_key: str, corp_id: str) -> dict:
    """返回加密的 success 响应。
    
    Args:
        token: 服务端配置的 callback_token，用于签名
        aes_key: 服务端配置的 callback_aes_key，用于加密
        corp_id: 企业 corp_id，作为 receiveid
    """
    nonce = secrets.token_hex(8)
    timestamp = str(int(time.time()))
    msg = "success"
    encrypt = encrypt_callback(aes_key, msg, corp_id, nonce)
    signature = sign_callback(token, timestamp, nonce, encrypt)
    return {
        "msg_signature": signature,
        "timeStamp": timestamp,
        "nonce": nonce,
        "encrypt": encrypt,
    }
```

**check_url 处理**：
- 钉钉首次配置回调时发送 `check_url` 请求
- 必须返回加密的 success 响应

**单测要求**：
- 使用**钉钉官方示例向量**做验签和加解密单测
- 覆盖验签成功、验签失败、解密失败、receiveid 不匹配

**跨租户处理**（两类场景）：

| 场景 | 处理方式 | 响应 | 测试要求 |
|-----|---------|------|---------|
| 解密后 `CorpId` 未知（租户在 IMS 不存在） | 忽略，不写事件 | HTTP 200 + `{"code": 0}` | 单元测试覆盖 |
| 管理接口查询他租户的事件/批次/人员 | 拒绝 | `1504` 资源不可用 | 单元测试覆盖 |

**Worker 处理**：
- Worker 按时间顺序处理
- **同一人员的多个事件串行处理**（避免并发冲突）
- 处理成功 → `status=SUCCESS`
- 处理失败 → 记 `FAILED`，进入退避重试

**单条失败处理**：
- 增量同步中单条事件处理失败 → 该事件记 `FAILED`
- **不影响其他事件**，不整体回滚
- 失败事件进入退避重试流程

**重试规则**：
- 自动重试：退避间隔 1/5/15/60 分钟
- 手动重试：立即投递，`retry_count` 不清零
- 批量重放：死信 `retry_count` 清零

**幂等规则**：
- 同一 `event_id` 重复投递只处理一次
- 处理前检查 `OrgSyncEvent` 表是否已有该 `event_id`
- 已有且状态为 `SUCCESS` → 直接返回成功
- 已有且状态为 `PENDING`/`RETRYING` → 不重复投递

### 11.3 事件回调安全

**回调接口**：`POST /admin-api/ims/callback/dingtalk/event`（本 PR 新建，含 SHA1 验签逻辑）

**服务端配置**（`DingTalkSettings`）：
- `callback_token`：验签用的 token
- `callback_aes_key`：加解密用的 AES key（43 字符 Base64）

**验签算法**（本 PR 新建实现）：
```python
def verify_callback_signature(
    token: str,          # 服务端配置的 callback_token
    timestamp: str,      # query 参数
    nonce: str,          # query 参数
    encrypt: str,        # body 中的 encrypt 字段
    signature: str,      # query 参数
) -> bool:
    to_sign = "".join(sorted([token, timestamp, nonce, encrypt]))
    expected = hashlib.sha1(to_sign.encode()).hexdigest()
    return hmac.compare_digest(expected, signature)
```

**处理流程顺序**：
1. 验签（失败 → 1008）
2. 防重放（失败 → 1008）
3. AES 解密（失败 → 1008）
4. receiveid 校验（不匹配 → 1008）
5. 租户匹配（未知 → code 0）
6. 写事件

**AES 解密**：
- key = Base64Decode(aes_key + '=')
- IV = key 前 16 字节
- AES-256-CBC 解密后去 PKCS#7 填充
- 校验明文尾部 receiveid == corp_id

**成功应答**：必须返回加密的 success（msg_signature/timeStamp/nonce/encrypt）

**单测**：使用钉钉官方示例向量做验签和加解密测试

**防重放**：
- `timestamp` 超过 5 分钟 → 拒绝
- `nonce` 在 Redis 去重（key: `dingtalk:nonce:{nonce}`，TTL 10 分钟）

**验签失败或重放响应**：
- HTTP 200 + `{"code": 1008, "msg": "验签失败"}`（按 B0a FP-D07-01）
- **不写事件**
- **记日志**

**跨租户隔离**：
- 解密后 `CorpId` 未知 → 忽略，HTTP 200 + code 0
- 管理接口跨租户查询 → `1504`
