## 1. 登录页 `/login`（原型 `login.html`；【AUTH 规格】P1）

**页面线框（文字版）**：全屏无侧栏。左侧品牌区（系统名“IMS 内部管理系统”+ 一句说明），右侧 400px 登录卡片：标题“登录” → Tabs〔钉钉扫码｜账号登录〕→ Tab 内容 → 卡片底部小字“遇到问题请联系系统管理员”。H5（钉钉 App 内打开）不显示本页，直接走免登过渡页（LG-06）。

### FP-B1-LG-01 登录页框架与入口选择
- **入口**：未登录访问任何业务路由时由 B0b 路由守卫跳转 `/login?redirect=<原路由>`；直接访问 `/login`；退出登录后。
- **角色权限**：匿名。
- **字段和校验**：—。
- **状态流转**：页面加载 → 调 `GET /auth/login-options` → 钉钉已启用：显示两个 Tab，默认 Tab = 本浏览器上次成功登录使用的方式（`localStorage`），首次访问默认“钉钉扫码”；钉钉未启用：只显示“账号登录”，不显示 Tab 头。
- **计算规则**：
  1. 已登录（本地有有效会话且 `/auth/me` 成功）访问 `/login` → 直接跳到登录落地页（LG-08）；
  2. `redirect` 只接受站内相对路径（以 `/` 开头且不以 `//` 开头），否则丢弃（与 B0a FP-D02-01 同口径）；
  3. URL 带 `ssoError` 参数时（LG-05）在卡片顶部显示错误提示条，并自动切到“钉钉扫码”Tab；
  4. `login-options` 请求网络失败时静默重试 3 次（间隔 1 秒，【AUTH 规格】P1 网络异常），仍失败按“钉钉未启用”展示并提示“网络异常，钉钉登录暂不可用”。
- **错误码**：—（`login-options` 不返回业务错误）。
- **接口和表**：`GET /admin-api/ims/auth/login-options`（**本批新增**，匿名，加入 B0a FP-A01-02 匿名白名单）→ `{dingtalkEnabled, corpId, clientId}`（不返回任何密钥）；读 B0a 参数 `dingtalk.mode`。
- **B0b 组件**：Tabs（UI-C03）、Toast（UI-C20）；路由守卫（FP-R-07）、authStore（FP-R-04）。
- **依据**：【AUTH 规格】P1；04-B-21“登录页同时提供账号密码与钉钉扫码两个入口”；B0b FP-R-03；【ADR-009】；原型 `login.html`（仅账号密码）。**【本清单裁定】**登录页为“钉钉扫码 + 账号登录”双入口（规格只有扫码、原型只有账号密码，按 04-B-21 合并）。

### FP-B1-LG-02 账号密码登录
- **入口**：登录页“账号登录”Tab。
- **角色权限**：匿名。
- **字段和校验**：
  | 字段 | 控件 | 校验（前端） |
  |------|------|--------------|
  | 用户名 | 文本框，占位“请输入用户名”，自动去首尾空格 | 必填（“请输入用户名”）；前端不校验格式，避免暴露用户名规则 |
  | 密码 | 密码框，可切换明文 | 必填（“请输入密码”）；前端不校验长度 |
  - 回车提交；提交中按钮 loading 并禁用，防重复提交；本期**不启用验证码**（B0a `captcha` 参数不传）【本清单裁定：靠 B0a 的 5 次锁定防暴力】。
- **状态流转**：提交 → 成功：保存令牌 → 调 `/auth/me` → `pwdResetRequired=true` 跳 `/password-reset`（PW-01），否则跳落地页（LG-08）；失败：见 LG-03。
- **计算规则**：用户名或密码错误统一提示，不区分“用户不存在”；钉钉同步自动建的用户没有密码（B0a FP-D07-03），用账号登录一律得到 1214。
- **错误码**：1214（表单下方红字“用户名或密码错误”，清空密码框）；1215、1216、1008、5007 见 LG-03；1001（参数缺失，正常不会出现）。
- **接口和表**：B0a `POST /admin-api/ims/auth/login`、`GET /admin-api/ims/auth/me`；`ims_sys_user`、登录日志（渠道 `PASSWORD`，见 LG-09）。
- **B0b 组件**：FormField / FormRules（UI-C17）、Toast（UI-C20）；authStore（FP-R-04）。
- **依据**：B0a FP-D01-01；【ADR-009】；【PRD】§5.1 第 2 条；原型 `login.html`“本地账号进入系统…提交用户名和密码”。

### FP-B1-LG-03 登录失败分支
- **入口**：LG-02、LG-05、LG-06 的失败返回。
- **角色权限**：匿名。
- **字段和校验**：—。
- **状态流转 / 计算规则**：
  | 返回 | 页面表现 |
  |------|----------|
  | 1215 锁定（`data.remainMinutes`） | 卡片顶部红色提示条“账号已锁定，请 {n} 分钟后再试”，{n} 每分钟递减；倒计时期间，**同一用户名**的“登录”按钮禁用，修改用户名后恢复；倒计时到 0 提示条消失 |
  | 1216 冻结或离职 | 红色提示条“账号已冻结或已离职，无法登录，请联系管理员”（B0a 0.4 文案 + 规格 P1“请联系管理员”） |
  | 1008（租户停用 / 过期） | 红色提示条“所属组织已停用，请联系管理员” |
  | 1003（本设备会话被新登录挤掉，在业务页发生） | 由 B0b FP-R-03 处理：toast 后回到登录页 |
  | 5003 钉钉超时（扫码 / 免登） | 提示条“钉钉服务暂不可用，请稍后重试，或使用账号登录” |
  | 网络错误（无响应） | toast“网络异常，请检查网络后重试”；**登录提交不自动重试**（非幂等）【本清单裁定：规格 P1“自动重试 3 次”只用于 `login-options` 等读接口】 |
  | 5007 / 其他 | toast“系统繁忙，请稍后再试” |
- **错误码**：1215、1216、1008、1003、5003、5007。
- **接口和表**：同 LG-02；登录日志记失败原因。
- **B0b 组件**：Toast（UI-C20）；错误码策略（FP-R-02）。
- **依据**：B0a FP-D01-01、0.4；【AUTH 规格】P1 异常分支 b～e；【PRD-V1】AUTH-R3、AUTH-R4。

### FP-B1-LG-04 钉钉扫码登录（PC）
- **入口**：登录页“钉钉扫码”Tab。
- **角色权限**：匿名。
- **字段和校验**：—。
- **状态流转**：
  1. 进入 Tab → `GET /auth/sso/dingtalk/authorize-params?redirect=<redirect>` 取得 `{clientId, redirectUri, state, scope}`（state 生成规则同 B0a FP-D02-01：32 位随机、Redis 5 分钟、一次性）；

- **接口和表**：`GET /admin-api/ims/auth/position/rules`（**本批新增**，分页）。

- **依据**：【AUTH 规格】P3 列定义；原型 `authPosition.html` 列与操作（`ops:*` 角色编码已废弃，04-C-13，不显示角色编码）。

### FP-B1-POS-03 新建规则（抽屉 560px）
- **入口**：〔新建规则〕。
- **角色权限**：`ims:auth:position-rule:create`。
- **字段和校验**：
  | 字段 | 控件 | 校验 |
  |------|------|------|
  | 规则名称 | 文本 | 必填；≤ 64 字；同租户未删除规则中唯一 → 1284 |
  | 钉钉岗位 | PositionSelect（`dict_position` 启用值） | 必填；非启用字典值 → 1503 |
  | 主角色 | RoleSelect 单选 | 必填；只能选启用角色（B0b FP-C23-01：停用、待配置角色不可新选）；不存在 → 1500，已停用 → 1501 |

- **状态流转**：保存 → 规则 `ENABLED`，`version=1`，写版本记录 `CREATE`；若该岗位已有启用规则 → 走 POS-05 替换确认；保存后**不改变任何现有人员**，只对之后入职 / 调岗到该岗位的人员生效（POS-R2 同口径）。
- **计算规则**：一个岗位最多一条启用规则（POS-R1）；同一岗位可以有多条停用规则。
- **错误码**：1001、1281、1284、1500、1501、1503、1008。
- **接口和表**：`POST /admin-api/ims/auth/position/rules {ruleName, positionCode, mainRoleId, extraRoleIds[], description, replaceExisting?}`（**本批新增**）；`ims_auth_position_role_rule`、`ims_auth_position_rule_role`、`ims_auth_position_rule_version`；写操作日志。
- **B0b 组件**：FormDrawer（UI-C14）、FormField（UI-C17）、PositionSelect / RoleSelect（UI-C23）。
- **依据**：【AUTH 规格】P3 编辑抽屉字段（ruleName ≤64、dingtalkPosition 必填、description ≤200、grantRoleIds ≥1）；【PRD】§4.1“授予某角色（+ 可选附加角色）”；【PRD】§4.2.1 G5；B0a FP-B04-01。**【本清单裁定】**规格 `grantRoleIds` 多选拆为“主角色 1 个 + 附加角色 0～5 个”（B0a 规则表 `role_id` 单值保留为主角色，附加角色进新表；改动 B0a FP-D05-01，见 BG-02）。

### FP-B1-POS-04 编辑规则（生成新版本）
- **入口**：行〔编辑〕。
- **角色权限**：`ims:auth:position-rule:update`。
- **字段和校验**：同 POS-03，但**钉钉岗位只读**（要换岗位请新建规则）；抽屉头显示“当前版本 v{n}，保存后生成 v{n+1}”；已选中的待配置主角色 / 附加角色保留显示（带“待配置”角标），可删除，不能新选待配置角色。

- **接口和表**：`PUT /admin-api/ims/auth/position/rules/{id} {ruleName, mainRoleId, extraRoleIds[], description, baseVersion}`（**本批新增**）。

- **依据**：【AUTH 规格】P3“编辑模式头部显示当前版本 v3，保存后生成 v4”、POS-R2；【PRD-V1】5.3.3 POS-R2；【PRD】FR-AUTH-020、AC-AUTH-020。**【本清单裁定】**钉钉岗位编辑时只读、乐观锁 1285。

### FP-B1-POS-05 替换绑定（POS-R1）
- **入口**：新建（POS-03）或启用（POS-06）时，该岗位已有另一条启用规则。
- **角色权限**：create 或 update。
- **状态流转**：首次提交（不带 `replaceExisting`）→ 1281（带原规则信息）→ 前端弹确认框“岗位「{岗位}」已绑定启用规则「{原规则} v{n}」（在用 {m} 人）。确认后原规则停用、改由本规则供给；原规则已授予的 {m} 人权限不变。确认替换？” → 确认后带 `replaceExisting=true` 重新提交 → 同一事务内：原规则 `DISABLED`（版本记录 `REPLACED`）、本规则 `ENABLED`。
- **计算规则**：原规则的在用人员继续计入原规则套用人数，可在原规则的成员抽屉中按本岗位新规则刷新（POS-10）；并发下两条请求同时替换 → 以数据库唯一约束（岗位 + 启用）兜底，后到者 1281。
- **错误码**：1281。
- **接口和表**：同 POS-03 / POS-06。
- **B0b 组件**：ConfirmDialog（UI-C16）。
- **依据**：【AUTH 规格】P3“保存时若钉钉岗位已绑定启用规则 → 二次确认‘替换绑定’（POS-R1）”；【PRD-V1】POS-R1；【AUTH 契约】“同一岗位不可存在两条启用规则”。

### FP-B1-POS-06 停用 / 启用
- **入口**：行〔停用〕/〔启用〕。
- **角色权限**：`ims:auth:position-rule:update`。
- **状态流转**：`ENABLED →（停用）→ DISABLED`；`DISABLED →（启用）→ ENABLED`（岗位已有启用规则时走 POS-05）；写版本记录 `DISABLE` / `ENABLE`（版本号不变）。

- **错误码**：1281、1504、1008、1001（已归档）。
- **接口和表**：`POST /admin-api/ims/auth/position/rules/{id}/enable`、`POST …/{id}/disable`（**本批新增**）。
- **B0b 组件**：ConfirmDialog（UI-C16）、Toast（UI-C20）。
- **依据**：【AUTH 规格】P3 停用确认文案；【PRD】§4.2.1 G1。

### FP-B1-POS-07 删除（POS-R3）

### FP-B1-POS-10 按新版本刷新在用人员（POS-R2 的“手动刷新”）
- **入口**：POS-09 的刷新按钮；POS-04 保存后提示中的〔去刷新〕。
- **角色权限**：`ims:auth:position-rule:refresh`（R1）。
- **状态流转**：选择人员 → 预览弹窗（Modal 720px）：每人一行“姓名｜当前版本｜将增加的角色｜将移除的角色”，合计“将影响 N 人：增加角色 a 次，移除角色 b 次”；无任何变化的人员标“无变化”→〔确认刷新〕→ 后台逐人执行 → 结果 toast“已刷新 N 人（无变化 k 人、失败 f 人）”，失败明细可展开。
- **计算规则**（对每个人）：
  1. 目标角色集合 = 当前版本主角色 + 附加角色；
  2. **移除**：该人员 `rule_id = 本规则`、`source=DINGTALK_AUTO` 且不在目标集合中的角色行；`source=MANUAL` 的同名角色**不动**；
  3. **增加**：目标集合中该人员没有的角色，以 `source=DINGTALK_AUTO`、`rule_id`、`rule_version=当前版本` 写入；存在 `manual_removed=1` 记录的角色**跳过**（04-A-25），在预览中标“已被手工移除，跳过”；
  4. 已有且保留的角色行更新 `rule_version`；
  5. 人员当前岗位 ≠ 规则岗位（调岗缓冲中）→ 跳过，标“岗位已变化，不刷新”；
  6. 受影响人员 `permVersion+1`（B0a FP-D03-04，即时生效）；写操作日志（每人一条，含前后角色）；
  7. 单次最多 500 人，超过分批提示。
- **错误码**：1001（未选人 / 超 500）、1008、1504。
- **接口和表**：`POST /admin-api/ims/auth/position/rules/{id}/refresh-preview {userIds[] | allOutdated:true}`、`POST …/{id}/refresh {userIds[] | allOutdated:true, clientToken}`（**本批新增**）；`ims_sys_user_role`、操作日志。
- **B0b 组件**：Modal（UI-C18）、DataTable（UI-C07）、Toast（UI-C20）。
- **依据**：【PRD-V1】POS-R2“已套用用户不自动变更，需调岗或手动刷新”；【PRD-V1】5.3.1 第 4 条“模拟某用户权限预览（变更前 Diff）”；04-A-25。**【本清单裁定】**刷新的范围、跳过规则与预览形式。

## 5. 后台能力（无独立页面，均有页面可观察的结果）

### FP-B1-BG-01 同步事件分类与快照字段（扩展 B0a FP-D07-01）
- **规则**：
  1. 事件接收时按钉钉事件类型初定 `biz_type`：人员入职 → `HIRE`，人员离职 → `RESIGN`，人员变更 → `USER_UPDATE`，部门新增 / 变更 / 删除 → `DEPT_CREATE` / `DEPT_UPDATE` / `DEPT_DELETE`；字典 `dict_org_event_type` 中文：入职 / 调岗 / 信息变更 / 离职 / 部门新增 / 部门变更 / 部门删除；
  2. Worker 处理 `USER_UPDATE` 时，若主部门或岗位发生变化 → 改为 `TRANSFER`（调岗）；
  3. 处理时写快照：`subject_user_id`、`subject_name`、`before_dept_names` / `after_dept_names`（名称快照，部门以后改名不影响历史）、`dept_id`（人员事件 = 处理后的主部门，离职事件 = 离职前主部门；部门事件 = 该部门本身），用于数据范围过滤；
  4. `processed_time`、`delay_seconds = processed_time − event_time`；每次尝试写 `ims_auth_org_sync_event_attempt`；
  5. 【PRD-V1】ORG-R2“失败重试 3 次”与【AUTH 契约】“≤16 次”**都不采用**，以已审 B0a 的“1/5/15/60 分钟退避、第 5 次失败进死信”为准【本清单裁定】。
- **依据**：【PRD-V1】5.2.2 `event_type` hire/transfer/resign/dept_change；【AUTH 规格】P2 事件类型筛选；B0a FP-D07-01/05。**【本清单裁定】**事件类型从规格 4 种细化为 7 种（规格的 dept_change 拆为部门新增 / 变更 / 删除，另加“信息变更”）。

### FP-B1-BG-02 岗位供给扩展：主角色 + 附加角色 + 版本记录（扩展 B0a FP-D05-01）
- **规则**：
  1. 授予时取该岗位**启用规则当前版本**的全部角色（主 + 附加），逐个写 `source=DINGTALK_AUTO`、`rule_id`、`rule_version`；`manual_removed=1` 的跳过（B0a 第 2 条不变）；
  2. 回收时回收**原岗位规则授予的全部** `DINGTALK_AUTO` 角色行（按 `rule_id` 找，不再只找单个 `role_id`），时间按 BG-03；
  3. 新岗位无规则 → 按 B0a 第 1 条自动建 `PENDING_CONFIG` 角色 + 建规则（规则名称 = 岗位名称，`version=1`，版本记录 `AUTO_CREATE`，操作人“钉钉同步”）+ 待办；岗位已有规则但为停用 → 不授予、不建角色；
  4. 同一角色同时来自手工授予与规则：保留两行来源（手工行不受供给影响），权限按并集。
- **依据**：【PRD】§4.1、§4.2.1 G1～G6；B0a FP-D05-01。**【本清单裁定，改动 B0a FP-D05-01】**。

### FP-B1-BG-03 调岗 24 小时权限缓冲（ORG-R3）
- **规则**：人员岗位变化（钉钉调岗事件、对账发现岗位变化、管理员在 B2 改岗位）时：
  1. 新岗位规则的角色**立即授予**；
  2. 原岗位规则授予的 `DINGTALK_AUTO` 角色**不立即回收**，设 `revoke_at = now + 24 小时`；Worker 每 10 分钟回收到期行并 `permVersion+1`；
  3. 24 小时内又调回原岗位 → 清除 `revoke_at`（不回收）；24 小时内再次调到第三个岗位 → 原岗位角色保持原 `revoke_at`，第二岗位角色新设 `revoke_at`；
  4. 原岗位角色同时也是新岗位规则的角色 → 不设回收，直接把 `rule_id/rule_version` 改为新规则；
  5. 离职（`RESIGNED`）不走缓冲：账号直接不可登录（B1-D1 已定，与 B0a 一致；含工作台），角色行保留供审计；
  6. 部门变化不设缓冲：数据范围按新部门即时生效（缓冲只针对角色）。
- **页面可见**：人员详情抽屉角色旁显示“将于 … 回收”（ORG-11）；套用人员抽屉“仅看岗位已变化的人员”（POS-09）。
- **依据**：【PRD-V1】ORG-R3“调岗事件保留原权限 24 小时缓冲，随后切换新岗位模板权限”；【AUTH 契约】状态图“24h 权限缓冲 ORG-R3”；B0a FP-D05-01 第 3 条（立即回收）。**【本清单裁定，改动 B0a FP-D05-01】**缓冲期内新旧权限并集、新岗位权限立即生效。

### FP-B1-BG-04 岗位消失归档（G7）
- **规则**：每日对账结束后：`source=DINGTALK` 的岗位，在钉钉全量人员中已无人使用，且 IMS 中没有在职 / 冻结人员 → 字典值停用、该岗位规则 `archived=1`（版本记录 `ARCHIVE`）、该岗位的钉钉自动角色若无任何成员 → 角色停用（`DISABLED`，备注“岗位已归档”）；写对账明细 `POSITION_ARCHIVE`。以后该岗位再次出现 → 字典值启用、规则取消归档并恢复归档前状态（版本记录 `UNARCHIVE`）、角色恢复归档前状态（G6 幂等，不重建）。本地岗位（`source=LOCAL`）不自动归档。
- **依据**：【PRD】§4.2.1 G6、G7；原型底部说明“岗位消失且无用户时归档（POS-R3）”；B0a FP-D05-01 `archived` 字段（B0a 未写触发规则）。**【本清单裁定】**。

### FP-B1-BG-05 同步告警
- **规则**（通知走 B0a FP-G01，接收人 = 持有 `ims:system:org-sync:run` 的在职用户，站内消息）：
  1. 事件进入死信 → 通知“组织同步事件进入死信：{事件类型} {人员 / 部门}，请处理”；同一小时内多条合并为一条“过去 1 小时新增 n 条死信”；
  2. 同步延迟 > 5 分钟（B0a 已记告警事件）→ 每小时最多一条通知“组织同步延迟超过 5 分钟（当前平均 x 分钟）”；
  3. 对账连续 2 次失败 → 通知（P1 级）“组织对账连续 2 次失败：{原因}”（V1-A4），同时页面红色横幅（ORG-02）。
- **依据**：【PRD-V1】ORG-R2“仍失败告警管理员”、BR-001；`开发方案/IMS-验收标准与测试策略…` ET-AUTH-002-03（V1-A4）；B0a FP-D07-05。

### FP-B1-BG-06 工号
- **规则**：`ims_sys_user.emp_no` 由钉钉人员 `job_number` 同步写入（钉钉为准，覆盖本地值）；本地用户可空（维护在 B2 用户页）；同租户不强制唯一（钉钉侧可能为空或重复，只做索引）；工号在组织同步页、人员详情、套用人员列表显示并可搜索。
- **依据**：【AUTH 规格】P2 列“工号”、关键字“姓名/工号”；B0a FP-B03-01 字段表无工号。**【本清单裁定，给 B0a 用户表加列】**。

### FP-B1-BG-07 菜单、权限码、字典种子与默认授权
- **规则**（按 B0a FP-H05-01“只补缺不覆盖”）：
