## 1. 公司管理（CO）

### FP-B5-CO-01 列表
- **入口**：侧栏 公司资产 → 资源管理 → 公司管理。
- **角色权限**：`ims:corp:company:query`。
- **页面线框**：页头〔导出〕〔新建公司〕；筛选：名称、信用代码、状态（全部 / 启用 / 停用）〔查询〕〔重置〕；表头：公司 ID、名称、信用代码、公众号容量（已用 / 总量）、状态、操作〔详情〕〔编辑〕〔停用 / 启用〕。
- **规则**：已用 = 关联该公司的公众号数（B7 前恒为 0；`platformType IN (WECHAT_OFFICIAL, WECHAT_SERVICE)`，M4 BR-M4-002）；剩余 < 5 显示黄色“容量紧张”（Q-B11）；按创建时间倒序，分页 20。
- **接口**：★ `GET /company/page`。
- **依据**：【CORP 规格】P-R1；【M4】FR-M4-001；TC CR-CO-01、CR-CO-10。

### FP-B5-CO-02 新建 / 编辑
- **角色权限**：`create` / `update`。
- **规则**：必填：名称；可填：信用代码（18 位统一社会信用代码格式）、行业、地址、法人、法人身份证（加密，详情脱敏）、公众号容量（≥0 整数，默认 0）；名称、信用代码租户内唯一，重复 → 1001“公司名称已存在 / 信用代码已存在”（Q-T4）；编辑不可改容量（改容量走 CO-05）。
- **错误码**：1001、1503。
- **接口**：★ `POST /company`、`PUT /company/{id}`。
- **依据**：【M4】4.1.2；TC CR-CO-02～04。

### FP-B5-CO-03 停用 / 启用
- **规则**：确认框“停用后新登记账号不可再选此公司，已关联账号不受影响”；停用后选择器不返回（BG-01），后续批次写接口引用 → 1501。
- **接口**：★ `PUT /company/{id}/status`。
- **依据**：【MASTER 规格】铁律；TC CR-CO-09。

### FP-B5-CO-04 详情
- **规则**：抽屉 480px：主体信息；公众号容量卡（总量 / 已注册 / 剩余）；扩容记录表（时间、原容量、新容量、原因、操作人）；关联公众号表（B7 前显示空状态“暂无关联账号”）。
- **接口**：★ `GET /company/{id}`。
- **依据**：【CORP 规格】P-R1；TC CR-CO-05。

### FP-B5-CO-05 扩容
- **角色权限**：`expand`。
- **规则**：输入新容量与原因（必填）；新容量 < 已注册数 → 1222；写扩容记录子表与变更日志。
- **错误码**：1222、1001。
- **接口**：★ `POST /company/{id}/expand`；表 `ims_org_company_expansion`。
- **依据**：【M4】BR-M4-004、AC-M4-001-4；TC CR-CO-08。

### FP-B5-CO-06 导出（Q-B6）
- **规则**：参数同列表；B0a 异步导出；法人身份证脱敏。
- **接口**：★ `POST /company/export`。
- **依据**：TC CR-CO-10；B0a FP-H02-02。

## 2. 实名人管理（RN）

### FP-B5-RN-01 列表与脱敏
- **页面线框**：〔导出〕〔新增实名人〕；筛选：姓名、证件类型、状态（在职 / 离职）、证件号（精确，hash 查）；表头：实名人 ID、姓名、证件号（脱敏）、手机（脱敏）、中介人（首个名称 + “等 n 人”）、关联员工、状态、操作。
- **规则**：证件号前 3 后 4，手机 `138****5678`；任何接口不返回明文（D5）。
- **接口**：★ `GET /realname/page`。
- **依据**：【CORP 规格】P-R2；【M4】AC-M4-002-0；TC CR-RN-01、04。

### FP-B5-RN-02 新增 / 编辑
- **规则**：必填：姓名、证件类型、证件号；身份证 18 位校验位不对 → 1001；同租户同证件号（hash）唯一 → 1001“证件号已存在”；可选“关联员工”（UserSelect，04-B-03）；编辑时证件号显示脱敏，需“修改证件号”开关才可重填。
- **错误码**：1001、1500（关联员工不存在）、1503。
- **接口**：★ `POST /realname`、`PUT /realname/{id}`。
- **依据**：04-B-03；【M4】4.2.2；TC CR-RN-02、03。

### FP-B5-RN-03 状态（在职 / 离职）
- **规则**：离职后选择器不返回；已有证件不受影响；后续批次写接口引用 → 1501。
- **接口**：★ `PUT /realname/{id}/status`。
- **依据**：TC CR-RN-06。

### FP-B5-RN-04 中介人（Q-B8）
- **规则**：详情抽屉“中介人”子表增删改；字段见 0.5；佣金比例 0～100 两位小数；无 `commission` 权限码时显示 `****`（接口也不返回值）。
- **接口**：★ 15～17。
- **依据**：【M4】4.2.3、AC-M4-002-2/5。

### FP-B5-RN-05 删除（Q-B7）
- **规则**：被手机卡、证件、（B7 后）平台账号引用 → 1502“关联的实体已被其他记录引用”，提示引用数；否则逻辑删除并删除其中介人。
- **错误码**：1502、1504。
- **接口**：★ `DELETE /realname/{id}`。
- **依据**：【M4】AC-M4-002-3。

### FP-B5-RN-06 详情
- **规则**：抽屉：基本信息（脱敏）、中介人表、证件索引（该实名人证件列表，点击跳证件管理并带持有人筛选）、关联手机卡、关联账号摘要（B7 前为空）。
- **接口**：★ `GET /realname/{id}`。
- **依据**：【CORP 规格】P-R2；TC CR-RN-05。

### FP-B5-RN-07 导出（Q-B6）
- **规则**：同列表筛选；证件号、手机号脱敏；不导出佣金比例。
- **接口**：★ `POST /realname/export`。
- **依据**：TC CR-RN-07。

## 4. 证件档案（CT，证件管理页 Tab 1）

### FP-B5-CT-01 列表与数字化率
- **角色权限**：`ims:cert:archive:query`（全量，受数据范围）或 `query-self`（只看本人）。
- **页面线框**：数字化率横幅“数字化率 xx%（目标 > 95%）〔查看统计〕”，未达标红色；筛选：持有人、证件类型、证件号（精确 hash）、状态、有效期范围；〔上传证件〕；表头：持有人（外协加灰标“外协”）、证件类型、证件号（脱敏）、签发日期、有效期至、剩余天数（≤7 红 / ≤30 黄 / 已过期红底“已过期-锁定”）、状态、操作〔详情〕〔查看原图〕〔审核〕。
- **规则**：只有 `query-self` 时服务端只返回持有人关联本人（实名人 `user_id` = 本人或 `holder_user_id` = 本人）的证件；统计弹窗按类型展示（Q-B5 口径）。
- **接口**：★ `GET /cert/archive/list`、`GET /cert/archive/digital-metrics`。
- **依据**：【CERT 规格】P1；BR-005、BR-013；TC CR-CERT-01、11、12。

### FP-B5-CT-02 上传证件
- **角色权限**：`upload`。
- **规则**：抽屉 560px：持有人三选一（实名人 / 员工 / 外协姓名，Q-B2）、证件类型（Q-B4）、证件号（身份证前端 + 服务端校验）、签发日期、有效期至（须晚于签发日期）、扫描件（B0a 上传，scene=`cert`，jpg/png/pdf）；提交后状态“待审”；同持有人同类型已有 EFFECTIVE / EXPIRING / PENDING_REVIEW → 1032，弹窗引导“去换证”（跳到期预警 Tab 换证抽屉）；文件按版本存储不覆盖。
- **错误码**：1001、1032、1500、1501（实名人已离职）、1503。
- **接口**：★ `POST /cert/archive/upload`；○ 文件上传。
- **依据**：【CERT 契约】2.1.1；CERT-A-R3/R4；V1-D2；TC CR-CERT-02～06。

### FP-B5-CT-03 审核
- **角色权限**：`review`。
- **规则**：待审档案〔审核〕→ 通过 / 拒绝（拒绝必填原因）；通过 → EFFECTIVE（若为换证新证，旧证 RECYCLED、预警任务 RENEW_RESOLVED）；拒绝 → REJECTED；非待审状态 → 1033；上传人不能审核自己上传的档案 → 1008（B0a FP-G03-02 回避口径【本清单裁定】）；审核通过后立即按有效期计算一次预警级别。
- **错误码**：1033、1008、1504。
- **接口**：★ `PUT /cert/archive/{id}/review`。
- **依据**：【CERT 契约】2.1.4；CERT-A-R4。

### FP-B5-CT-04 分级查看原图与水印
- **规则**：
  1. 级别 = max(当前用户启用角色在 SC-01 的级别, L3 白名单 → 3)，默认 L1；
  2. L1：只返回索引信息，请求原图 → 1034，前端显示“访问级别不足”；
  3. L2：返回 60 秒签名 URL，经 B0a 水印钩子叠加“工号 + 姓名 + 时间戳”，全屏查看层无下载、禁右键与拖拽；
  4. L3：同 L2，且证件号明文显示（仍禁下载、仍叠水印）；
  5. 待审档案查看原图 → 1033；
  6. 每次请求（含被拒）写 `ims_cert_view_log` 并调 `audit_sensitive_view`；
  7. 同一用户 1 小时内第 11 次 → 1035，并发消息给持有 `ims:cert:security:audit` 者（Q-B10）。
- **错误码**：1033、1034、1035、1504。
- **接口**：★ `GET /cert/security/view/{certId}`。
- **依据**：【CERT 契约】2.3.1；CERT-S-R1～R3；V1-D3；TC CR-CERT-07、08、10。

### FP-B5-CT-05 详情
- **规则**：抽屉 560px：元信息、状态、审核记录、预警记录；持有 `audit` 者附最近 5 条查看记录（查看人、级别、时间）。
- **接口**：★ `GET /cert/archive/{id}`（含 `viewPermission`）。
- **依据**：【CERT 规格】P1 §4.3、§7。

### FP-B5-CT-06 OCR 识别预填（Q-B9 老板裁定 2026-10-13）
- **角色权限**：`upload`。
- **规则**：上传抽屉扫描件上传成功后显示〔识别〕；调 `POST /cert/archive/ocr {fileKey, certType}`，服务端经培训 AI 底座（B0a OpenAI 兼容客户端骨架，连接配置读 B10「模型连接」培训 AI 记录，mock / real 模式同培训 AI）把扫描件（PDF 取第 1 页）作为图片发给模型，返回 `{recognized, name, certNo, issueDate, expireDate}`；识别值只预填表单并标“识别结果，请核对”，须人工确认后走 CT-02 提交，服务端仍按 CT-02 全量校验；`ocr_result` 存识别 JSON（证件号加密）；未配置 / 调用失败 / 超时返回 `recognized=false`，前端提示“识别失败，请手工填写”，不阻断、不报错码；调用日志沿用 B0a 培训 AI 调用日志（加 `scene=CERT_OCR`），不记图片与证件号明文；业务代码不得出现地址 / 模型名字面量。
- **错误码**：1001（fileKey 非本人上传或非 `cert` 场景）、1008。
- **接口**：★ `POST /cert/archive/ocr`。
- **联调核实（技术项，不报老板）**：B10 培训 AI 当前模型 `qwen3.8-max` 是否支持图片输入；不支持时在 B10 培训 AI 记录增加“OCR 模型名”可选字段（默认空 = 同试卷模型）。
- **依据**：老板裁定 2026-10-13；V1-D1；B0a FP-H08-01/02；B10 FP-B10-CF-06。

### FP-B5-CT-07 证件删除（Q-B7 老板裁定 2026-10-13）
- **角色权限**：`delete`（种子只授 R1）。
- **规则**：列表行 / 详情〔删除〕→ ConfirmDialog danger“删除后不可恢复查看，审计记录保留”；`is_locked` 为真（被开播登记等锁定）→ 1502“证件已锁定，不可删除”；否则逻辑删除（`del_flag`），文件不物理删除（B0a FP-E01-03），关闭相关到期预警任务与待办（`todo.cancel`），写操作日志；删除后列表、选择器、数字化率均不再计入；查看审计日志保留。
- **错误码**：1008、1502、1504。
- **接口**：★ `DELETE /cert/archive/{id}`。
- **依据**：PRD §4.2（证件删除仅 R1）；老板裁定 2026-10-13。

## 5. 到期预警（EX，Tab 2）

### FP-B5-EX-01 每日扫描与手动扫描
- **规则**：B0a `@job` 每日 08:00（北京时间）扫描 EFFECTIVE / EXPIRING 证件：剩余 ≤30 天 YELLOW、≤7 天 RED、≤0 LOCKED（证件 EXPIRED）；新增或升级级别时生成 / 更新预警任务，并 `notify` + `todo.create(type=预警, source_type=CERT_EXPIRE)`（接收人见 Q-T9）；同一证件同级别只推一次（CERT-E-R2）；〔手动扫描〕需 `scan`，确认后执行同一逻辑，幂等；提供服务方法 `cert.is_locked(realname_id)` 供 B9 开播拦截。
- **接口**：★ `POST /cert/expire/scan`。
- **依据**：CERT-E-R1/R2/R3；BR-013；B0a FP-H01-01、G01、G02；TC CR-CERT-04、05。

### FP-B5-EX-02 列表与统计
- **页面线框**：统计卡 黄 / 红 / 锁定数 + 近 30 天趋势；筛选：持有人、级别、状态（预警中 / 已换证 / 已锁定）；表头：持有人、证件类型、证件号（脱敏）、有效期至、剩余天数、级别、已通知、状态、操作〔换证〕〔催办〕。
- **接口**：★ `GET /cert/expire/list`、`GET /cert/expire/stats`。
- **依据**：【CERT 规格】P2；【CERT 契约】2.2.1、2.2.4。

### FP-B5-EX-03 换证登记
- **角色权限**：`renew`。
- **规则**：抽屉内上传新证（同 CT-02，`renew_from_id`=旧证，豁免 1032）→ 新证待审；审核通过后旧证 RECYCLED、任务 RENEW_RESOLVED、相关待办 `todo.complete`；新证与旧证持有人或类型不同 → 1001。
- **接口**：★ `PUT /cert/expire/{id}/renew`。
- **依据**：【CERT 契约】2.2.3；TC ML-06（换证恢复）。

### FP-B5-EX-04 人工催办
- **角色权限**：`remind`。
- **规则**：选渠道（站内 / 钉钉，默认都选）；不受同级别去重限制，但同一任务 10 分钟内重复点击只发一次【本清单裁定：防误点】；记录 `last_remind_time`、`remind_count`；任务已解除 → 1001。
- **接口**：★ `PUT /cert/expire/{id}/remind`。
- **依据**：【CERT 契约】2.2.5。
