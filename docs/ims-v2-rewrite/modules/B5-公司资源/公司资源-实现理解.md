## 1. 本批做什么

做 00 第 2 节的 4 个页面：公司、实名人（含中介人）、手机卡、证件（档案 / 到期预警 / 分级与审计三个 Tab），加 3 个选择器、证件到期扫描、OCR 预填。

## 2. 全局口径（本批遵守，不另起一套）

| 口径 | 落点 |
|------|------|
| 软删 | `deleted = id`，与 `UserService.delete_user`、`AuditBase.deleted` 一致。不新增 `del_flag`，不用 `deleted = 1`。列表和仓储默认 `deleted == 0` |
| 会话失效 | `AuthService.verify_token` 发现用户不存在或 `deleted != 0` → **1002** |
| 冻结 / 离职 | 同一函数发现用户状态为冻结或离职 → **1216**（登录路径已有；在线请求补到这一处） |
| 租户停用 / 过期 | `reject_unavailable_tenant` → **1008**，文案常量 `TENANT_UNAVAILABLE_MSG` = 「所属组织已停用，请联系管理员」 |
| 权限版本 | Redis `ims:perm_ver:u:{uid}`、`ims:perm_ver:t:{tid}`，用 `Cache.incr`。不入库、不写进 JWT。版本与登录时写入会话的值不一致 → **1008** |
| 缺权限 / 须改密 | 已有 `authorize`、`require_permission`、`require_any_permission`；须改密白名单仍是改密、登出、`/me`，其余 **1008** |
| 不存在或跨租户 | `Repository.get` → `BizError.not_found`（**1504**），响应不含名称 |
| 时间 | 业务取时只用 `get_now`。测试用 `set_clock`，结束用 `reset_clock`。禁止业务代码直接 `datetime.now()` |
| 测试库 | B5 用例连真实 MySQL（`IMS_DB_URL`）和真实 Redis（`IMS_REDIS_URL`）。缺任一配置时用例失败，不新增 skip，不回退 sqlite |
| 覆盖率 | 总行 ≥ 80%；本批列入 `scripts/p0_services.txt` 的 Service 分支 ≥ 90% |
| 上传 | 证件场景自己做扩展名、MIME、文件头、大小校验，不信任前端 |
| 外链 | `assert_http_url` 只校验 scheme 为 `http` 或 `https`。不拒绝私网、环回、链路本地。OCR 请求的 `train_ai.base_url` 走同一函数 |

`verify_token` 把 1002 / 1216 / 租户 1008 / `perm_ver` 比对放在这一个函数里，位于会话过期和黑名单（仍是 1002）之后。B5 的公司、实名人、手机卡、证件函数里不再各写一遍。

与 B2 并行时的合并策略：B2 若先合入同一闸门，B5 rebase 时丢掉本 PR 对 `verify_token` 的重复修改，保留 B2 的闸门，只留下 `UT-B5-BG-04-*`。B2 若后合入，由 B2 在冲突里保留本 PR 已写入的同一闸门，不各写一套。刷新令牌上的冻结 / 离职仍是 1002，不改成 1216。

main 上 `TENANT_UNAVAILABLE_MSG` 仍是「所属组织已停用」。实现 PR 把这一常量改成完整句，登录、刷新、在线请求共用。B5 不复制第二句文案。

## 3. 数据模型

表继承 `AuditBase`（已有 `id`、`tenant_id`、`creator`、`create_time`、`updater`、`update_time`、`deleted`）。迁移一个 Alembic 版本，可升可降：`003_b5_corp_resource`。只加列、只加 0.5 列出的新表，外加下面两处 0.5 没写、但功能点和 E2E 已经要用的列。

加密对齐 B0a FP-C03-01，不另定算法。`app/core/crypto.py` 的 `encrypt_field` / `decrypt_field` 使用 AES-256-GCM，密钥读 `SecuritySettings.field_key`（环境变量前缀 `IMS_SECURITY_`），密文带版本前缀，轮换读 `field_key_versions`。同一明文两次加密密文不同（随机 nonce）。`hash_field` 使用 HMAC-SHA256，密钥是独立的 `SecuritySettings.hash_key`，不复用 `field_key`。main 还没有 `EncryptedStr` 类型，业务函数只调这三个函数。等值查询只用 `*_hash`。

脱敏：`app/core/masking.py` 新增 `mask_id_card`（前 3 后 4）、`mask_mobile`（`138****5678`）。不复用现有 `export_mobile`（它的掩码形状与 D5 不一致）。任何响应、导出、日志都不带明文。L3 查看原图时证件号明文只出现在 `view_cert` 的当次响应。

### 3.4 数据范围字段

本批不加 `dept_id`。公司与实名人、手机卡、证件分开写，因为 main 上两处行为不同：

- `Repository._apply_data_scope`：`__scope_fields__` 为空时直接返回原查询，等于不限制。
- `validate_scope_models`：路由挂了 `scope_model` 且 `__scope_fields__` 为空时，启动失败。

**公司（技术核对 B1，采用「登录 + 权限码、不挂 scope_model」）**

`OrgCompany.__scope_fields__` 保持空。公司路由不设置 `scope_model`。列表和 `get_company` 只按租户与 `deleted == 0` 过滤，再加接口自己的权限码。同租户内 ALL、DEPT、SELF 看到同一批公司，`get_company` 不因数据范围返回 1504。不把公司放进「DEPT 列表为空」。

**实名人、手机卡（非空归属，与 `validate_scope_models` 一致）**

| 模型 | `__scope_fields__` | 路由 |
|------|-------------------|------|
| `MasterRealname` | `{"owner": "user_id"}` | `scope_model=MasterRealname` |
| `MasterSimCard` | `{"owner": "assigned_user_id"}` | `scope_model=MasterSimCard` |

这两张表没有 dept 列，DEPT 不贡献行，列表为空。`Repository.get` 本身不套数据范围，按 id 读改走 `read_in_scope`（或服务内同名谓词 `realname_matches_scope` / `sim_matches_scope`，与列表同一条件）。DEPT 且没有 SELF 命中时 1504。ALL 不额外限制。SELF 只命中 owner 列。

**证件（自定义谓词，不挂 scope_model）**

单列 owner 表达不了 01 的「实名人 `user_id` 或 `holder_user_id`」。证件路由不挂 `scope_model`，避免空字段启动失败，也避免仓储只滤一列。列表在 `Repository._base_query`（租户 + `deleted == 0`）之后调用 `cert_matches_scope`，`apply_scope=False`。业务代码不写 `tenant_id` 条件。

`cert_matches_scope`（CT-01，并给 Q-T9 复用）：

1. 只有 `ims:cert:archive:query-self`、没有 `ims:cert:archive:query`：命中「实名人 `user_id` = 当前用户，或 `holder_user_id` = 当前用户」。角色即使是 ALL 也不放宽。实名人条件同时要求在职且 `deleted == 0`。
2. 有 `ims:cert:archive:query`：
   - 范围含 `ALL`：本租户未删除证件都可见；
   - 否则并集里只有 `SELF` 能命中，条件与上一条相同；`DEPT` 不贡献证件行；
   - 全部角色都没配置数据范围：列表空，按 id 读 1504，写接口 1008（B0a FP-C02-02）。
3. 同时持有 `query` 和 `query-self`：按 `query` 的数据范围。01 写的是「只有 query-self 时」才收窄。

选择器 `list_company_options`、`list_realname_options`、`list_sim_card_options` 使用 `require_login`，不挂 `scope_model`，也不调用 `_apply_data_scope`。公司选择器返回启用且 `deleted == 0` 的公司。实名人选择器返回在职且 `deleted == 0` 的实名人（离职记录 `deleted` 仍为 0，靠状态排除）。手机卡返回未停用且 `deleted == 0`。字段只有 id、名称、脱敏号码，最多 50 条（Q-T8）。

| 用例 | 断言 |
|------|------|
| `UT-B5-BG-04-SCOPE-ALL` | ALL 角色的 `page_companies`、`list_certs` 能看到他人数据 |
| `UT-B5-BG-04-SCOPE-DEPT` | DEPT 角色的 `page_companies`、`get_company` 仍返回同租户公司；实名人、手机卡、证件列表为空；`get_realname`、`get_sim_card`、`get_cert` 在非本人时 1504；`list_company_options` 仍返回启用公司 |
| `UT-B5-BG-04-SCOPE-SELF` | 公司列表与 ALL 相同，不因 SELF 滤空；实名人只命中 `user_id`；手机卡只命中 `assigned_user_id`；证件能命中「实名人关联的是自己、holder_user_id 不是自己」 |
| `UT-B5-CT-01-QUERY-SELF` | 仅 `query-self` 且角色为 ALL，仍只有本人证件 |
| `UT-B5-BG-04-SCOPE-STARTUP` | 公司路由没有 `scope_model`；实名人、手机卡路由的 `scope_model.__scope_fields__` 非空，`validate_scope_models` 通过 |

E2E 种子的数据范围：`test_admin`、`test_xz`、`test_xz2`、`test_ro` 为 ALL（`test_ro` 要能执行 `E2E-B5-CT-05`）。`test_self` 只授 `query-self`。

## 4. 权限（本批只授 R1）

Q-B1：种子只给角色 `role_key=R1` 补 0.3 的全部权限码。标准角色 R2～R11 本批一条都不授。管理员以后在角色页按权限码分配。E2E 用「测试-」角色，`role_key` 前缀 `e2e_`，由 `tools/e2e_seed/b5.py` 创建，不写进标准角色种子。

`grant_b5_to_r1`（`tools/seed/`，只补缺不覆盖）写完 R1 菜单后 `Cache.incr("ims:perm_ver:t:{tid}")`，已登录的 R1 下一请求按第 2 节重新取权限。业务增删改不递增 `perm_ver`。

证件删除码 `ims:cert:archive:delete` 只出现在 R1 的授权里。`e2e_resource_admin`（`test_xz` / `test_xz2`）授予档案的 query、upload、review，**不授 delete**，与 `E2E-B5-CT-11` 一致。02 §0.2 的 `ims:cert:archive:*` 按这条收窄，不包含 delete。

级别配置 `ims:cert:security:config` 同样只授 R1。`test_xz` 有 `ims:cert:security:audit`，能看审计和风险报告，不能改级别（`E2E-B5-SC-03`）。

原图 L1 / L2 / L3 不是权限码。`resolve_view_level`：启用角色在 `CertLevelRule` 里的级别取最大，人在 `CertL3Whitelist` 则为 3，否则默认 1。R1 种子写入 L3 白名单。R1 不豁免高频 1035（Q-B10）。

无权限按钮前端用已有 `v-perm` 不渲染。接口仍由 `require_permission` 返回 1008。

### 5.5 OCR：复用培训 AI，不另起一套

OCR 以工作包 Q-B9 为准（老板消息里曾编号为 Q-B2，不另写一套规则）。00 §2「不做 OCR」与此冲突，由产品改 00，本文件和代码不改那一句。与 B21、B10 `FP-B10-CF-06` 共用 `TrainAIClient`（`app/integrations/train_ai/client.py`）和配置键 `train_ai.enabled`、`train_ai.mode`、`train_ai.base_url`、`train_ai.model`、`train_ai.api_key`、`train_ai.timeout_ms`。

`recognize_cert` 不新建客户端类，不新建配置表，不新建 HTTP 栈。它调用同一类上新增的 `recognize_image`：

- 配置读取、mock / real、超时、调用日志与 `generate_questions` 同一路径
- `app/services/cert.py` 和 `app/api/cert.py` 不出现地址或模型名字面量（`UT-B5-CT-06-LITERAL`，口径同 B0a `UT-H08-12`）
- 请求前对 `train_ai.base_url` 调用 `assert_http_url`：scheme 不是 `http` 或 `https` 时当作未配置。不解析主机，不拒绝私网、环回、链路本地
- PDF 只取第 1 页交给模型；转页失败走未识别，不报新错误码
- 调用日志 `scene=CERT_OCR`，不记图片字节、不记证件号明文
- 未配置、失败、超时（客户端今天会抛 1106 / 1107 / 1109）全部吞掉，接口 `code=0` 且 `recognized=false`。前端提示「识别失败，请手工填写」
- 成功返回 `{recognized, name, certNo, issueDate, expireDate}`，只预填。入库仍走 `upload_cert` 的全量校验。`ocr_result` 存 JSON，其中证件号经 `encrypt_field`

B10 未合入时，单测和 E2E 把 `train_ai.mode` 设为 mock，不读模型连接表。B10 合入后只改配置来源到培训 AI 那一行，`recognize_cert` 的入参不变。`qwen` 是否接受图片是联调项：不支持时由 B10 给培训 AI 记录加可选 OCR 模型名，空则仍用 `train_ai.model`。B5 不改 B10 的表。

### 5.8 上传校验与外链

`validate_cert_file`（`app/services/cert_file.py`）在落盘前执行，scene 注册表 `app/core/file_scenes.py` 增加 `cert`：

| 检查 | 允许 | 失败 |
|------|------|------|
| 扩展名 | `.jpg` `.jpeg` `.png` `.pdf` | 5005「仅支持 jpg、jpeg、png、pdf 格式」 |
| MIME | `image/jpeg`、`image/png`、`application/pdf` | 5005「文件内容与格式不符」 |
| 文件头 | JPEG `FF D8 FF`，PNG `89 50 4E 47`，PDF `%PDF` | 同上 |
| 大小 | ≤ 20MB（证件页面规格） | 5005「文件不能超过 20 MB」 |

扩展名、MIME、文件头三者不一致即 5005。不调用未安装的系统 libmagic，直接比文件头，避免环境差异。场景 `watermark=True`。

`assert_http_url`（`app/integrations/base.py`）只做 scheme 门禁：允许 `http`、`https`，拒绝 `file`、`ftp`、无 scheme、其他 scheme。函数不解析主机，`http://127.0.0.1` 通过。`TrainAIClient` 真实调用前用它检查 `train_ai.base_url`，拒绝时 OCR 返回 `recognized=false`。用户表单没有外链字段，上传不接受 URL 代替文件。
