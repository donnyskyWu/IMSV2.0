## 1. 边界

本线做 `/profile` 页内三个 Tab（基本信息、修改密码 / 设置密码、我的会话）和 E2E-B2-PC-01～03。权限 `LOGIN_ONLY`，不设权限码。

顶栏头像下拉〔个人中心〕〔退出登录〕归 **#26**（产品裁定）。本线不改 `ims-web/src/components/layout/AppLayout.vue`。E2E-B2-PC-01 步骤 1 的下拉点击依赖 #26 把〔个人中心〕链到 `/profile`；页内断言直接打开 `/profile`。

`POST /admin-api/ims/auth/password/set`、`GET /admin-api/ims/auth/session/my`、`DELETE /admin-api/ims/auth/session/my?sid=` 的后端按 #26 §2.9 由 #26 实现。本线只调用。不第二套改密。

须改密时路由守卫仍把 `/profile` 带回 `/password-reset`（B0b FP-R-04）。强制改密只走已有 `ims-web/src/views/ChangePassword.vue`。

### 2.1 改密语义（#16，不改顺序，不并行实现）

`AuthService.change_own_password`：用户不存在 1002；旧密码不匹配（空哈希也算）**1214**；新密码过短、含空格、缺字母或数字、或与当前密码相同 **1001**。过短用已有 1001，不新造码。旧密码也错且新密码过短时，现码先 1214。

成功后其他会话作废，当前会话保留。被作废的会话下一次请求 **1002**。

### 2.2 本人写入只接受允许字段

#26 未写这条。本线仍要求，并标在 §5：

| 接口 | 允许字段 |
|---|---|
| `POST /auth/password/change` | `oldPassword`、`newPassword` |
| `POST /auth/password/set` | `newPassword` |

`roleIds`、`tenantId`、`status`、`deptId` 以及其他未列入的键静默忽略。允许字段照常保存，返回成功，不因多了这些键返回 1001。PC-01 没有更新接口。测试用请求之外的连接查库，被忽略列与保存前一致。

### 2.3 权限即时生效与会话失效

产品裁定，不新造错误码：

- 权限变化（角色、菜单、套餐）后，下一次请求按新权限返回 **1008** 或 **1216**。
- 会话失效（改密作废其他会话、下线、令牌失效）返回 **1002**。
- 实时权限用 `permVersion`（B0a FP-D03-04）：Redis `ims:perm:<userId>:<permVersion>`，变更时对该用户 `permVersion+1`（大批量用 `tenantPermVersion+1`），下次请求比对版本再重算。

个人中心不改权限，只消费这个结果。#26 §1.7 把停用用户的下次请求写成 1002，与本裁定不一致，见 §5。

### 2.4 钉钉设置密码

main 已含 #20（`6ce0a0c`）。E2E-B2-PC-02 不再等该 PR。扫码与免登走已有：

- `GET /admin-api/ims/auth/login-options`
- `GET /admin-api/ims/auth/sso/dingtalk/authorize-params`
- `GET /admin-api/ims/auth/sso/dingtalk/callback`
- `POST /admin-api/ims/auth/sso/dingtalk/h5-login`

实现在 `ims-backend/app/services/dingtalk_login.py`。`password_hash` 为空时 Tab 显示「设置密码」，无当前密码项。设置成功后可用账号密码登录。

## 5. 与 #26 仍不一致

1. 顶栏。#26 §0.1 写「B0b 已交付、无需本批实现」，路径是 `ims-frontend/src/layouts/AppLayout.vue`。该路径不存在。产品裁定入口归 #26。真实文件是 `ims-web/src/components/layout/AppLayout.vue`，下拉项目前没有路由命令。
2. #26 未写 `password/set` 与会话列表的 JSON 字段。01 只给了 `newPassword` 和查询参数 `sid`。v0.1 里的 `loginTime` / `loginMethod` / `current` 等名字作废，不能当成已对齐。
3. #26 的 PC-01 只复用 `GET /me`，没有手机、角色字段。现有 `UserInfo` 也没有手机和角色名。01 要求展示脱敏手机和角色。谁补字段，#26 没写。
4. 多余字段静默忽略（§2.2）#26 没写。
5. #26 §1.7 写停用用户下次请求 1002。产品裁定是权限变化 1008 或 1216，会话失效才是 1002，实时权限走 `permVersion`。
6. #26 把单测放在 `ims-backend/tests/services/`、`ims-backend/tests/api/`，E2E 放在 `ims-frontend/e2e/b2-system/`，P0 脚本写成 `scripts/coverage_check.py`，另写了不存在的 `scripts/check_empty_tests.py`，Playwright 项目写成 chromium / firefox / webkit。这些路径和项目名都不在仓库里。以 §3 的真实路径为准。
7. #26 §5.1 把新接口写进 `app/api/system.py`，但 `password/set` 与 `session/my` 的前缀是 `/admin-api/ims/auth`，现有路由在 `ims-backend/app/api/auth.py`。
8. 分工：v0.1 写个人中心一个 PR 含后端。#26 §2.9 改为 set / session 后端在 #26，页面和 E2E 在本线。本版按 #26。
