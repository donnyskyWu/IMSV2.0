## 1. 边界

做：`/profile` 页（AppLayout 内、无菜单二级页）和页内三个 Tab：基本信息、修改密码 / 设置密码、我的会话。权限是 `LOGIN_ONLY`，不设权限码。

不做：顶栏头像下拉的〔个人中心〕入口和〔退出登录〕。`AppLayout.vue` 里该菜单项目前没有路由命令，归另一名 B2 代理。本切片不改 `AppLayout.vue` 的下拉模板和 `handleLogout`。

E2E-B2-PC-01 步骤 1 写的是「头像下拉 → 个人中心」。本切片的页面用例直接打开 `/profile`。下拉点击由顶栏那条线验收，不在本文件的用例里点菜单。

须改密时，路由守卫仍把 `/profile` 带回 `/password-reset`（B0b FP-R-04）。强制改密只走 B1 全屏页，不在个人中心完成。

## 3. 契约

### 3.1 PC-01 基本信息

只读。展示姓名（已有 `user.nickname`）、用户名、手机（脱敏）、主部门 / 所属部门、岗位、角色、数据范围（已有 `dataScopeText`）。没有保存按钮，不提交资料。

现有 `/me` 的 `user` 没有手机和角色，`deptNames`、`positionLabel` 仍为空。假设只追加这些只读字段，不改菜单树（菜单树归 BG-03 / Q1，本切片不动）：

| 字段 | 含义 |
|---|---|
| `user.mobile` | 脱敏手机。走现有 `UserService._mask_mobile`，响应里不出现明文 |
| `user.roleNames` | 启用角色名称 |
| `user.deptNames` | 所属部门名 |
| `user.mainDeptName` | 已有，补上真实主部门 |
| `user.positionLabel` | 岗位中文 |

字段名待对齐。页面用 `MaskedText`（UI-C39）、Tabs（UI-C03），不新造组件。

布局假设：`App.vue` 把所有 `menuless` 渲染成无侧栏，强制改密页依赖这一点。个人中心要留在 AppLayout 里，因此 **不改** `App.vue`。`Profile.vue` 自己包一层 `AppLayout`，靠 `menuless` 跳过外层，避免双顶栏。若另一份实现理解改由 `App.vue` 套布局，本页去掉内嵌布局。

### 3.2 PC-02 修改密码（复用 #16，不并行实现）

请求体只有 `oldPassword`、`newPassword`。规则、文案、错误码与 `ChangePassword.vue` 一致。

`AuthService.change_own_password` 的现有顺序保持不动：

1. 用户不存在 → 1002
2. 旧密码不匹配（空哈希也算不匹配）→ **1214**，字段文案「当前密码不正确」
3. 新密码含空格、不满足「8～32 位且同时含字母和数字」、或与当前密码相同 → **1001**（过短属于这一条）

须改密白名单只有这三条，其余 **1008**：

- `POST /admin-api/ims/auth/password/change`
- `POST /admin-api/ims/auth/logout`
- `GET /admin-api/ims/auth/me`

成功后：`pwd_reset_required=0`，该用户其他会话作废，当前会话保留。集成测试已覆盖（`test_real_db_api.py`：其他 access 变 401 + 1002，当前 `/me` 仍成功）。本切片不改这段实现，也不再写一个改密服务。

「短密码先报 1001」指：新密码过短的错误码是已有 1001，不新造码。旧密码错误单独是 1214。#16 的集成测试把这两件事分成两次请求。旧密码也错、同时新密码过短时，现码先返回 1214。不调整这个顺序。

### 3.3 PC-03 设置密码

仅当 `password_hash` 为空。已有密码再调 → **1001**（01 已写，不新造码）。新密码规则同 B0a FP-D01-02，不符也是 1001。确认密码只在前端比对，不进请求体。

成功后该用户可以用账号密码登录（E2E-B2-PC-02）。钉钉扫码登录在 #20，尚未合入；种子里的「钉钉甲」是无密码用户（B1 02）。实现 PR 不得把这条标成 skip。#20 与「钉钉甲」种子未就绪时，解禁条件写在实现 PR 描述里，不用假登录冒充扫码。

### 3.4 PC-04 我的会话

Redis `ims:session:<sid>` 今天只有 `user_id`、`tenant_id`、`refresh_token`、`created_at`、`expires_at`，没有 IP、设备、登录方式。登录日志有 `ip` / `user_agent` / `device` 列，但写入时没有填 `device`，且失败登录也在日志里，不能拿来当在线会话列表。

本批在 **创建会话** 时补写 `ip`、`device`（由 User-Agent 解析）、`login_method`。不改绝对 7 天、轮换、最多 3 条、被挤下线 1003。刷新轮换会改同一份 `session_data`，补写的键要留在字典里。登录日志列结构不改。

`GET` 假设返回：

```json
{ "list": [{ "sid": "", "loginTime": "", "loginMethod": "PASSWORD", "ip": "", "device": "", "current": true }] }
```

最多 3 条。`current` 为访问令牌里的 `sid`。空 IP / 设备显示「—」。

`DELETE` 只下线非当前会话：删该 sid 的会话键、刷新索引、加入 access 黑名单、从 `ims:user_sessions:<userId>` 移除。被下线的窗口再请求得到现有 **1002**（HTTP 401），E2E 表现为回登录页。

### 3.5 本人资料写入（只接受允许字段）

PC-01 不提供更新姓名、手机、部门、角色的接口。本切片的本人写入只有设置密码，以及复用的改密。

允许字段：

| 接口 | 允许字段 |
|---|---|
| `POST /auth/password/change` | `oldPassword`、`newPassword` |
| `POST /auth/password/set` | `newPassword` |
| 本人资料更新 | 01 未列。默认不新增。另一份实现理解若列出允许字段，以那份为准 |

请求体里的 `roleIds`、`tenantId`、`status`、`deptId` 以及其他未列入的键 **静默忽略**。允许字段照常保存，返回成功（`code=0`），不因为多了这些键返回 1001。Schema 保持忽略多余字段，不用 `extra=forbid`。

测试用请求之外的新连接查库：被忽略字段与保存前一致（用户的 `tenant_id`、`status`、角色、部门归属不变）；允许字段已按规则落库。改密接口上多传这些键时同样忽略，1214 / 1001 的原有语义不变。

## 5. 质量门槛（实现 PR 才执行）

- 新用例放 `tests/integration/test_b2_profile_api.py`，pytest + FastAPI TestClient，连真实 MySQL 8 与 Redis 7（`IMS_DB_URL`、`IMS_REDIS_URL`）。
