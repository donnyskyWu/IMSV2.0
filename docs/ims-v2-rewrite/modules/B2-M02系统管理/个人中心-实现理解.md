### 2.1 改密与设置密码：只作废其他会话

两条都复用 main 上已有的 `AuthService.change_password(user_id, new_password, keep_session_id)`，传入当前会话 id。成功后：

- 当前 token 仍然有效
- 其他 token 返回 **1002**
- `pwd_reset_required` 清掉

作废会话只做三件事：删会话键 `ims:session:<sid>`、写入 `ims:token_blacklist:<sid>`、从 `ims:user_sessions:<userId>` 移除。不用 `token_version`。

`change_password` 不再增加 `token_version`。当前会话靠 `keep_session_id` 保留。PC-02、PC-03 的会话断言在本分支真跑。

测试（用例名，不写行号）：

- 已有：`TestPasswordChange.test_current_session_survives_password_change`、`TestPasswordResetGate.test_change_endpoint_requires_user_and_keeps_session`、`test_real_lock_freeze_and_password_change`
- 规则与 1214 / 1001：`TestPasswordChange.test_rules_and_persistence`。旧密码也错且新密码过短时，现码先 1214，不改这个顺序
- 设密成功：UT-B2-PC-03-01 断言当前 token 仍成功、其他 token 为 1002、`pwd_reset_required=0`。不断言 `token_version` 增加

### 2.2 只接受允许字段

| 接口 | 允许字段 |
|---|---|
| `POST /auth/password/change` | `oldPassword`、`newPassword` |
| `POST /auth/password/set` | `newPassword` |

`roleIds`、`tenantId`、`status`、`deptId` 静默忽略，返回成功，不因这些键返回 1001。PC-01 没有更新资料接口。

### 2.3 删除、冻结、离职与权限

用户状态只有三种：`ACTIVE`、`FROZEN`、`RESIGNED`。删除是操作，不是状态。

删除规则：只有从未登录的用户可删除（`last_login_time` 为空），写入 `deleted = user.id`。main 上的 `UserService.delete_user` 还没有调用 `_drop_sessions`，由 #26 补上。已删除用户的旧 token 返回 **1002**。个人中心不实现删除用户。

权限热缓存仍是 main 的 `ims:perm:{userId}`（`AuthService.PERM_CACHE_PREFIX`），TTL 30 分钟。v1.9 起版本号不再拼进这个键。权限变更时递增 Redis 版本号并主动删掉热缓存，下一请求返回 **1008**。版本号键：用户级 `ims:perm_ver:u:{uid}`，租户级 `ims:perm_ver:t:{tid}`。不进数据库列，不进 JWT。冻结、离职返回 **1216**。

租户停用或过期：登录、刷新、在线请求都返回 **1008**，文案「所属组织已停用，请联系管理员」。

refresh 与 main 保持同一条路径，只允许 #26 v2.0 列出的 4 处差异（本分支已并入 `67af27d`）：

1. 索引值从 `session_id` 改为 `session_id:user_id`，`_parse_claim` 按 `:` 拆出 user_id
2. `user_id` 传入 `_issue_rotated_tokens`
3. 会话缺失和黑名单分支用 user_id 查用户，冻结或离职返回 **1216**，其余 **1002**
4. 冻结或离职分支返回 **1216**（main 是 1002）

令牌仍是 `secrets.token_urlsafe` 随机串，不是 JWT。领取仍用 `Cache.claim_refresh`。租户换套餐同步 R1（只补不删，并递增 `ims:perm_ver:t:{tid}`）归 #26 的 T-03，个人中心不实现；权限变化后的 **1008** 与上表同一口径。

会话缺失或已在黑名单时，先查用户再决定错误码。访问令牌用 JWT 的 `sub`。refresh 的用户 id 来自索引值。下面这张表同时适用于访问令牌和 refresh（冻结或离职就是 **1216**，不再单列一行）：

| 查到的情况 | 结果 |
|---|---|
| `deleted <> 0`，或没有这个用户 | **1002** |
| `deleted = 0` 且状态为 `FROZEN` 或 `RESIGNED` | **1216** |
| 其余（含在职用户的会话已被删掉） | **1002** |

| 情形 | 结果 | 用例名 |
|---|---|---|
| 管理员删除用户（逻辑删除，不是状态） | 旧 token **1002** | E2E-B2-U-15、UT-B2-BG-07-02 |
| 冻结 | 旧 token **1216** | E2E-B2-U-10、UT-B2-BG-07-03 |
| 离职 | 旧 token **1216** | E2E-B2-U-14、UT-B2-BG-07-04 |
| `verify_token` 时会话已失效且用户已冻结 | **1216** | UT-B2-BG-07-06 |
| refresh 时会话已失效且用户已冻结 | **1216** | UT-B2-BG-07-07 |
| 权限变化（角色、菜单、套餐） | 下一次请求 **1008** | UT-B2-BG-07-01、UT-B2-BG-07-05 |
| 租户停用或过期 | **1008**，文案「所属组织已停用，请联系管理员」 | E2E-B2-T-03 |
| 改密、设密作废的其他会话，或下线他人会话 | **1002** | E2E-B2-PC-03、UT-B2-PC-04-06 |

E2E 断言响应码，并断言旧 token 再请求被拒绝。

### 2.4 我的会话

`GET` 的 `data.list` 只有六个字段：`sid`、`deviceName`、`ip`、`loginTime`、`lastActiveTime`、`current`。页面不显示登录方式。最多 3 条，沿用 main `AuthService.MAX_SESSIONS = 3`：登录时挤掉最旧的一条。个人中心不再做第二套上限。

`DELETE`：

| 情形 | 结果 | 用例名 |
|---|---|---|
| `sid` 为空 | **1001** | UT-B2-PC-04-02 |
| 会话不存在 | **1504** | UT-B2-PC-04-03 |
| 会话属于别人 | **1504** | UT-B2-PC-04-04 |
| 当前会话 | **code 0**，与退出相同 | UT-B2-PC-04-05 |
| 其他会话 | **code 0**，该会话失效，其 token **1002** | UT-B2-PC-04-06、E2E-B2-PC-03 |

02 里「窗口 2 刷新」这一步允许 `page.reload()`。刷新只用于这一步，不能拿来代替等待。其余等待用断言。不用 `waitForTimeout` / `sleep`，不靠加大超时或 `retries` 变绿。

### 2.5 钉钉设置密码（E2E-B2-PC-02 真跑）

扫码与免登接口已在 main（#20，`6ce0a0c`）：`login-options`、`sso/dingtalk/authorize-params`、`sso/dingtalk/callback`、`sso/dingtalk/h5-login`，实现在 `ims-backend/app/services/dingtalk_login.py`。`ims-web/src/views/Login.vue` 今天只有账号登录。本线不做扫码组件，也不人工扫码。

E2E-B2-PC-01～03 都在 `live-proxy` 真跑，连真实后端，不 `test.skip`。`playwright.live.config.ts` 的 `testMatch` 含 `live-proxy.spec.ts` 和 `b2-profile.spec.ts`。三个浏览器项目不收录，也不放同名 skip。`prod-build` 不跑。

`live-proxy` 下钉钉登录走 mock：

- 模式用 `DingTalkSettings.mode` 的默认值 `mock`（环境变量 `IMS_DINGTALK_MODE`）。同时设置非空 `IMS_DINGTALK_APP_KEY`，否则 `load_dingtalk_config` 视为未启用。不把 mode 设成 `real`。
- `authCode` 不来自钉钉 App。用例先调 `GET /admin-api/ims/auth/sso/dingtalk/authorize-params`，拿到写进 Redis `ims:sso_state:` 的 `state`。再让浏览器打开 `GET /admin-api/ims/auth/sso/dingtalk/callback?authCode=<任意非空串>&state=<该 state>`。callback 认查询参数 `authCode`、`auth_code`、`code`。
- mock 不看这个串的内容。`HttpxDingTalkLoginClient.exchange` 在 mode 不是 `real` 时固定返回 `DingTalkClient` 的 mock 用户：`user_id=mock_dingtalk_user_001`，`mobile=13800138000`，`union_id=mock_union_001`。
- 种子「钉钉甲」在 `ims-backend/tools/seed/users.py`，只在 e2e 环境写入。main 上没有这个账号。昵称是「钉钉甲」。登录名与映射都是 `mock_dingtalk_user_001`（登录接口用户名至少 4 位，不能用三个汉字）。`password_hash` 为空，映射行 `dingtalk_user_id=mock_dingtalk_user_001`。重复执行种子时只把密码清回空，不改姓名。`DingTalkLoginService._match` 按这个 userid 命中。
- 成功后 callback 302 到 `/sso-callback#accessToken=...&refreshToken=...`。main 上没有落地页，本线补了 `ims-web/src/views/SsoCallback.vue`：读片段后立刻清掉片段。不新建扫码页。CI 的 live-proxy 作业设置 `IMS_DINGTALK_MODE=mock` 和 `IMS_DINGTALK_APP_KEY=e2e-ding-client`。

断言：

- 页面显示「设置密码」
- 没有「当前密码」
- 设置成功后可以用账号密码登录
- 设密前的当前 token 仍然有效（§2.1）
