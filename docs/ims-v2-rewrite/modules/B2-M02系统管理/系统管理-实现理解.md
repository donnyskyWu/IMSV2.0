### 1.5 【小黑-5】Q1 `/me` 祖先目录补全

**要求**：`/me` 由后端补祖先目录；B1 的 visibleMenus 按 `/me` 返回的树原样过滤，前端不要再补祖先目录。

**实现方式**：

1. **后端 `_build_user_menu_tree()` 扩展**（修改 `app/services/auth.py`）：

```python
# 伪代码：补全祖先目录
def _build_user_menu_tree(self, user_id: int, tenant_id: int) -> list[dict]:
    # 1. 获取用户角色授权的叶子菜单 ID（MENU 和 BUTTON）
    role_menu_ids = self._get_role_menu_ids(user_id)
    
    # 2. 与租户套餐取交集
    role_menu_ids = self._intersect_with_package(role_menu_ids, tenant_id)
    
    # 3. 补全祖先目录：对每个已授 MENU，递归找 parent_id 直到根
    all_menu_ids = set(role_menu_ids)
    for menu_id in role_menu_ids:
        all_menu_ids |= self._get_ancestor_ids(menu_id)
    
    # 4. 查询所有需要的菜单（DIR + MENU），visible=0 的目录整枝不显示
    menus = session.query(Menu).filter(
        Menu.id.in_(all_menu_ids),
        Menu.status == "ENABLED",
        Menu.visible == 1,  # 隐藏的目录不带出
        Menu.type.in_(("DIR", "MENU")),
    ).all()
    
    # 5. 嵌套树构建（已存在 _nest_menu_tree）
    return _nest_menu_tree(menus)
```

2. **关键规则**：
   - 只授菜单时 `/me` 补祖先目录
   - 祖先目录 `visible=0` 时整枝不显示
   - 不带出同目录下未授权的兄弟菜单

3. **前端不再补祖先**：
   - `ims-frontend/src/stores/user.ts` 中 `visibleMenus` 直接使用 `/me` 返回的树
   - 删除前端递归补目录的逻辑（如有）

**对应测试**：

### 1.7 【小红-7】权限变更实时生效

**要求**：改角色、改菜单授权、停用用户后，在线用户的下一次请求就按新权限判（1008 或 1216），不等令牌过期。写明失效机制。

**实现方式**：

1. **权限缓存失效机制**（已存在 `_drop_cache`）：

```93:99:ims-backend/app/services/access.py
def _drop_cache(session: Any, role_id: int) -> None:
    from app.domains.sys.models import UserRole
    from app.services.auth import AuthService

    prefix = AuthService.PERM_CACHE_PREFIX
    for link in session.query(UserRole).filter(UserRole.role_id == role_id).all():
        Cache.delete(f"{prefix}{link.user_id}")
```

2. **触发时机**：
   | 操作 | 触发方法 | 影响用户 |
   |------|----------|----------|
   | 角色分配/移除菜单 | `grant_menu()` / `revoke_menu()` 调用 `_drop_cache(role_id)` | 该角色全部成员 |
   | 停用角色 | `role.status='DISABLED'` 后调用 `_drop_cache(role_id)` | 该角色全部成员 |
   | 用户分配/移除角色 | 直接删除 `PERM_CACHE_PREFIX{user_id}` | 当前用户 |
   | 停用用户 | `freeze_user()` 作废全部会话（黑名单 + 会话键删除） | 当前用户 |
   | 套餐变更 | 删除该租户全部用户的权限缓存 | 租户全部用户 |

3. **会话吊销时机**（已存在）：

```546:552:ims-backend/app/services/user.py
    async def freeze_user(self, user_id: str) -> None:
        """Freeze a user and invalidate every session (FP-B03-01)."""
        _session, user = self._load_user(user_id)
```

   - `POST /menu/create`、`PUT /menu/update`：查重返回 `BizError(1001, msg="权限码已存在")`

4. **删除已被引用**：
   | 资源 | 引用方 | 返回码 | 提示 |
   |------|--------|--------|------|
   | 菜单 | 角色、套餐、子菜单 | 1502 | 该菜单已被 n 个角色 / n 个套餐引用 |
   | 字典值 | 业务表（停用值不可删） | 1502 | 停用的字典值不能删除，可能被历史数据引用 |
   | 角色 | 用户成员、岗位供给规则 | 1502 | 该角色有 n 名成员 |
   | 部门 | 子部门、用户 | 1502 | 该部门下有 n 个子部门 / n 名人员 |
