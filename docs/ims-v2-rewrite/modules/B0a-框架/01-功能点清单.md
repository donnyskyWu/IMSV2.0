## 0. 约定

### 0.1 编号与书写
- 功能点编号 `FP-<任务号>-<序号>`，如 `FP-A02-03` 属于 FW-A02；单测用例编号 `UT-<任务号>-<序号>`。
- 每个功能点写：**输入 / 输出 / 规则 / 错误码 / 表或接口 / 依据**。“—”表示不涉及。
- 依据简称同 04 清单：【PRD】【共享规范】【全局规范】【补充规范】（`产品规格/全局开发规范-完整版补充.md`）【错误码附录】（`产品规格/错误码映射表-附录.md`）【ADR-00x】【XX 规格/契约】【裁定 xxx】；“04-xx”指 04 清单条目；“FW-xx”指 01 清单任务。
- 标「**【本清单裁定】**」的是规格未写、由产品在本清单定的口径（我可裁定）；开发按此实现，规格文档在对应批次同步修改。

## A. 工程与通用约定（FW-A01～A06）

### FP-A01-01 应用工厂与分环境配置
- **输入**：环境变量 `IMS_ENV`（`dev` / `test` / `e2e` / `prod`）+ 配置文件 `config/<env>.yaml` + 环境变量覆盖（同名大写下划线）。
- **输出**：FastAPI 应用实例；只读配置对象 `settings`。
- **规则**：
  1. 配置分组：`db`（IMS 主库，开发 / 测试库名按字面 **`imsV2.0`**）、`football_live`（只读连接串、结构定义文件路径——结构定义以 `live_room-真实DDL.sql` 为准，FW-H06）、`redis`、`jwt`（密钥、access 2h、refresh 7d）、`file`（`storage_root`）、`dingtalk`（IMS 应用 AppKey/AppSecret/AgentId/模式）、`dingtalk_attendance`（考勤应用独立一组，FW-H07）、`train_ai`（培训 AI 客户端运行时读取的配置键，FW-H08；**默认值仅作框架占位，真实维护与读取走 B10，不进 B2 系统参数页**）、`integrations.<系统>.mode`（`real` / `mock`）；内容 AI 与培训 AI 的正式模型连接均由 **M10 / B10** 业务表维护，不在 B2 系统参数页；

- **错误码**：—（启动期失败，不对外）。
- **表或接口**：—。
- **依据**：FW-A01；【ADR-009】§1；D-06、D-07、D-08、培训 AI 决策。

### FP-A01-03 健康检查
- **输入**：`GET /health`（匿名）。
- **输出**：`{code:0, data:{status:"UP"|"DEGRADED", db:"UP"|"DOWN", redis:"UP"|"DOWN"|"MEMORY", footballLive:"UP"|"DOWN"|"DISABLED", version}}`。
- **规则**：IMS 主库 DOWN → `status=DOWN` 且 HTTP 503；Redis 或 Football 只读库 DOWN → `DEGRADED`（HTTP 200）；不输出任何连接串。
- **错误码**：—。
- **表或接口**：`GET /health`。
- **依据**：FW-A01；FW-H06（Football 不可用不影响 IMS 场次功能）。

### FP-A01-04 请求上下文

- **输出**：`ctx`（contextvars）：`traceId`、`userId`、`tenantId`、`permCodes`、`dataScopes`、`deptIds`、`ipGroupIds`、`clientIp`。

### FP-A02-02 错误码注册表
- **输入**：`app/core/error_codes.py` 中按域登记的条目：`code`、`domain`、`msg`（中文业务句，可含 `{占位}`）、`frontStrategy`（`toast` / `relogin` / `noPermission` / `silent` / `fieldError`）。
- **输出**：`BizError(code, **params)` 抛出时自动取中文提示；导出 JSON 供前端（FP-H03-01）。
- **规则**：
  1. 号段表取【错误码附录】§2 与本清单 0.4，域与号段一一对应；
  2. 同码重复登记 → 启动失败；域登记了不属于自己号段的码 → 启动失败；跨域通用码 1001、1008、1500～1504、5001～5007 归“COMMON”域，任何域可抛；
  3. 中文提示不得含英文枚举码、接口路径、开发代号（【裁定】B025）——静态检查登记表中的 `msg`：出现 `[A-Z_]{3,}` 或 `/admin-api` 即失败（错误码数字本身不算）。
- **错误码**：—。
- **表或接口**：—。
- **依据**：FW-A02；【错误码附录】§1～§4；【裁定】B025。

### FP-A02-03 全局异常处理
- **输入**：请求处理中抛出的任何异常。
- **输出**：
  - 参数校验失败 → `code=1001`，`data.fieldErrors=[{field, message}]`（字段名为 camelCase，message 中文）；
  - `BizError` → 对应码与中文提示；
  - 数据库异常 → 5001；Redis 异常 → 5002；外部适配器超时按各自码（钉钉 5003、Football 1271 等）；
  - 其他未分类异常 → **5007**「系统繁忙，请稍后再试」。
- **规则**：响应体与 `msg` 不得包含堆栈、SQL、内部类名；完整堆栈只写服务端日志并带 `traceId`；1504 一律使用通用提示“资源不可用”，不带 id、名称。
- **错误码**：1001、5001、5002、5003、5007、1504。
- **表或接口**：—。
- **依据**：FW-A02；【错误码附录】§4；【SYS 规格】P2A 第 5 条；本清单 0.4。

### FP-A03-01 分页参数与结果
- **输入**：`pageNo`（≥1，默认 1）、`pageSize`（1～100，默认 10）。
- **输出**：`data={list:[], total:int, pageNo, pageSize}`。
- **规则**：`pageNo<1`、`pageSize<1` 或 `>100`、非整数 → 1001；`total` 为满足条件的总数（含数据范围过滤后）。
- **错误码**：1001。
- **表或接口**：所有分页接口。
- **依据**：FW-A03；【ADR-009】§3；【全局规范】§2.5；0.3 本清单裁定。

### FP-A03-02 排序白名单
- **输入**：`sortField`（camelCase）、`sortOrder`（`asc` / `desc`，默认 `desc`）。
- **输出**：按白名单字段排序；未传时按模型声明的默认排序（缺省 `createTime desc, id desc`）。
- **规则**：每个分页接口在定义时声明可排序字段；不在白名单内 → 1001（`fieldErrors` 指向 `sortField`）；排序值不拼接进 SQL 字符串。
- **错误码**：1001。
- **表或接口**：所有分页接口。
- **依据**：FW-A03。

### FP-A04-01 命名转换
- **输入 / 输出**：接口 JSON 字段 camelCase ↔ 库列 snake_case，由 Schema 基类统一完成（Pydantic `alias_generator`）。
- **规则**：请求体只接受 camelCase；出现 snake_case 字段视为未知字段并忽略（不报错）；响应只输出 camelCase。
- **错误码**：—。
- **依据**：FW-A04；【ADR-009】§3；【全局规范】§1。

### FP-A04-02 时间与日期
- **规则**：库内 DATETIME 存北京时间（无时区）；输出 `yyyy-MM-ddTHH:mm:ss+08:00`；输入接受带时区（转换为北京时间）与不带时区（视为北京时间）；日期字段 `yyyy-MM-dd`；月份字段 `yyyy-MM`；非法格式 → 1001。
- **错误码**：1001。
- **依据**：FW-A04；【全局规范】§7.4。

### FP-A04-03 金额与百分比
- **规则**：金额类型 `Money`：输入接受数字或字符串，最多 2 位小数，超出 → 1001；运算用 Decimal；输出字符串两位小数（`"0.30"`）。百分比类型 `Percent`：界面输入 `5` 表示 5%，库存 `0.0500`（DECIMAL(6,4)），输出给前端为 `5`（数值）【本清单裁定：接口用百分数，库存小数】。
- **错误码**：1001。
- **依据**：FW-A04；【全局规范】§7.4；【裁定】BUG-070。

### FP-A04-04 枚举与主键输出
- **规则**：后端枚举一律字符串 canonical 值（如 `ACTIVE`），中文标签由字典提供（FP-B07-04 一致性校验）；入参非法枚举值 → 1503（字典值不合法）。主键默认输出数字；配置 `api.id_as_string=true` 时所有 `id`、`*Id` 输出字符串（迁移前核查，见 04-B-05）。【已核实，见 04 §3：Football `system_users` 有 8 个 id 超过 2^53，建议默认开启，待裁定】
- **错误码**：1503。
- **依据**：FW-A04；【全局规范】§4；04-B-05。

- **输出**：`ims-backend/openapi.json`；前端 `ims-web/src/api/generated/<域>.ts`（类型 + 请求函数）。

- **错误码**：—。
- **依据**：FW-A05；【全局规范】§7.2、§7.3。

### FP-A06-01 脚手架输入定义
- **输入**：`tools/scaffold/defs/<域>/<表>.yaml`：表名、中文名、权限码前缀、字段（名、类型、长度、必填、唯一、字典类型、引用表与删除策略、是否敏感、是否列表列 / 查询条件 / 排序）、数据范围归属字段、默认排序、抽屉宽度（S/M/L）。
- **输出**：校验通过的定义；不合法 → 命令失败并列出问题（如引用表未登记、字典类型不存在、权限码前缀不符合 `ims:<域>:<资源>`）。
- **规则**：引用字段必须声明删除策略（FP-B06-01）；需要数据范围过滤的表必须声明归属字段（FP-C02-03）。
- **依据**：FW-A06；省用量规则第 5 条。

### FP-B01-01 审计基类
- **输入 / 输出**：所有 `ims_*` 模型继承 `AuditBase`：`id BIGINT 自增`、`tenant_id BIGINT NOT NULL`、`creator BIGINT`、`create_time DATETIME`、`updater BIGINT`、`update_time DATETIME`、`deleted BIGINT NOT NULL DEFAULT 0`。
- **规则**：
  1. `creator/updater` 取 `ctx.userId`（Worker 为 0，迁移脚本为固定用户名 `data-migration` 对应的系统用户 id，【共享规范】§7.7.2）；`create_time/update_time` 自动填充；
  2. 逻辑删除时 `deleted = id`（非 1）【本清单裁定：使“业务编码 + deleted”唯一键在删除后可重建同编码；判断“已删除”一律用 `deleted <> 0`】；
  3. 业务编码唯一键一律建为 `(tenant_id, 编码列, deleted)`；
  4. 测试扫描：`app/domains` 下任何 `ims_` 表模型未继承 `AuditBase` → 失败（`AuditBase` 例外清单仅：日志表、关联表——关联表只要求 `tenant_id`、`create_time`、`creator`）。
- **错误码**：重复编码 → 由各模块定义（框架提供 `UniqueConflict` 转换钩子，默认 1001 + `fieldErrors`）。
- **表或接口**：全部业务表。
- **依据**：FW-B01；【共享规范】§7.4.1、§7.5、§7.6；04-B-05、B-06。

- **字段**：`id`（迁入保留原值）、`username`（唯一：`tenant_id+username+deleted`，4～30 位字母数字下划线）、`nickname`（页面统一称“姓名”，04-B-25）、`mobile_enc`（AES 密文）、`mobile_hash`（HMAC-SHA256，用于按手机号匹配，不可逆）【本清单裁定】、`email`、`password_hash`（bcrypt）、`status`（`ACTIVE` 在职 / `FROZEN` 冻结 / `RESIGNED` 离职，字典 `dict_user_status`）、`main_dept_id`、`position_code`（`dict_position`）、`login_fail_count`、`lock_until`、`last_login_time`、`last_login_ip`、`pwd_reset_required`（首次 / 重置后须改密）、`source`（`LOCAL` / `DINGTALK` / `MIGRATED`）+ 审计字段。

### FP-B06-01 引用登记
- **输入**：模型字段声明 `Ref(target="ims_master_realname", on_delete=RESTRICT|CASCADE_SOFT|SET_NULL, allow_disabled=False, external=False)`。
- **输出**：进程内引用登记表。
- **规则**：字段名以 `_id` 结尾且类型为 BIGINT 的列（审计列、`tenant_id` 除外）未声明 `Ref` 也未在 `NotARef` 例外中 → 启动失败；`external=True`（如 `football_room_id`）不参与删除保护与巡检中的“孤儿”判断。
- **依据**：FW-B06 第 1、4 条；D-02。

### FP-B06-02 写入前校验
- **规则**：新增 / 修改时，对每个非空引用字段在**同一事务**内 `SELECT … LOCK IN SHARE MODE` 读取被引用行：不存在或 `deleted<>0` → **1500**；跨租户 → **1504**；状态为停用 / 注销且该字段未声明 `allow_disabled` → **1501**。
- **错误码**：1500、1501、1504；`data.field` 指出字段名（camelCase）。
- **依据**：FW-B06 第 2、5 条。

### FP-B06-03 删除 / 停用前被引用检查
- **规则**：删除或停用主数据时，遍历以 `RESTRICT` 指向它的全部关系，统计未删除的引用行；有引用 → **1502**，`data.refs=[{entity:"平台账号", count:3}]`（中文实体名取登记册；只统计本租户）。停用检查同样适用（无论策略）。
- **错误码**：1502。
- **依据**：FW-B06 第 3 条；【错误码附录】§3。

### FP-B06-04 级联策略
- **规则**：`CASCADE_SOFT`：父记录逻辑删除时同事务逻辑删除子记录，任一失败整体回滚；`SET_NULL`：同事务将引用字段置空并写变更历史（FP-F02-01）；`RESTRICT` 见 FP-B06-03。
- **依据**：FW-B06 第 4 条。

### FP-B06-05 批量模式

- **输出**：每行的校验结果列表（行号、字段、错误码、中文原因）。
- **规则**：按被引用表批量 `IN` 查询，规则与单行完全一致；供导入（FP-H02-01）与迁移（FP-H05-02）使用。

### FP-B07-01 字典类型与字典值

### FP-B07-03 字典与参数缓存
- **规则**：字典按类型缓存于 Redis（键 `ims:dict:<type>`），参数缓存键 `ims:param:<key>`；修改后**同事务提交后立即删除缓存**，并发布失效消息；其他进程本地缓存 TTL 60 秒【本清单裁定】；前端字典接口 `GET /admin-api/ims/system/dict-data/simple-list?dictType=` 返回启用值（含 `colorType`）。
- **依据**：FW-B07“参数修改后缓存在约定时间内失效”——约定时间 = 60 秒。

### FP-B07-04 后端枚举与字典一致性校验
- **规则**：后端每个字符串枚举类声明 `__dict_type__`；测试遍历全部枚举，每个值在对应字典种子中都存在且有中文 `dictLabel`，缺失即失败；中文标签不得含英文大写编码（【裁定】B025）。

### FP-B08-01 部门表 `ims_sys_dept`

### FP-B08-02 部门树查询
- **输入**：`GET /admin-api/ims/system/dept/tree?status=&keyword=`。
- **输出**：树节点 `{id, parentId, name, source, status, localOrphan, memberCount, directMemberCount, leaderName, children}`。
- **规则**：
  1. `memberCount` = 本部门及全部下级部门内的**去重**在职 + 冻结用户数（不含离职）；`directMemberCount` = 直接归属本部门的人数（含非主部门归属）【本清单裁定：树上显示含下级人数，悬停显示直属人数】；
  2. `keyword` 命中部门名时返回该节点及其祖先路径（祖先保持可展开）；
  3. 默认不返回停用部门，`status=ALL` 时返回并标停用；
  4. 部门树本身**不受数据范围限制**（组织结构是公共信息），但仅持有 `ims:system:dept:query` 或 `ims:system:user:query` 者可调用【本清单裁定】；
  5. 性能：2000 个部门、2 万用户时响应 ≤ 500ms（单次聚合查询，不逐节点查）。
- **错误码**：1008。
- **依据**：FW-B08 第 2 条；【PRD】SYS-001“部门树”；OPS ADR-013。

- **依据**：FW-B08 第 2 条；04-B-26。

### FP-B08-07 停用 / 删除部门

- **依据**：FW-B08 第 3 条；04-A-22 第 7 条；OPS ADR-013。

## C. 数据层（FW-C01～C04）

### FP-C01-01 会话与事务
- **规则**：每个 HTTP 请求一个 IMS 主库会话；服务层方法以 `@transactional` 声明事务边界，嵌套调用复用外层事务；方法抛出任何异常 → 整体回滚；路由层不得直接 `commit`（静态检查）；Football 只读会话独立（FP-H06-01），不参与 IMS 事务。
- **依据**：FW-C01；【ADR-009】。

### FP-C01-02 通用仓储
- **方法**：`get(id)`（不存在、已删或跨租户 → 统一抛 1504）、`page(query, page)`、`list(query)`、`create(obj)`、`update(obj)`、`soft_delete(id)`（走 FP-B06-03/04）、`bulk_create`、`bulk_update`；参数 `include_deleted=True` 可查到已删除记录（仅限内部与巡检使用，接口层不得暴露）。
- **规则**：默认过滤 `deleted = 0`；所有方法自动经过租户与数据范围过滤（FP-C02）；乐观锁不默认启用，模型声明 `__versioned__=True` 时启用 `version` 列，版本冲突 → 1001（提示“数据已被他人修改，请刷新后重试”）【本清单裁定】。
- **错误码**：1504、1001。
- **依据**：FW-C01；【SYS 规格】P2A 第 5 条。

### FP-C02-01 租户过滤
- **规则**：ORM 查询编译阶段（`do_orm_execute` 事件）对所有含 `tenant_id` 的模型自动追加 `tenant_id = ctx.tenantId`；新增时自动写入 `ctx.tenantId`，请求体中的 `tenantId` 一律忽略；平台级表（菜单、字典、套餐、租户）声明 `__platform__=True`，读取不加租户条件、写入需平台租户（id=1）用户且持有对应权限码，否则 1008。
- **错误码**：1504（按 id 访问他租户数据）、1008。
- **依据**：FW-C02；04-B-06；【SYS 规格】P2A 第 1 条；【ADR-007】。

### FP-C02-02 数据范围谓词
- **输入**：`ctx.dataScopes`（用户全部**启用**角色的 `data_scope` 集合）、`ctx.deptIds`（用户全部所属部门，04-B-26）、`ctx.ipGroupIds`（用户所属 IP 组）、`ctx.userId`。
- **规则**：模型声明归属字段 `__scope_fields__ = {"dept": "dept_id", "ip_group": "ip_group_id", "owner": "owner_user_id"}`（可只声明部分）。谓词按角色取**并集**：
  - 含 `ALL` → 不加限制；
  - `DEPT` → `dept 字段 IN ctx.deptIds`（不含下级）；
  - `IP_GROUP` → `ip_group 字段 IN ctx.ipGroupIds`；
  - `SELF` → `owner 字段 = ctx.userId`（模型未声明 owner 时退回 `creator`）；
  - 多个范围用 `OR` 连接；某范围对应字段在模型中未声明时该范围对该模型**不贡献可见数据**（不视为全部）；
  - 全部角色都未配置数据范围（或无启用角色）→ 列表返回空、按 id 访问 → 1504，写接口 → 1008。
- **错误码**：1008、1504。
- **依据**：FW-C02、FW-D04；【PRD】§1.4 BR-305；【SYS 规格】P2 第 3 条、P2A 第 2 条；04-B-26、A-22 第 8 条。

### FP-C02-03 防漏配
- **规则**：路由声明 `scope_model=<模型>` 时该模型必须声明 `__scope_fields__`，否则启动失败；不需要数据范围的路由必须显式标注 `auth_level="LOGIN_ONLY"`（认证级白名单：只校登录 + 租户），白名单清单可导出审阅；业务代码出现 `tenant_id ==`、`.tenant_id==`、`filter_by(tenant_id=` → 静态检查失败（`app/db/` 除外）。
- **依据**：FW-C02 第 4、5 条。

### FP-C02-04 发布 / 分享数据双重过滤
- **规则**：模型声明 `__shared__=True` 时可见条件 = 查看者范围内 **且** 创建者在发布时的范围快照覆盖查看者（快照存 `publish_scope` JSON）；框架提供谓词函数，具体使用的模块（BI 报表等）在模块批次接入。
- **依据**：FW-C02；【PRD】BR-212。
- **说明**：BR-212 的“创建者范围”取发布时快照还是实时范围，规格未写，本清单裁定取**发布时快照**（发布后创建者调岗不影响已分享对象），BI 批次评审时再确认。

### FP-C02-05 fail-closed
- **规则**：非匿名白名单路由在处理时 `ctx.userId` 或 `ctx.tenantId` 缺失 → 1008（不是 500，不返回数据）；权限、范围计算任何异常 → 1008 并记录错误日志。
- **错误码**：1008。
- **依据**：FW-C02 第 6 条；【SYS 规格】P2A 第 4 条。

### FP-C03-01 字段加密
- **规则**：字段类型 `EncryptedStr`：AES-256-GCM，密钥来自配置 `security.field_key`（支持多版本，密文前缀带版本号便于轮换）；需要等值查询的字段额外生成 `<字段>_hash`（HMAC-SHA256，独立密钥）；库中密文 ≠ 明文、同一明文两次加密密文不同。
- **依据**：FW-C03；【PRD】BR-306。

### FP-C03-02 脱敏输出
- **规则**：Schema 字段声明 `Masked(kind="id_card"|"mobile"|"bank"|"cost", plain_perm="ims:<域>:<资源>:plain")`：
  - `id_card`：前 3 后 4，中间 `*`；`mobile`：`138****5678`；`bank`：后 4 位；
  - `cost`：成本类金额，用户持有 `plain_perm` 时返回明文，否则返回 `"***"`——R9 等只读财务查看角色不授予该权限码即得到 `***`（不按角色名判断）；
  - 有 `plain_perm` 的用户返回明文；查看证件原件另写查看日志（FP-F02-02）；
  - 导出（FP-H02-02）使用同一 Schema，脱敏一致。
- **依据**：FW-C03；【全局规范】§5.2；【裁定】BUG-080；04-A-07。

### FP-C04-01 通用编号生成器
- **输入**：规则名、业务日期、分组键（如平台码）。
- **输出**：编号字符串。
- **规则**：Redis `INCR ims:seq:<规则>:<日期>:<分组>`，TTL 48 小时；业务编码列唯一索引兜底，冲突重试 3 次仍失败 → 5001；Redis 不可用时降级为数据库行锁序列表 `ims_sys_sequence`，恢复后取两者较大值续号（【分期技术约束】V1-E4）。
- **首批规则**：竞品送审单号 `CA + yyyyMMdd + 4 位序列`、档案编号 `CP + yyyyMMdd + 4 位序列`【本清单裁定：位数沿用场次规则；【裁定】B089 只定了前缀】。
- **依据**：FW-C04；【共享规范】§7.4.3；【裁定】B089。

### FP-C04-02 场次编号
- **规则**：`IMS + yyyyMMdd（北京时间创建日期）+ 3 位平台码 + 4 位当日序列`，共 18 位（【共享规范】§7.4.3 写“19 位”，按其格式实际为 3+8+3+4=18 位，以格式为准）；序列按“日期 + 平台码”维度，日切重置；当日达到 9999 时降级为 5 位序列（共 19 位）并产生 P2 告警事件（【分期技术约束】V1-E5）；编码列名 `session_code`（04-B-22）。
- **平台码表**（字典 `dict_platform_type` 的 `ext_code`）【本清单裁定，04-B-22 要求产品出表】：

  | 抖音 | `DOUYIN` | `DYS` |

  | 公众号 | `WECHAT_MP` | `GZH` |

- **依据**：FW-B05、FW-C04；【共享规范】§7.4.3；04-B-22；D-04。

### FP-C04-03 幂等
- **输入**：请求头 `X-Client-Token`（UUID，≤64 字符）。
- **规则**：路由声明 `idempotent=True` 时：token 缺失 → 1001；Redis `SET NX ims:idem:<userId>:<路由>:<token>` 24 小时；首次请求执行并缓存响应；处理中重复到达 → 等待最长 5 秒后返回首次结果，仍未完成返回 1001（提示“请求处理中，请勿重复提交”）；已完成重复到达 → 返回首次结果，不再落库；首次失败（业务错误）也缓存结果。首批使用：场次创建、冲话费强制（模块批次接入）。
- **错误码**：1001。
- **依据**：FW-C04；04-B-14。

## D. 认证与权限（FW-D01～D07）

### FP-D01-01 账号密码登录
- **输入**：`POST /admin-api/ims/auth/login {username, password, captcha?}`（匿名）。
- **输出**：`{accessToken, refreshToken, expiresIn:7200, pwdResetRequired}`。
- **规则**：
  1. 用户不存在或密码错误 → **1214**（同一提示，不暴露存在性）；失败计数 +1；
  2. 连续失败第 5 次 → 设置 `lock_until = now + 15 分钟` 并返回 **1215**（`data.remainMinutes`）；锁定期内即使密码正确也返回 1215；锁定期过后首次登录前计数清零；
  3. 状态 `FROZEN` / `RESIGNED` → **1216**（在密码校验通过后判断，避免借此探测状态）；
  4. 租户停用或过期 → 1008；
  5. 成功：计数清零，写 `last_login_time/ip`，创建会话（FP-D01-03），写登录日志（FP-F01-02）；
  6. 不存在的用户名同样计数（按用户名维度存 Redis 15 分钟）以防撞库【本清单裁定】；
  7. 时间源可注入（单测用）。
- **错误码**：1001、1214、1215、1216、1008。
- **依据**：FW-D01；【ADR-009】；【PRD】AUTH-001；本清单 0.4。

### FP-D01-02 密码策略
- **规则**：长度 8～32，至少含字母与数字【本清单裁定】；bcrypt（cost=10）；管理员重置密码生成 10 位随机密码只显示一次，并置 `pwd_reset_required=1`；`pwd_reset_required=1` 的用户登录后只能调用“修改密码”“退出”“我的信息”接口，其余 → 1008（前端引导到改密页）；修改密码需校验原密码（错误 → 1214），新旧相同 → 1001；修改或重置密码后作废该用户全部其他会话。
- **错误码**：1001、1214、1008。
- **依据**：FW-D01；04-A-23（重置密码）、C-19（个人中心）。

### FP-D01-03 令牌与会话
- **规则**：access token = JWT（`sub=userId`、`tid=tenantId`、`sid=会话 id`、`exp=2h`）；refresh token = 随机串，Redis 存 `ims:session:<sid>`（7 天）；每个用户会话列表 `ims:user_sessions:<userId>`（按创建时间）；新会话使数量 > 3 时作废最早会话，被作废会话再次请求 → **1003**（HTTP 401）；refresh：`POST /admin-api/ims/auth/refresh-token {refreshToken}` 成功则签发新 access + 新 refresh（旧 refresh 立即失效，轮换）；refresh 无效、过期或重复使用 → 1002（HTTP 401）。
- **错误码**：1002、1003。
- **依据**：FW-D01；【ADR-009】；【AUTH 契约】第 119 行（1002 / 1003）。

### FP-D01-04 登出与强制下线
- **规则**：`POST /admin-api/ims/auth/logout` 删除当前会话并把 access 的 `sid` 写入黑名单（TTL = access 剩余时间）；管理员“强制下线”（权限 `ims:system:user:kick`）作废目标用户全部会话；冻结、离职、改密、重置密码时同样作废全部会话；被作废会话的请求 → 1002。
- **错误码**：1002、1008。
- **依据**：FW-D01；04-A-23。

### FP-D01-05 管理员解锁
- **规则**：`ims:system:user:unlock` 权限持有者可清除 `lock_until` 与失败计数；写操作日志。
- **依据**：04-A-23。

### FP-D02-01 钉钉 SSO 跳转与 state
- **输入**：`GET /admin-api/ims/auth/sso/dingtalk/redirect?redirect=<前端路由>`（匿名）。
- **输出**：302 到钉钉授权地址。
- **规则**：生成 32 位随机 `state` 存 Redis 5 分钟（值含 `redirect`，`redirect` 只允许站内相对路径，否则替换为 `/`）；钉钉未启用（`dingtalk.mode` 未配置）→ 页面提示“钉钉登录未开启”（登录页隐藏钉钉入口，接口返回 1008）。
- **依据**：FW-D02；【共享规范】§8.4；【ADR-009】。

### FP-D02-02 钉钉 SSO 回调
- **输入**：`GET /admin-api/ims/auth/sso/dingtalk/callback?authCode=&state=`。
- **规则**：
  1. `state` 不存在、过期或已使用 → **1002**（`GETDEL` 原子取出，只能用一次）；
  2. 经适配器用 `authCode` 换钉钉 userid 与手机号（超时 → 5003，钉钉返回错误 → 1006）；
  3. 匹配顺序：`ims_auth_user_mapping.dingtalk_user_id` → 未命中再按 `mobile_hash` 匹配本地用户（命中则补建映射）；均未命中 → **1217**，**不签发令牌**；
  4. 命中用户状态 FROZEN / RESIGNED → 1216；
  5. 成功：签发令牌（同 FP-D01-03，登录方式记“钉钉”），302 回前端 `/sso-callback#accessToken=…&refreshToken=…&redirect=…`（令牌放 URL 片段，不进服务端日志）【本清单裁定】。
- **错误码**：1002、1006、1216、1217、5003。
- **依据**：FW-D02；【ADR-009】“按手机号命中本地用户，命不中不签发”；【AUTH 契约】第 119 行；D-06。

### FP-D03-01 接口权限声明
- **规则**：路由依赖 `Depends(perm("ims:system:user:update"))`，可声明多个（任一满足 / 全部满足两种）；认证级白名单用 `auth_level="LOGIN_ONLY"`；匿名用 `auth_level="ANONYMOUS"`（仅限 FP-A01-02 列出的接口）；启动时扫描：业务路由三者皆无 → 启动失败；声明的权限码未在菜单种子中登记 → 启动失败。
- **依据**：FW-D03 第 1 条；04-C-13。

### FP-D03-02 权限判定
- **输入**：用户全部**启用**角色（`status=ENABLED`）的菜单权限码 + 功能点 R/W/D。
- **规则**：
  1. 权限集合 = 各启用角色并集 ∩ 租户套餐菜单；`DISABLED`、`PENDING_CONFIG` 角色不贡献任何权限；
  2. 读接口要求 R，写接口（新建、修改、提交等）要求 W，删除 / 作废接口要求 D；路由声明动作类型，默认 GET=R、其他=W；
  3. 不满足 → **1008**；集合为空 → 1008；
  4. 只读预览：对拥有 R 但无 W 的用户，读接口按自身数据范围返回数据（不 403、不 1008）（【裁定】C086）。
- **错误码**：1008。
- **依据**：FW-D03；【ADR-008】；【SYS 规格】P2A 第 4 条；【裁定】BUG-080、C086。

### FP-D03-03 禁止按角色名判断（静态检查）
- **规则**：`app/` 下（种子脚本除外）出现以下模式即失败：与 `"R1"`～`"R11"`、`"admin"`、`"super_admin"`、任何标准角色 `role_key` 字面量比较；`role_key`、`role.name` 出现在 `if` 条件中；`in roles`、`in role_keys`。
- **依据**：FW-D03 第 4 条；04-A-07；【评估】“157 处硬编码角色判断”。

### FP-D03-04 权限缓存与生效时间
- **规则**：用户权限快照缓存于 Redis `ims:perm:<userId>:<permVersion>`（TTL 30 分钟）；角色授权、角色状态、用户-角色、套餐菜单变更时，对受影响用户的 `permVersion` +1（大批量时对租户级 `tenantPermVersion` +1）；每个请求比对版本号，版本变化即重算——因此变更**即时生效**，满足“5 分钟内”；Redis 不可用时每请求从库计算。
- **依据**：FW-D03 第 5 条；【PRD】§9“权限同步 < 5 min”。

### FP-D04-01 数据范围配置
- **规则**：角色数据范围单选 `ALL` / `DEPT` / `IP_GROUP` / `SELF`（字典 `dict_data_scope`，中文：全部 / 本部门 / 所属 IP 组 / 仅本人）；未配置保存为空，空 = 无数据；执行见 FP-C02-02。
- **依据**：FW-D04；BR-305。

### FP-D05-01 岗位 → 角色供给
- **输入**：岗位变化事件（钉钉同步、本地改岗位）`{userId, oldPosition, newPosition, eventId}`。
- **规则**：
  1. 新岗位在规则表 `ims_auth_position_role_rule`（`position_code`、`role_id`、`version`、`status`、`archived`）中无规则 → 自动建角色 `source=DINGTALK_AUTO`、`status=PENDING_CONFIG`、无任何权限、`data_scope` 空，并建规则；给持有 `ims:system:role:update` 的用户生成待办“新岗位「xx」已生成待配置角色，请配置权限”（G1，fail-closed）；
  2. 授予：给用户加 `source=DINGTALK_AUTO` 的用户-角色（若该用户+角色存在 `manual_removed=1` 则跳过）；
  3. 回收：岗位变更时只回收原岗位对应的 `DINGTALK_AUTO` 角色，`MANUAL` 授予不回收；
  4. 幂等：按 `eventId` 去重（`ims_auth_event_log` 唯一键），重复投递结果不变；
  5. 规则修改生成新版本，旧版本归档可查。
- **错误码**：—（异步处理，失败进重试，FP-D07-05）。
- **依据**：FW-D05；【ADR-008】G1～G7；【AUTH 规格】P3；04-A-24、A-25；【裁定】BUG-060。

### FP-D06-01 我的菜单与权限
- **输入**：`GET /admin-api/ims/auth/me`（`LOGIN_ONLY`）。
- **输出**：`{user:{id, username, nickname, avatar, mainDeptName, deptNames[], positionLabel, pwdResetRequired}, menus:[树], permCodes:[...], permDetails:{code:{r,w,d}}, dataScopeText:"本部门（市场一部、市场二部）"}`。
- **规则**：菜单树 = 租户套餐菜单 ∩ 启用角色菜单，按 `sort` 排序，只含 `DIR` / `MENU`（`BUTTON` 只体现在 `permCodes`）；`dataScopeText` 用字典中文 + 部门名 / IP 组名，多角色用“、”连接，不出现枚举码（【裁定】B025）；`PENDING_CONFIG` 或空权限用户返回空菜单与提示文案“您的账号尚未分配权限，请联系管理员”。
- **依据**：FW-D06；【SYS 规格】P3、P8；【裁定】B025。

### FP-D07-01 钉钉事件接收
- **输入**：`POST /admin-api/ims/callback/dingtalk/event`（匿名，验签）：人员入职 / 变更 / 离职、部门新增 / 变更 / 删除。
- **规则**：验签失败 → 拒绝（HTTP 200 + 1008，不处理）；事件先落 `ims_auth_org_sync_event`（`event_id` 唯一、`event_type`、`event_time`、`payload`、`status`（`PENDING` 待处理 / `SUCCESS` 成功 / `RETRYING` 失败重试 / `DEAD` 死信）、`retry_count`、`last_error`）后立即应答，由 Worker 异步处理；重复 `event_id` 直接应答成功不重复入库。
- **依据**：FW-D07 第 1 条；【AUTH 规格】P2 `OrgSyncStatus`；【共享规范】§8.4。

### FP-D07-02 部门同步（钉钉为准）
- **规则**：
  1. 只处理 `dingtalk_dept_id` 非空的部门；
  2. 钉钉新增 → 新建 `source=DINGTALK`；钉钉变更 → 用钉钉值覆盖名称、上级、排序、负责人，若本地值与钉钉值不同，把被覆盖的本地值写变更历史（FP-F02-01，`reason=DINGTALK_OVERRIDE`）；钉钉上级不存在于 IMS 时先拉取上级再处理；
  3. 钉钉删除 → IMS 部门停用 + 逻辑删除；其直属成员按钉钉最新归属更新；在钉钉中已无任何部门的成员、以及该部门下未绑定钉钉的本地用户 → 移入「待分配」并设为主部门；给持有 `ims:system:user:update` 的用户发待办（一个部门一条，列出人数）；
  4. 被删部门下的 `LOCAL` 子部门（含其本地子树、成员）→ 改挂到**最近的仍存在的祖先**（全无则根部门），`local_orphan=1`，生成待办“本地部门「xx」的上级已被钉钉删除，请确认保留、改挂或删除”；不移动成员（04-A-22 第 4 条）；
  5. 钉钉新建部门与某 `LOCAL` 部门同父同名 → 不合并，同步报告中记“存在同名本地部门”（04-A-22 第 5 条），此时同名校验对同步不生效；
  6. 乱序：以事件时间为准，事件时间早于部门 `last_sync_at` 的变更事件丢弃（记录为“已过期”）；
  7. 管理员确认“待确认”部门（保留 / 改挂 / 删除）后 `local_orphan=0`，待办关闭。
- **错误码**：1006（同步失败记录）。
- **依据**：FW-D07 第 2～4 条；04-A-21、A-22；FW-B08。

### FP-D07-03 人员同步
- **规则**：匹配顺序：钉钉 userid 映射 → 手机号（`mobile_hash`）；未匹配 → 新建用户（`source=DINGTALK`、`ACTIVE`、`password_hash` 为空（未设密码，不能账号密码登录，按 1214 处理；个人中心显示“设置密码”，04-C-19）、`username` = 钉钉 userid）并建映射；部门归属以钉钉为准替换该用户 `source=DINGTALK` 的归属行（`source=LOCAL` 的归属保留），主部门取钉钉主部门；岗位写 `dict_position`（新岗位自动入字典）并触发 FP-D05-01；离职 → `RESIGNED`、作废全部会话、发布 `user.resigned`；钉钉侧不同步密码。
- **依据**：FW-D07 第 5 条；【PRD】§5.1 第 2 条；04-A-23、A-24、B-26。

### FP-D07-04 全量对账
- **输入**：手动 `POST /admin-api/ims/system/org-sync/reconcile`（权限 `ims:system:org-sync:run`）或 Worker 每日 02:00（【共享规范】§8.4 `reconcile`）。
- **输出**：对账批次 `ims_auth_org_sync_batch`（开始/结束时间、新增/更新/停用部门数、新增/更新/离职人员数、待分配人数、同名提示、失败数、状态）。
- **规则**：拉取钉钉全量部门 + 人员，逐条按 FP-D07-02/03 处理；钉钉中不存在但 IMS 中 `source=DINGTALK` 的部门视为删除；同一时刻只允许一个对账（分布式锁，FP-H01-02），重复触发 → 1001（提示“同步正在进行中”）；钉钉不可用 → 批次失败，组织数据保持不变（【分期技术约束】V1-A6）。
- **错误码**：1001、1006、5003。
- **依据**：FW-D07 第 1、6 条；【共享规范】§8.4。

### FP-D07-05 重试、死信与重放
- **规则**：处理失败 → `RETRYING`，按 1、5、15、60 分钟退避重试，第 5 次失败 → `DEAD`；死信可在组织同步页“重放”（权限 `ims:system:org-sync:run`），重放从 `PENDING` 重新开始；同步延迟（事件时间 → 处理完成）> 5 分钟记告警事件（BR-001）。
- **依据**：FW-D07 第 1、6 条；【AUTH 规格】P2。

## E. 文件（FW-E01～E02）

### FP-E01-01 上传
- **输入**：`POST /admin-api/ims/file/upload`（multipart：`file`、`scene`）。
- **输出**：`{fileKey, fileName, size, contentType, url}`；`url` 为下载接口相对地址。
- **规则**：场景校验见 FP-E02-01；存储路径 `{storage_root}/{scene}/{tenantId}/{yyyyMM}/{uuid}.{ext}`，`fileKey` = 相对路径；先写临时文件、校验通过后原子改名；元数据写 `ims_file`（`file_key` 唯一、`scene`、`original_name`、`size`、`content_type`、`ext`、`sha256`、`biz_type`、`biz_id`（业务保存时回填）、`creator`、`tenant_id`）；磁盘写失败 → 5005。
- **错误码**：5005、1001。
- **依据**：FW-E01；【全局规范】§6.3；04-B-07。

### FP-E01-02 下载
- **输入**：`GET /admin-api/ims/file/{fileKey:path}`。
- **规则**：`fileKey` 规范化后含 `..`、绝对路径、反斜杠或不在 `storage_root` 下 → 1001；元数据不存在或 `tenant_id` 不符 → 1504；元数据已绑定业务记录时，按场景注册的“业务归属校验函数”判断当前用户对该业务记录是否可见（数据范围），不可见 → 1504；未绑定业务的文件仅上传人可下载；响应头 `Content-Disposition` 用原文件名（RFC 5987 编码）。

- **依据**：FW-H07 第 4 条；【MEET 契约】§2.3.2；【MEET 规格】第 542 行；D-07。
