## 0. 约定

### 0.1 编号与书写
- 功能点编号：`FP-T-xx` 样式与 Token；`FP-R-xx` 请求层与全局 Store；`FP-Cxx-yy` 组件（与 02 清单 UI-Cxx 对应）；`FP-Lxx` 布局模板（UI-Lxx）；`FP-P-xx` 组件示例页。
- 组件功能点写：**输入**（props）/ **输出**（事件、插槽、v-model）、**规则**、**错误码**（组件需处理的后端码）、**接口**（调用的后端接口，来自 B0a）、**依据**。
- 「**【本清单裁定】**」= 规格未写、产品在本清单定的口径。

### 0.2 交付范围（【本清单裁定】，调和 05 计划“42 个组件”与 02 清单第 5 节“第 8、9 组随模块交付”）
| 类别 | B0b 交付内容 |
|------|--------------|
| 完整交付（不依赖业务模块接口） | Token / 主题、请求层与 Store、UI-C01～C23、C29、C30、C32～C40、C42，8 个模板 |
| 交付“组件 + 对外 API 冻结 + 示例数据源”，真实数据源随模块批次接入 | UI-C24 实名人、C25 平台账号、C26 IP 组、C27 作者、C28 公司 / 设备 / 手机卡、C31 赛事 / 选题（对应 02 清单第 5 节第 8 行）；UI-C41 关系图 / 流程设计器（第 9 行）——B0b 做只读渲染与示例，编辑能力随 B13 流程批次 |
| 示例页 | `/demo/*` 路由，只在 `dev` / `test` 构建中注册，生产构建不包含【本清单裁定】 |

### 0.3 前端通用规则（所有组件遵守）
1. 颜色、字号、间距只能用 Token（CSS 变量），组件与页面中出现十六进制颜色或 `rgb(` → lint 失败（Token 定义文件除外）；
2. 状态中文名与颜色只来自字典（`dictStore`），页面不得写 `statusLabel` / 颜色映射；
3. 页面不得出现英文枚举码、接口路径、BR/ADR/模块代号（【裁定】B025）——示例页同样适用；
4. 权限只按权限码（`v-perm` / `hasPerm`），代码中出现按角色名、`role_key` 判断 → lint 失败（04-A-07）；
5. 业务代码不得手写 `/admin-api` 路径，只能调用 `src/api/generated/*`（FW-A05）；
6. 金额、百分比、时间显示统一走 UI-C39 与 `format` 工具；
7. 所有组件提供 TypeScript 类型；对外 API（props / events / slots）在第一个使用它的模块批次前冻结（02 清单原则 3），冻结后改动需走评审。

## R. 请求层与全局 Store

### FP-R-01 Axios 实例与统一解包
- **输入**：`src/api/generated/*` 生成的请求函数。
- **输出**：成功时直接 resolve `data`；`code≠0` 时 reject `BizError{code, msg, data}`。
- **规则**：基础地址 `/admin-api/ims`；请求头 `Authorization: Bearer <access>`、`X-Trace-Id`（每请求新 UUID）；写操作需要幂等的接口由生成器自动带 `X-Client-Token`（按一次用户提交生成一次，重试复用）；默认超时 30 秒（导入导出上传 5 分钟）。
- **依据**：FW-A02、FW-H03；04-B-14。

### FP-R-02 错误码处理策略
- **输入**：`src/api/error-codes.json`（B0a FP-H03-01 生成）。
- **规则**（按 `strategy`）：
  - `fieldError`（1001）：若调用方是表单（UI-C17），把 `data.fieldErrors` 映射到对应字段红框提示，不弹 toast；否则 toast `msg`；
  - `relogin`（1002、1003 与 HTTP 401）：见 FP-R-03；
  - `noPermission`（1008）：toast“暂无权限”，**不跳 403 页**，当前页面保持（【裁定】C086）；
  - `toast`（含 1500～1504 及其他业务码）：toast 后端 `msg`；1504 时若当前在抽屉内则关闭抽屉并刷新列表【本清单裁定】；
  - 5xxx：toast `msg` +“问题编号：<traceId 前 8 位>”（便于报障）【本清单裁定】；
  - 网络错误 / 超时：toast“网络异常，请检查网络后重试”；
  - 调用方可传 `silent: true` 自行处理。
- **依据**：FW-H03；B0a FP-H03-01；【裁定】C086。

### FP-R-03 令牌刷新与跳登录
- **规则**：收到 HTTP 401：
  1. 若 `code=1003` → toast“您的账号已在其他设备登录，本设备已下线”，清会话，跳登录页（带 `redirect`）；
  2. 否则用 refresh token 调 `POST /auth/refresh-token`；刷新期间的其他 401 请求排队，刷新成功后**按原参数重放一次**；
  3. 刷新失败（1002）→ 清会话，跳登录页（`/login?redirect=<当前路由>`），toast“登录已失效，请重新登录”；
  4. 同一时刻只发起一次刷新；重放后仍 401 不再刷新，直接跳登录页。
  登录页同时提供账号密码与钉钉扫码两个入口（04-B-21）；登录页本身在 B1 批次，本批只提供跳转与 `sso-callback` 落地处理（读取 URL 片段中的令牌后立即清除片段）。
- **依据**：04-B-21；B0a FP-D01-03、FP-D02-02。

### FP-R-04 会话 Store（`authStore`）
- **规则**：access / refresh 存 `localStorage`【本清单裁定：同一浏览器多标签共享会话】；登录后调 `GET /auth/me` 缓存 `user`、`menus`、`permCodes`、`permDetails`、`dataScopeText`；`pwdResetRequired=true` 时路由守卫只放行个人中心改密页；登出清空并跳登录页；多标签页通过 `storage` 事件同步登出。
- **接口**：`/auth/me`、`/auth/logout`。
- **依据**：FW-D06；04-C-19。

### FP-R-05 权限判断（`hasPerm` / `hasAnyPerm`）
- **规则**：基于 `permCodes`；`hasPerm(code, 'r'|'w'|'d')` 使用 `permDetails`；权限变化（后端版本号变化导致 `/auth/me` 重新获取）后按钮显隐即时更新；每 5 分钟或窗口重新获得焦点时静默刷新 `/auth/me`【本清单裁定，配合 B0a FP-D03-04】。
- **依据**：FW-D03、FW-D06；【PRD】§9 权限同步 < 5 min。

### FP-R-06 字典 Store（`dictStore`）
- **规则**：`getDict(type)` 首次请求 `GET /system/dict-data/simple-list?dictType=` 后缓存（会话内）；`label(type, value)`、`color(type, value)`；未知值显示原值并在控制台告警（不报错）；`refresh(type)` 手动刷新；缓存 10 分钟过期【本清单裁定】；并发请求同一类型只发一次。
- **接口**：B0a FP-B07-03 字典接口。
- **依据**：FW-B07；02 清单原则 2。

### FP-R-07 路由守卫与动态路由
- **规则**：路由表由前端静态登记（路径 → 组件），是否可访问由“我的菜单树”决定；未登录访问业务路由 → 跳登录页；访问不在菜单树中的路由 → 显示 UI-C11 无权限态（页面框架保留、不显示 403 白页）；二级页（个人中心、学习中心等无菜单页）登记为 `meta.menuless=true`，仅校验登录；`/demo/*` 仅在 `dev`/`test` 注册。
- **依据**：FW-D06；【裁定】C086、B048；04-C-19。

### FP-R-08 格式化工具
- **规则**：`fmtMoney("1234.5") → "¥1,234.50"`，负数加 `.neg`；`fmtPercent(5) → "5%"`；`fmtTime(iso) → "YYYY-MM-DD HH:mm"`；`fmtDate`；周期显示“2026-10-05 ~ 2026-10-11”、“2026-10”；空值显示“—”。
- **依据**：02 清单 1.6；【裁定】BUG-070、B090。

### 列表类

#### FP-C06-01 QueryBar 查询栏
- **输入**：`fields:[{key, label, type:'input'|'select'|'dict'|'date'|'daterange'|'user'|'dept'|..., props}]`、`v-model`（条件对象）、`collapseAfter=4`。

- **规则**：一行排布（gap 8px，内部控件高 30px）；超过 `collapseAfter` 的条件收进“更多”，展开后多行；回车即查询；“重置”清空条件后立即查询并回到第 1 页；输入框去首尾空格；条件同步到 URL 查询参数（刷新保持）【本清单裁定】。
- **依据**：UI-C06；【全局规范】§6.1、§6.2。

#### FP-C07-01 DataTable 数据表格
- **输入**：`columns:[{key, label, width?, type:'text'|'mono'|'number'|'money'|'percent'|'status'|'time'|'masked'|'actions', dictType?, sortable?, fixed?}]`、`data`、`loading`、`selectable`、`rowKey='id'`、`emptyType`。
- **输出**：`sort-change({sortField, sortOrder})`、`selection-change(rows)`；插槽 `cell-<key>`、`actions`。
- **规则**：`mono` 列等宽 12px；`number`/`money`/`percent` 右对齐、`tabular-nums`；`status` 列自动用 StatusTag（需 `dictType`）；`money` 负数红；`actions` 列内文字按钮 + 危险文字按钮，按钮均需 `v-perm`；行操作超过 3 个时第 4 个起收进“更多”；无数据显示 UI-C11（`emptyType` 决定文案）；排序只对 `sortable` 列开放，参数名与后端 `sortField`/`sortOrder` 一致；加载中显示骨架。
- **依据**：UI-C07；B0a FP-A03-02。

#### FP-C08-01 Pagination 分页

#### FP-C09-01 StatusTag 状态标签

### 表单与弹层类

#### FP-C14-01 FormDrawer 表单抽屉

- **规则**：树顶按钮“同步钉钉组织”（权限码 `ims:system:org-sync:run`，无权限不显示）；按钮下方小字“上次同步：YYYY-MM-DD HH:mm”（来自最近批次，无记录显示“尚未同步”）；点击二次确认“将以钉钉组织为准更新部门与人员，本地对钉钉部门的修改会被覆盖，本地新建的部门不受影响。确定同步？”；进行中按钮显示“同步中…”不可点，每 3 秒查询批次状态；完成后 toast 摘要“同步完成：新增部门 a、更新 b、停用 c；新增人员 d、离职 e；待分配 f 人”，有“待确认”部门或同名提示时追加“有 n 个本地部门待确认”；失败 toast 后端提示；返回 1001（正在进行）提示“同步正在进行中”；完成后树刷新。
- **接口**：`POST /system/org-sync/reconcile`、`GET /system/org-sync/latest-batch`。
- **依据**：UI-C42；04-C-21（本按钮只触发一次全量对账，过程监控在组织架构同步页）；B0a FP-D07-04。

## L. 布局模板（UI-L01～L08）

#### FP-L01 标准列表页
- **结构**：PageHeader → （可选）StatCard → QueryBar → DataTable → Pagination；新建 / 编辑走 FormDrawer，详情走 DetailDrawer。
- **规则**：进入页面按 URL 参数恢复查询条件、页码；查询、重置、改页、改每页条数行为见 FP-C06/C08；新建 / 编辑保存成功后刷新当前页（新建回到第 1 页）；删除成功后刷新，若当前页已无数据退回上一页；脚手架（B0a FP-A06-03）生成的页面即本模板。
- **依据**：UI-L01。

#### FP-L02 统计卡 + Tab 列表页
- **规则**：4 列 StatCard → Tabs（`syncQuery='tab'`）→ 每个 Tab 一个列表（各自保留查询条件）；切换 Tab 回到第 1 页；统计卡点击可切到对应 Tab（可选）。
- **依据**：UI-L02。

#### FP-L03 左树右表页（含联动规则 ①～⑦）
- **结构**：左栏（240px，可折叠，独立滚动）放树（部门场景用 UI-C42；分类 / 岗位 / 字典类型用通用树）；右栏：节点路径与「含下级」开关（部门场景）→ QueryBar → DataTable → Pagination。
- **联动规则**（02 清单 UI-L03 原文，逐条实现）：
  1. **① 选中节点 → 右表重新查询**：以该节点为筛选条件（部门场景参数 `deptId` + `includeChildren`）、回到第 1 页，QueryBar 其他条件保留；
  2. **② 节点路径与「含下级」开关**：右表上方显示“当前：根 / 市场部 / 市场一组”；部门场景有「含下级」开关，**默认开**；切换开关回到第 1 页重新查询；
  3. **③ 选「全部」= 不按节点过滤**：路径显示“全部”，「含下级」开关隐藏；选「待分配」只看待分配人员；
  4. **④ 新建默认带入当前节点**：右表“新建”时表单中的节点字段默认 = 当前选中节点（如新建用户的所属部门 = 当前部门、主部门 = 当前部门）；当前为「全部」或停用节点时不带入；
  5. **⑤ 右表操作后左树人数局部刷新**：右表操作改变归属或人数（调整部门、删除人员、新建人员）成功后，重新拉取部门树人数并保持当前展开与选中状态（不整树折叠、不丢选中）；
  6. **⑥ 当前节点被删除 → 回到父节点**：左树增删改节点或钉钉同步后，若当前选中节点被删除（或被停用且未勾选显示停用），自动选中父节点（父节点也被删除时取最近的仍存在的祖先）并重新查询右表；
  7. **⑦ 选中节点写入 URL**：`?deptId=…&inc=1`（及右表查询条件、页码）写入 URL，刷新、浏览器后退 / 前进均恢复同一状态；URL 中的节点已不存在时回到「全部」并 toast“所选部门已不存在”。
- **数据范围**：右表数据受当前用户数据范围限制（后端执行）；左树显示完整组织（B0a FP-B08-02 第 4 条）——因此可能出现“节点有人数、右表为空”，此时右表空态文案为“当前统计范围内暂无人员”，PageHeader 显示统计范围【本清单裁定】。
- **依据**：UI-L03、UI-C13、UI-C42；04-B-26（任一所属部门可筛到）；B0a FP-B08-03。

#### FP-L04 看板 / 统计页
- **结构**：PageHeader（含统计范围）→ 周期选择（PeriodPicker）→ StatCard → Chart → 排行表。
- **规则**：切换周期后全部区块重新加载；每个区块独立加载 / 空态 / 失败重试；“截至”时间显示到时分（【裁定】B090）。
- **依据**：UI-L04。

#### FP-L05 工作台页
- **结构**：待办 Tab（审批 / 归还 / 审核 / 确认 / 预警 / 告警，计数取 `/todo/my/count`）+ 消息（全部 / 未读 / 已读）+ 快捷入口（按权限码显示）。
- **规则**：点击待办跳转其 `route`；跳转目标无权限时 toast“暂无权限”不跳转。
- **依据**：UI-L05；B0a FP-G01-02、FP-G02-02。

#### FP-L06 设计器 / 编辑器页
- **结构**：三栏（左组件区 168 / 中画布 / 右属性区 292）；顶部工具栏（保存、预览、返回）。
- **规则**：有未保存修改时离开页面二次确认（路由守卫 + 浏览器 `beforeunload`）；B0b 只交付布局骨架与只读画布（FP-C41-01）。
- **依据**：UI-L06。

#### FP-L07 填报 / 作答页（无侧栏二级页）
- **结构**：无侧栏，顶栏保留；内容全宽；底部固定提交栏。
- **规则**：路由 `meta.menuless=true`；离开有未保存内容时二次确认；提交按钮防重复。
- **依据**：UI-L07；【裁定】B048。

#### FP-L08 详情抽屉模板
- **结构**：抽屉头（标题 + StatusTag）→ 页内 Tab（基本信息 DescriptionList / 关联 / 时间线 Timeline）→ 底部操作（按权限码）。
- **依据**：UI-L08、UI-C15。
