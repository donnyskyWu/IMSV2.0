### 2.3 接口明细

#### 2.3.1 POST /admin-api/ims/meet/minutes — 登记会议/录入纪要

**路由层权限声明**: `@require_perm("ims:meet:minutes:add")`

**请求体**:
```typescript
interface MeetingMinutesCreateReq {
  title: string;              // 必填，≤128 字
  meetingDate: string;        // 必填，ISO 8601
  meetingRoom?: string;       // 可选，≤64 字
  recorderUserId?: number;    // 可选，默认当前用户
  attendees: {
    internal: number[];       // 内部参会人 userId 列表
    external?: string[];      // 外部参会人姓名列表（每人 ≤32 字，Q-D13）
  };
  summary?: string;           // 纪要正文（富文本，后端白名单净化，≤20000 字）
  decisions?: Array<{
    content: string;          // ≤512 字，存储时 HTML 转义
  }>;
  actionItems?: Array<{
    description: string;      // ≤256 字
    assigneeUserId: number;   // 责任人（须为本租户启用内部用户，外部人不能当责任人）
    dueDate: string;          // yyyy-MM-dd，≥今天
  }>;
  clientToken: string;        // 幂等键（存储 24h TTL）
}
```

**响应**: `MeetingMinutesVO`

**逻辑**:
1. 幂等校验：`clientToken` 存在且未过期 → 返回已有结果
2. 参数校验：主题 ≤128、至少 1 名参会人、外部参会人每人 ≤32 字、行动项期限 ≥ 今天 → 1001
3. 引用校验：
   - 记录人：存在 → 1500，停用/离职 → 1501
   - 内部参会人：同上
   - 行动项责任人：须为内部用户，外部参会人不能当责任人
4. 记录人未指定时取当前用户；记录人主部门写入 `dept_id`
5. 正文白名单净化（允许标签白名单：p, br, strong, em, u, ol, ul, li, span）
6. 正文为空 → `status=REGISTERED`；正文非空 → `status=MINUTES_RECORDED`（Q-D3）
7. 生成编号 `MM + yyyyMMdd + 3 位流水`（并发防重：Redis INCR + DB 唯一约束兜底；>999 时扩展为 4 位）
8. 内部参会人发送会议通知（B0a `notify`，渠道 INBOX + DINGTALK）
9. 每条行动项调用 `todo.create(type=确认, source_type=MEET_ACTION_ITEM)`（Q-D6）
10. 会后 > 24h 录入 → `warnings` 带 1116（不阻断）
11. 写操作日志

**错误码**:
| 码 | 场景 |
|----|------|
| 1001 | 参数校验失败 |
| 1008 | 缺少 `add` 权限码 |
| 1500 | 记录人/内部参会人/责任人不存在 |
| 1501 | 记录人/内部参会人/责任人已停用或离职 |

#### 2.3.2 GET /admin-api/ims/meet/minutes/list — 纪要列表

**路由层权限声明**: `@require_any_perm("ims:meet:minutes:query", "ims:meet:minutes:query-self")`

**Query 参数**:
- `pageNo`, `pageSize` (必填，pageSize ≤ 100)
- `title` (可选，模糊匹配)
- `meetingDateStart`, `meetingDateEnd` (可选，默认近 30 天)
- `status` (可选)

**响应**: `PageResult<MeetingMinutesVO>`

**数据范围逻辑**（Q-D11 详细实现）:

```python
def build_scope_condition(user, has_query, has_query_self, data_scope):
    """
    数据范围：query 按角色数据范围 OR 本人相关
    - ALL: 无额外条件
    - DEPT(含下级): dept_id IN (用户可见部门 ID 列表)
    - SELF: 仅本人相关
    
    本人相关定义：
    - recorder_user_id = 当前用户
    - attendees.internal JSON_CONTAINS 当前用户
    - 存在行动项 assignee_user_id = 当前用户
    """
    conditions = []
    
    if has_query:
        if data_scope == "ALL":
            pass  # 无额外条件
        elif data_scope == "DEPT":
            # 含下级部门
            dept_ids = get_user_visible_depts(user, include_children=True)
            conditions.append(Minutes.dept_id.in_(dept_ids))
    
    if has_query_self:
        # OR 本人相关（他部门会议但本人是参会人/记录人/责任人可见）
        self_condition = or_(
            Minutes.recorder_user_id == user.id,
            func.json_contains(Minutes.attendees, f'[{user.id}]', '$.internal'),
            Minutes.id.in_(
                select(ActionItem.minutes_id)
                .where(ActionItem.assignee_user_id == user.id)
            )
        )
        if conditions:
            conditions = [or_(and_(*conditions), self_condition)]
        else:
            conditions = [self_condition]
    
    if not has_query and not has_query_self:
        raise BizError(1008)
    
    return conditions
```

**此范围逻辑统一用于**：列表、详情、编辑、归档、附录、删除、回填、留痕率、升级接收人

#### 2.3.4 PUT /admin-api/ims/meet/minutes/{id} — 编辑纪要

**路由层权限声明**: `@require_perm_or_recorder("ims:meet:minutes:edit")`

**请求体**: 同创建（含 `baseVersion` 用于乐观锁）

**逻辑**:
1. 先查范围（不在范围 → 1504）
2. 再判状态（已归档 → 1117）
3. 再判权限（非记录人且无 `edit` → 1008）
4. 乐观锁校验（`baseVersion` != 当前 `version` → 1001"数据已被修改，请刷新后重试"）
5. 行动项变更处理（防覆盖已闭环项）：
   - 新增 → `todo.create`
   - 删除（未闭环）→ `todo.cancel`
   - 改责任人/期限 → 更新待办（已闭环项不可改 → 1001）
6. 会后 > 24h → `warnings` 带 1116
7. 写操作日志

**错误码**:
| 码 | 场景 |
|----|------|
| 1001 | 参数校验/已闭环行动项修改/乐观锁冲突 |
| 1008 | 非记录人且无 `edit` 权限 |
| 1117 | 已归档不可修改 |
| 1504 | 纪要不存在/超出范围 |

1. 按数据范围过滤统计
2. 分母为 0 时，留痕率返回 100（或 null 表示无数据）
3. 未归档清单分页上限 100 条

**错误码**:
| 码 | 场景 |

## 7. 定时任务

### 7.1 meeting_reminder_job（24h/48h 提醒）

- **调度**: 每小时执行
- **时间计算**: 全部使用 `app.core.clock.get_now()` 获取北京时间
- **规则**（Q-D9）:
  1. 会后超 24h 仍 `REGISTERED` → 给记录人发消息
  2. 会后超 48h 未归档（非 `ARCHIVED`）→ 给记录人 + `supervise` 用户发消息
- **幂等机制**: 
  - Redis SETNX 键 `meet:reminder:{minutes_id}:{level}`（level = 24h/48h）
  - 或 DB `remind_24h_at` / `remind_48h_at` 非空时跳过
  - 条件 UPDATE 防并发：`UPDATE ... SET remind_24h_at = ? WHERE id = ? AND remind_24h_at IS NULL`
- **离职检查**: 记录人已离职时不推送

### 7.2 meeting_overdue_job（逾期推送与升级）

- **调度**: 每日 09:00（北京时间）
- **时间计算**: 全部使用 `app.core.clock.get_now()` 获取北京时间日期
- **规则**（Q-D7, Q-D8）:
  1. 扫描 `due_date < 今天` 且 `status != CLOSED` 的行动项
  2. 标记 `status = OVERDUE`
  3. **逾期满 1 天**（`due_date + 1 < 今天` 且 `notified_at IS NULL`）→ 推送责任人
  4. **逾期满 3 天**（`due_date + 3 < 今天` 且 `escalated_at IS NULL`）→ 推送 `supervise` 用户
- **幂等机制**: 
  - Redis SETNX 键 `meet:overdue:{item_id}:{level}`（level = 1d/3d）
  - 条件 UPDATE 防并发：`UPDATE ... SET notified_at = ? WHERE id = ? AND notified_at IS NULL`
- **升级接收人**: 持有 `ims:meet:minutes:supervise` 且**数据范围覆盖该会议**的用户（Q-D7 不按角色名）
- **离职检查**: 责任人已离职时不推送
