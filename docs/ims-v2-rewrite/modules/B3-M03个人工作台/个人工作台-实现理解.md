## 1. 表结构变更

### 1.1 `ims_sys_todo` 表扩展

> 现有表，B0a 已建骨架（`assignee_user_id`、`title`、`event_id`、`status` 默认 `OPEN`）。

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `type` | VARCHAR(30) | **NULL**（回填后改 NOT NULL） | 待办类型，取 `dict_todo_type` |
| `source_module` | VARCHAR(50) | NULL | 来源模块中文名 |
| `source_type` | VARCHAR(50) | NULL | 来源单据类型 |
| `source_id` | BIGINT | NULL | 来源单据 ID |
| `route` | VARCHAR(300) | NULL | 跳转路由，由投递模块写入 |
| `content` | TEXT | NULL | 待办内容描述 |
| `due_time` | DATETIME | NULL | 截止时间 |
| `done_by` | BIGINT | NULL | 处理人 user_id |
| `done_time` | DATETIME | NULL | 处理时间 |

**字典 `dict_todo_type` 7 项存储码值**：

| 序号 | 存储码值 | 中文标签 | 颜色 |
|------|----------|----------|------|
| 1 | `APPROVAL` | 审批 | primary |
| 2 | `RETURN` | 归还 | warning |
| 3 | `REVIEW` | 审核 | info |
| 4 | `CONFIRM` | 确认 | success |
| 5 | `WARNING` | 预警 | warning |
| 6 | `ALERT` | 告警 | danger |
| 7 | `STUDY` | 学习 | neutral |

**状态迁移（升级）**：

```sql
-- 1. 改默认值（models.py 同步改为 PENDING）
ALTER TABLE ims_sys_todo ALTER COLUMN status SET DEFAULT 'PENDING';

-- 2. 存量数据迁移（含已删除的行）
UPDATE ims_sys_todo SET status = 'PENDING' WHERE status = 'OPEN';

-- 3. 回填 type（存量数据只来自 position_supply，integrity 写的是 ims_sys_inbox）
--    3a. 先按标题匹配岗位相关（活跃行）
UPDATE ims_sys_todo SET type = 'CONFIRM', source_module = '岗位供给', route = '/ims/auth/position'
WHERE type IS NULL AND title LIKE '%岗位%' AND deleted = 0;

--    3b. 兜底：所有剩余 NULL 行（含 deleted≠0、标题不含岗位）统一设为 CONFIRM
UPDATE ims_sys_todo SET type = 'CONFIRM' WHERE type IS NULL;

-- 4. 回填完成后，再执行 NOT NULL 变更（单独迁移版本）
--    此时不应存在任何 type IS NULL 的行
ALTER TABLE ims_sys_todo MODIFY COLUMN type VARCHAR(30) NOT NULL;
```

**状态迁移（降级）**：

```sql
-- PENDING → OPEN；DONE/CANCELLED/CLOSED 保持原值（无法还原为 OPEN）
UPDATE ims_sys_todo SET status = 'OPEN' WHERE status = 'PENDING';
-- DONE/CANCELLED/CLOSED 不改，降级后业务代码需兼容这些值
ALTER TABLE ims_sys_todo ALTER COLUMN status SET DEFAULT 'OPEN';
```

**新增索引**：`idx_todo_tenant_status_due (tenant_id, status, due_time)`

**models.py 变更**：`status` 默认值从 `OPEN` 改为 `PENDING`。

### 1.2 新建 `ims_sys_todo_assignee` 表

> B0a FP-G02-01 已登记但仓库未建。继承 `AuditBase`（与 main 现有表模型一致，如 `TodoItem`、`User` 等），主键由应用层 `assign_pk(session, obj)` 分配。

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | BIGINT | PK | 主键（应用层 `assign_pk` 分配，**非自增**） |
| `tenant_id` | BIGINT | NOT NULL | 租户（AuditBase） |
| `todo_id` | BIGINT | NOT NULL, INDEX | 关联 `ims_sys_todo.id` |
| `user_id` | BIGINT | NOT NULL, INDEX | 处理人 |
| `closed` | TINYINT(1) | NOT NULL DEFAULT 0 | 本人是否已关闭 |
| `closed_time` | DATETIME | NULL | 关闭时间 |
| `creator` | BIGINT | NULL | 创建人（AuditBase） |
| `create_time` | DATETIME | NULL | 创建时间（AuditBase） |
| `updater` | BIGINT | NULL | 更新人（AuditBase） |
| `update_time` | DATETIME | NULL | 更新时间（AuditBase） |
| `deleted` | BIGINT | NOT NULL DEFAULT 0 | 逻辑删除（AuditBase） |

**唯一索引**：`uk_todo_assignee (todo_id, user_id, deleted)`

**数据回填（在 Alembic 迁移中用 ORM/Session）**：

```python
# migrations/versions/xxxx_b3_create_todo_assignee.py
from app.domains.sys.models import TodoItem, TodoAssignee
from app.db.ids import assign_pk

def upgrade():
    # 1. 建表（略）
    # 2. 回填存量数据
    bind = op.get_bind()
    session = Session(bind=bind)
    
    todos = session.query(TodoItem).filter(
        TodoItem.deleted == 0,
        TodoItem.assignee_user_id.isnot(None)
    ).all()
    
    for todo in todos:
        assignee = TodoAssignee(
            tenant_id=todo.tenant_id,
            todo_id=todo.id,
            user_id=todo.assignee_user_id,
            closed=0,
            create_time=todo.create_time,
            creator=todo.creator,
            deleted=0,
        )
        assign_pk(session, assignee)  # 应用层分配 id
        session.add(assignee)
    
    session.commit()
```

**`ims_sys_todo.assignee_user_id` 处理策略**：
- **保留列，不废弃**：写入时双写（`assignee_user_id` + `todo_assignee` 表），读取只查 `todo_assignee` 表
- 原因：降级时需要 `assignee_user_id`，且 `position_supply.py` 等现有代码仍在写此列

## 2. 新增服务（本 PR 新建）

### 2.1 待办服务 `app/services/todo.py`【新增】

> main 上没有 B0a 的 `todo.create/complete/cancel`，本 PR 新建。

| 方法 | 功能 | 说明 |
|------|------|------|
| `create(type, source_module, source_type, source_id, title, route, assignee_user_ids, due_time?)` | 创建待办 | 同时写 `ims_sys_todo` + `ims_sys_todo_assignee`；双写 `assignee_user_id`（第一个处理人）；创建时钉钉推送（24 小时去重）；幂等（同 source_type+source_id+type 返回已有待办） |
| `complete(source_type, source_id, by_user)` | 完成待办 | 设 `status=DONE`、`done_by`、`done_time` |
| `cancel(source_type, source_id, reason)` | 作废待办 | 设 `status=CANCELLED`；**由源模块调用**（源模块删除/取消单据时调此接口） |
| `close_for_user(todo_id, user_id)` | 本人关闭 | 只写 `assignee.closed=1`，**不**写 `status=CLOSED`；审批/审核类 → 1001；非 PENDING → 1001 |
| `get_my_page(user_id, type?, status?, keyword?, page)` | 我的待办分页 | JOIN `assignee` 过滤 `user_id` 且 `closed=0` |
| `get_my_count(user_id)` | 我的待办计数 | 返回 `{total, byType, overdue}` |
| `get_my_detail(todo_id, user_id)` | 我的待办详情 | 他人/不存在 → 1504 |

**P0 服务路径**：`app/services/todo.py`

**钉钉推送与去重**：
- 创建时调用 `notify()` 推送钉钉工作通知
- 去重键：`todo:{source_type}:{source_id}:{user_id}`，Redis TTL 24 小时
- 重复创建时跳过推送，记录为 `SKIPPED_DUP`

### 2.2 消息服务 `app/services/message.py`【新增】

> main 上没有 B0a 的 `notify`，本 PR 新建。

| 方法 | 功能 | 说明 |
|------|------|------|
| `notify(event_type, biz_key, receivers, title, content, route?, channels)` | 发送通知 | 站内信 + 钉钉推送；24 小时去重 |
| `get_my_page(user_id, read_status?, keyword?, page)` | 我的消息分页 | 只返回本人消息 |
| `get_my_detail(message_id, user_id)` | 消息详情 | 他人/不存在 → 1504 |
| `mark_read(user_id, ids)` | 标记已读 | **all or nothing**：若 ids 含他人或不存在消息，整个请求返回 1504；幂等 |
| `mark_all_read(user_id)` | 全部已读 | 返回 `{updated}` |
| `get_unread_count(user_id)` | 未读数 | 返回本人未读消息数 |

**P0 服务路径**：`app/services/message.py`

### 3.2 错误码使用

| 场景 | 错误码 | 依据 |
|------|--------|------|
| 他人/不存在/跨租户的待办或消息 id | **1504** | B0a FP-G01-02、G02-02 |
| 关闭非 PENDING 待办 | **1001** | Q10 |
| 关闭审批/审核类待办（`type IN ('APPROVAL','REVIEW')`） | **1001** | Q6 |

export const useUnreadStore = defineStore('unread', {
