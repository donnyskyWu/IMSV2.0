## 1. 表结构变更

### 1.1 `ims_sys_todo` 表扩展

> 现有表，B0a 已建骨架（`assignee_user_id`、`title`、`event_id`、`status` 默认 `OPEN`）。

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `type` | VARCHAR(30) | NOT NULL | 待办类型，取 `dict_todo_type`（审批/归还/审核/确认/预警/告警/学习） |
| `source_module` | VARCHAR(50) | NULL | 来源模块中文名 |
| `source_type` | VARCHAR(50) | NULL | 来源单据类型（按 Q2，HOME P2 的 4 个源归入已有类型） |
| `source_id` | BIGINT | NULL | 来源单据 ID |
| `route` | VARCHAR(300) | NULL | 跳转路由，由投递模块写入 |
| `content` | TEXT | NULL | 待办内容描述 |
| `due_time` | DATETIME | NULL | 截止时间 |
| `done_by` | BIGINT | NULL | 处理人 user_id |
| `done_time` | DATETIME | NULL | 处理时间 |

**状态变更**：`status` 取值由 `OPEN` 改为 `PENDING/DONE/CANCELLED/CLOSED`（Q3）。迁移脚本：
- 升级：`UPDATE ims_sys_todo SET status='PENDING' WHERE status='OPEN' AND deleted=0`
- 降级：`UPDATE ims_sys_todo SET status='OPEN' WHERE status='PENDING' AND deleted=0`

**新增索引**：`idx_todo_tenant_status_due (tenant_id, status, due_time)`

### 1.2 新建 `ims_sys_todo_assignee` 表

> B0a FP-G02-01 已登记但仓库未建。

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | BIGINT | PK 自增 | 主键 |
| `tenant_id` | BIGINT | NOT NULL | 租户 |
| `todo_id` | BIGINT | NOT NULL, INDEX | 关联 `ims_sys_todo.id` |
| `user_id` | BIGINT | NOT NULL, INDEX | 处理人 |
| `closed` | TINYINT(1) | NOT NULL DEFAULT 0 | 本人是否已关闭 |
| `closed_time` | DATETIME | NULL | 关闭时间 |
| `create_time` | DATETIME | NOT NULL | 创建时间 |
| `creator` | BIGINT | NULL | 创建人 |

**唯一索引**：`uk_todo_assignee (todo_id, user_id)`

**数据回填**（迁移脚本）：
```sql
INSERT INTO ims_sys_todo_assignee (tenant_id, todo_id, user_id, closed, create_time, creator)
SELECT tenant_id, id, assignee_user_id, 0, create_time, creator
FROM ims_sys_todo WHERE deleted=0 AND assignee_user_id IS NOT NULL;
```

### 1.3 `ims_sys_inbox` 表扩展

> 现有表（`user_id`、`title`、`body`）。按 Q11 沿用表名，不改为 `ims_sys_message`。

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `event_type` | VARCHAR(50) | NULL | 消息事件类型 |
| `source_module` | VARCHAR(50) | NULL | 来源模块中文名 |
| `route` | VARCHAR(300) | NULL | 跳转路由 |
| `ref_type` | VARCHAR(50) | NULL | 关联业务类型 |
| `ref_id` | BIGINT | NULL | 关联业务 ID |
| `read_status` | VARCHAR(20) | NOT NULL DEFAULT 'UNREAD' | UNREAD/READ |
| `read_time` | DATETIME | NULL | 已读时间 |

**新增索引**：`idx_inbox_user_read (user_id, read_status, create_time)`

## 2. 接口实现方案

### 2.1 接口清单与功能点映射

| # | 方法 路径 | 功能点 | 权限 | 实现要点 |
|---|-----------|--------|------|----------|
| 1 | `GET /auth/workbench/dashboard` | WB-02, WB-03 | LOGIN_ONLY | 返回 `{todoCount, unreadMessageCount, ...}` 其余字段返回 `null`（Q4） |
| 2 | `GET /todo/my/page` | TD-01, TD-02, WB-04 | LOGIN_ONLY | 只查本人（`todo_assignee.user_id = ctx.userId AND closed=0`），支持 type/status/keyword 筛选 |
| 3 | `GET /todo/my/count` | TD-05 | LOGIN_ONLY | 返回 `{total, byType:{审批:n,...}, overdue:n}`，只计 PENDING 且未关闭 |
| 4 | `GET /todo/my/get?id=` | TD-03 | LOGIN_ONLY | 校验是否本人待办，他人/不存在 → 1504 |
| 5 | `PUT /todo/my/close` | TD-04 | LOGIN_ONLY | 只写 `assignee.closed=1`，不改来源单据；审批/审核类 → 1001；非 PENDING → 1001 |
| 6 | `GET /message/my/page` | MS-01, WB-05 | LOGIN_ONLY | 只查本人（`user_id = ctx.userId`），支持 readStatus/keyword 筛选 |
| 7 | `GET /message/my/unread-count` | MS-04 | LOGIN_ONLY | 返回本人未读消息数 |
| 8 | `GET /message/my/get?id=` | MS-02 | LOGIN_ONLY | 他人/不存在 → 1504 |
| 9 | `POST /message/my/read` | MS-02 | LOGIN_ONLY | 批量标记已读，幂等；ids 中非本人消息 → 1504 |
| 10 | `POST /message/my/read-all` | MS-03 | LOGIN_ONLY | 只置本人未读为已读，返回 `{updated}` |

**路径前缀**：`/admin-api/ims`

### 2.2 错误码使用

| 场景 | 错误码 | 依据 |
|------|--------|------|
| 他人/不存在/跨租户的待办或消息 id | **1504** | B0a FP-G01-02、G02-02 |
| 关闭非 PENDING 待办 | **1001** | Q10 |
| 关闭审批/审核类待办 | **1001** | Q6 |
| 须改密阶段调用任一接口 | **1008** | D2（10 个接口均不在白名单） |
| 参数校验失败（pageNo/pageSize 等） | **1001** | FP-A03-01 |

**不新增错误码**：所有场景均使用已有码 1001/1008/1504。

## 8. 门槛确认

| 门槛 | 实现方式 |
|------|----------|
| **新增服务列进 `p0_services.txt`** | 新增 `app/services/workbench.py`、`app/services/todo.py`、`app/services/message.py`，列入 `p0_services.txt` |
| **分支覆盖 ≥90%（P0 服务）** | 上述三个服务必须分支覆盖 ≥90% |
| **总覆盖 ≥80%** | 单测 + E2E 合计行覆盖 ≥80% |
| **后端用真实 MySQL 和 Redis** | pytest 连接真实测试库，不用 fakeredis 或 sqlite |
| **不写空壳测试** | 每个 `def test_*` 必须有真实断言，不能只是 `pass` |
| **BG-05 逐个接口测** | 10 个接口每个都要测 1504（他人 id）、1008（须改密） |
| **E2E 用 Playwright 真跑** | `chromium`/`firefox`/`webkit` 三个浏览器，业务 skip = 0 |
| **不用固定等待** | 使用 `expect(locator).to_be_visible()` 等自动等待，禁止 `time.sleep` |
| **端口走环境变量** | 后端 `IMS_API_PORT`，前端 `VITE_API_BASE_URL`，不写死 3000 |
| **时间用 `app/core/clock.py`** | 所有 `datetime.now()` 改用 `get_now()`，单测可注入时间 |
