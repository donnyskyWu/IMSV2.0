## A. 工程与通用约定

### FW-A01 工程骨架（API 进程 + Worker 进程）
- **目标**：建立后端单仓骨架，API 与 Worker 两个进程共享同一领域代码。
- **范围**：FastAPI 应用工厂、配置加载（环境变量/配置文件，区分 dev/test/prod）、健康检查、统一路由注册（按模块自动挂载，前缀 `/admin-api/ims/`）、Worker 进程入口、Redis 连接、日志输出。不含任何业务表。
- **依据**：【ADR-009】技术栈；【共享规范】§8.1「统一前缀 `/admin-api/ims/`」。
- **单测验收标准**：
  1. 应用可在测试配置下启动，`/health` 返回 200；
  2. 模块路由注册后，路径前缀全部为 `/admin-api/ims/`（测试遍历路由表断言，非白名单路由不允许其他前缀；登录等认证路由如需例外须显式登记）；
  3. Worker 入口可加载同一套模型与服务，不重复定义模型（测试 import 断言）。

### FW-A02 统一响应、错误码与异常
- **目标**：所有接口返回 `{code, msg, data}`；错误码按模块号段集中注册，禁止散落魔法数字。
- **范围**：`CommonResult` 封装；业务异常类（携带错误码 + 中文业务提示）；全局异常处理（参数校验 → 统一码；未知异常 → 5xxx 且不泄漏堆栈）；错误码注册表（按【全局规范】§3 号段：AUTH 1001–1010、ASSET 1011–1020 … 系统 5001–5006）。
- **依据**：【全局规范】§2.3（通用响应包裹）、§3（错误码号段）；【共享规范】§8.1；【SYS】P2A 第 5 条（1504 不泄漏存在性）。
- **单测验收标准**：
  1. 成功响应 `code=0`，失败 `code≠0` 且 `msg` 为中文业务句；
  2. 重复注册同一错误码 → 启动失败（测试断言抛错）；
  3. 号段越界注册（如 TRAIN 模块注册 1151）→ 启动失败；
  4. 未捕获异常返回统一系统码，响应体不含 traceback；
  5. 1504 响应体不包含目标资源 id/名称。

### FW-A03 分页、排序、查询参数约定
- **目标**：统一分页与列表查询入参/出参。
- **范围**：`PageParam(pageNo, pageSize)`，默认 10、最大 100，前端选项 10/20/50；`PageResult(list, total)`；排序白名单机制（只允许声明过的字段排序，防注入）。
- **依据**：【全局规范】§2.1～§2.2、§2.5（分页）；【共享规范】§8.1 分页参数。
- **单测验收标准**：pageSize 缺省=10；pageSize=101 → 校验失败或截断为 100（二选一，须与前端约定一致并写入测试）；pageNo<1 → 校验失败；未声明字段排序 → 校验失败。

### FW-A04 序列化与格式约定（命名 / 时间 / 金额 / 枚举）
- **目标**：消灭旧代码中 24 份 `iso()`、27 处 `statusLabel` 之类的重复实现（见【评估】）。
- **范围**：API 字段 camelCase、库字段 snake_case 自动转换；时间统一 ISO 8601（含时区，按 Asia/Shanghai）；金额 `DECIMAL(12,2)`、序列化为字符串或两位小数（与前端约定）；百分比输入/存储转换工具（如佣金率 5 → 0.0500，见【裁定】BUG-070）；字符串枚举基类（API 只出英文 canonical 值，中文标签由字典/前端映射给出）。
- **依据**：【全局规范】§1（命名）、§4（权威枚举）、§7.4（数据约定：金额/时间）；【共享规范】§8.1；【裁定】BUG-070。
- **单测验收标准**：camel/snake 往返无损；时间序列化带时区；金额 0.1+0.2 场景无浮点误差；百分比 5 ↔ 0.0500 往返；非法枚举值入参被拒。

### FW-A05 API 契约产出与前端客户端生成
- **目标**：后端接口自动产出 OpenAPI，前端 API 客户端由契约生成，杜绝旧代码 801 处手写 `/admin-api` URL（见【评估】）。
- **范围**：OpenAPI 导出脚本；前端 TS 类型 + 请求函数生成；CI 校验“契约变更必须同步重新生成”。
- **依据**：【评估】前端问题清单；【全局规范】§7.2（请求约定）、§7.3（`src/api/types/{module}.ts` 与 API 契约一一对应）。
- **单测验收标准**：导出的 OpenAPI 可被生成器无错消费；新增一个示例接口后，未重新生成客户端时 CI 校验失败。

### FW-A06 增删改查脚手架（后端 + 前端骨架生成）
- **目标**：落实已定的省用量规则“增删改查骨架用脚手架生成”，各模块的列表 / 新建 / 编辑 / 详情 / 删除骨架不手写。
- **范围**：输入为一张业务表的模型定义（字段、类型、字典、引用关系、权限码前缀）；生成后端模型、仓储、服务（含 FW-B06 引用校验与 1502 删除保护的挂接点）、接口（分页查询 / 详情 / 新建 / 修改 / 删除，统一响应与权限注解）、接口单测样板；生成前端列表页（UI-L01：QueryBar + DataTable + Pagination）、新建 / 编辑抽屉（FormDrawer + 字典下拉 + 选择器）、详情抽屉、路由与菜单种子；生成的代码只作为起点，业务规则在生成后补写；重复生成不覆盖已手工修改的文件（提示差异）。
- **依据**：zhang wu 已定的省用量规则；【全局规范】§2（命名、分页、响应）、§6.1（组件清单）；02 清单 UI-L01、UI-C06～C09、UI-C14～C15。
- **单测验收标准**：用一张示例表生成后，后端接口单测与前端路由冒烟直接通过；生成的接口带权限码、带租户过滤、删除被引用记录返回 1502；字典字段渲染为下拉、引用字段渲染为选择器；对已手工修改的文件再次生成时不覆盖并输出差异提示。

## B. 数据模型

### FW-B01 审计基类与租户字段
- **目标**：所有 `ims_*` 业务表统一继承基类。
- **范围**：`id`（BIGINT 主键）、`creator`、`create_time`、`updater`、`update_time`、`deleted`（逻辑删除）、`tenant_id`（BIGINT NOT NULL）。唯一业务编码列与 `deleted` 的组合唯一策略。
- **依据**：【共享规范】§7.6 审计字段规范、§7.4.1 主键规范、§7.5 多租户；【ADR-007】。
- **主键（✅ 已决策 D-01 后定稿）**：IMS 自有表用 BIGINT 自增主键；导入的 Football/OPS 用户与 OPS 业务数据保留原主键，序列起点设为最大值 + 1（04 清单 B-05）。【已核实，见 modules/B0a-框架/04-开工前核实.md §3：旧 IMS / opsbiz / ai_platform 主键都远低于 2^53；Football `system_users` 有 8 个雪花 id 超过 2^53（最大 2059567794397171712），保留原主键时须开启 id 字符串输出，或改为重新分配 id，待裁定】Football 直播表不迁移、不建 IMS 主键副本（见 FW-H06）。
- **单测验收标准**：任意新模型未继承基类 → 测试扫描失败；creator/updater 由请求上下文自动填充；逻辑删除后默认查询不可见；同业务编码“删除后可重建”。

### FW-B02 迁移体系（Alembic 基线，禁止运行时改表）
- **目标**：结构变更只走迁移脚本。
- **范围**：Alembic 基线迁移；禁止 `create_all`、禁止启动时 `ALTER`（旧代码 34 个 `ensure_*_columns` 与 34 个 compat SQL 补丁不得再现，见【评估】）；迁移在 CI 中 upgrade/downgrade 双向验证。
- **依据**：【评估】数据层问题；【ADR-009】Alembic；【共享规范】§7.7。
- **✅ 已决策 D-01**：Football 直播表（`live_room`）继续直连只读，**不纳入 IMS 迁移体系**——Alembic 不得生成任何作用于 Football 库的迁移（见 FW-H06）；IMS 对直播数据的扩展字段只加在 IMS 自有表上。
- **单测验收标准**：空库 `upgrade head` 成功；`downgrade base` 成功；代码库中出现 `create_all(` 或启动期 `ALTER TABLE` → 静态检查失败；模型与迁移不一致（autogenerate 产生差异）→ CI 失败；迁移脚本中出现 Football 表名（如 `live_room`）或 Football 连接 → CI 失败。

### FW-B03 组织与用户主数据模型
- **目标**：建立用户、部门、岗位、用户-部门关系、钉钉映射的全局表。
- **范围**：用户主表（ims_sys_user，本地完整管理，主键不可改，错误码 1211）、用户-部门（多部门 + 主部门，见 04 清单 B-26）、岗位（钉钉岗位，见 A-24）、钉钉映射（dingtalk userid / unionid）、用户状态（在职 / 冻结 / 离职，取【AUTH 规格】P2 `ACTIVE/FROZEN/RESIGNED`）。部门表见 FW-B08。
- **依据**：【ADR-009】用户主数据；【SYS】P1 用户「禁止改用户主键」；【共享规范】§7.2 `ims_auth_user_mapping`；【PRD】AUTH-002 组织同步。
- **单测验收标准**：修改用户主键 → 1211；同一钉钉 userid 只能映射一个用户；用户可属多个部门且有且只有一个主部门；离职 / 冻结用户不可登录。

### FW-B04 角色、菜单、权限明细模型
- **目标**：落实「角色＝权限唯一载体」。
- **范围**：角色（role_key、来源 MANUAL/DINGTALK_AUTO、状态 ENABLED/PENDING_CONFIG、数据范围、绑定钉钉岗位且唯一）、菜单（目录/菜单/按钮、权限码）、角色-菜单、角色-功能点 R/W/D 明细、用户-角色（多角色）、租户与租户套餐-菜单。
- **依据**：【ADR-008】；【SYS】P2、P3、P8；【共享规范】§7.2 `ims_sys_role`/`ims_sys_role_menu`/`ims_role_perm_detail`；【ADR-007】租户套餐。
- **说明**：租户套餐按 04 清单 A-17 纳入本期（zhang wu 确认按原裁定）；D-01 决策后租户与套餐数据在 IMS 自有库维护（04 清单 B-29、C-20）。

### FW-B06 引用完整性（应用层实现，不建物理外键）　✅ 已决策 D-02
- **目标**：在**不建物理外键**的前提下（zhang wu 决策：物理外键会给数据迁移带来大问题），由框架统一保证引用完整性，杜绝旧代码“孤儿数据靠补丁修”的问题（【评估】）。
- **范围**：
  1. **引用登记表（外键字典的代码化）**：每个模型以声明方式登记“本表字段 → 被引用表”的关系及删除策略，产出与【共享规范】§7.4.2 外键字典一致的清单（文档由代码自动生成）；
  2. **写入前校验（服务层）**：新增/修改时校验被引用记录：不存在或已逻辑删除 → **1500**；已停用/注销 → **1501**（允许引用停用对象的字段须显式声明）；跨租户 → **1504**；
  3. **删除前被引用检查**：删除（含逻辑删除）、停用被引用的主数据时，若仍有未删除的引用记录 → **1502「关联的实体已被其他记录引用」**，响应带引用方类型与数量（不泄漏跨租户信息）；
  4. **软删除级联规则**：每条引用关系必须声明三选一策略——`RESTRICT`（默认，被引用即拒删，返回 1502）、`CASCADE_SOFT`（父记录逻辑删除时子记录同事务逻辑删除，如单据与其明细行）、`SET_NULL`（可空引用置空并记变更日志）；未声明策略 → 启动失败；
  5. **并发保护**：校验与写入在同一事务内，对被引用行加共享锁或以版本号复核，避免“校验通过后被删”；
  6. **批量导入 / 迁移**：导入与迁移走同一校验器（可批量模式），失败行进入错误清单（FW-H02、FW-H05）。
- **依据**：zhang wu 2026-10-12 决策 D-02；【共享规范】§7.3.1、§7.4.2（逻辑外键，应用层校验）；`产品规格/错误码映射表-附录.md` §3（1500 关联实体不存在 / 1501 已停用注销 / 1502 已被其他记录引用 / 1503 字典值不合法 / 1504 跨租户）；OPS `GLOBAL-CONVENTIONS.md` §11.3（删除/停用被引用的实名人 → 拒绝）。
- **单测验收标准**：
  1. 插入引用不存在 id → 1500；引用已停用对象 → 1501；引用他租户对象 → 1504；
  2. 删除被引用的实名人 / 公司 / 账号 → 1502，且响应含引用方类型与数量；停用被引用对象 → 1502；
  3. `CASCADE_SOFT` 关系：删除父记录后，子记录全部 `deleted=1`，且在同一事务（人为制造子记录删除失败时父记录也不删除）；
  4. `SET_NULL` 关系：删除后引用字段为空，并产生一条变更日志；
  5. 新增一个模型字段引用其他表但未在登记表声明 → 启动/CI 失败；
  6. 并发测试：A 事务删除被引用行、B 事务同时新增引用 → 两者不能同时成功；
  7. 由登记表自动生成的外键字典文档与代码一致（快照测试）。

## C. 数据层

### FW-C01 会话、事务与仓储基类
- **目标**：统一数据库会话、事务边界与通用 CRUD。
- **范围**：请求级会话；服务层事务装饰器；通用仓储（按 id 取、分页列表、逻辑删除、批量操作）；软删除默认过滤；乐观并发控制仅在模块明确需要时启用（规格未统一要求，不默认加）。
- **依据**：【ADR-009】SQLAlchemy 2.0；【共享规范】§7.6。
- **单测验收标准**：服务层异常时事务整体回滚；逻辑删除记录默认不出现在列表；`include_deleted=True` 可查到。

### FW-C02 租户隔离与数据范围过滤（统一中间件执行点）
- **目标**：租户过滤 + 数据范围过滤**只在一处**执行，业务代码禁止手写。
- **范围**：查询构造时自动追加 `tenant_id = ctx.tenantId`；按模型声明的“数据范围归属字段”（如部门字段、IP 组字段、负责人字段）自动拼接 BR-305 四级范围谓词；认证级接口白名单（只校登录 + 租户，不做 dataScope）需显式登记；发布/分享数据的“创建者范围 ∩ 查看者范围”双重过滤（BR-212）。
- **依据**：【SYS】P2A 第 1～7 条；【PRD】§1.4 BR-305；【ADR-007】；【共享规范】§7.5.4 开发红线。
- **单测验收标准**：
  1. A 租户用户查询不到 B 租户数据；跨租户按 id 访问 → 1504；
  2. 数据范围 ALL/DEPT/IP_GROUP/SELF 各构造一组数据，断言可见集合精确匹配；DEPT 不含下级部门；
  3. 多角色用户的数据范围取并集；
  4. 未声明数据范围归属字段的业务模型注册到需过滤的路由 → 启动失败（防漏配）；
  5. 业务代码中出现手写 `tenant_id ==` 过滤 → 静态检查失败；
  6. 白名单外的接口缺少上下文 → 拒绝（fail-closed）。

### FW-C03 敏感字段：加密存储与脱敏输出
- **目标**：敏感字段后端统一加密/脱敏，前端不承担脱敏责任。
- **范围**：AES-256 字段加密（证件号、手机号等，BR-306）；输出脱敏规则：身份证前 3 后 4、手机号 `138****5678`；按权限码决定是否返回明文；成本类金额对只读财务查看角色统一脱敏为 `***`（【裁定】BUG-080，R9 只读 + 成本脱敏）。
- **依据**：【PRD】§1.4 BR-306；【全局规范】§5.2（敏感字段规范，含 R9 成本 `***`）；【裁定】BUG-080。
- **单测验收标准**：数据库中密文不等于明文；无“查看明文”权限的用户得到脱敏值；同一接口对有权限用户返回明文；R9 等只读角色读取成本字段得到 `***`；导出接口同样脱敏。

### FW-C04 业务编号生成器与幂等
- **目标**：统一业务单号生成，防重复提交。
- **范围**：编号生成器（前缀 + 日期 + 序列，Redis 原子自增 + 唯一索引兜底），首批规则：场次 ID `IMS + yyyyMMdd + 3 位平台码 + 4 位当日序列`（【共享规范】§7.4.3）、竞品送审单号 CA / 档案编号 CP（【裁定】B089）；写接口 `client_token` 幂等（场次创建、冲话费强制）。
- **依据**：【共享规范】§7.4.3、§8.1 幂等（`client_token`）；【全局规范】§7.2 幂等（请求头 `clientToken`，命名不一致见 04 清单 B-14）；【裁定】B089。
- **单测验收标准**：并发 100 次生成无重复；日切序列重置；同一 `client_token` 重放返回同一结果且只落一条记录；序列达到 9999 的降级策略按规范执行并产生告警事件。

## D. 认证与权限

### FW-D01 本地登录与令牌
- **目标**：实现本地账号登录、令牌签发与会话管理。
- **范围**：用户名/密码登录；连续失败 5 次锁定 15 分钟；access token 2 小时、refresh token 7 天；同一用户最多 3 个有效会话（超出踢最早）；登出与令牌黑名单（Redis）；登录日志写入（FW-F01）。
- **依据**：【ADR-009】；【PRD】AUTH-001。
- **单测验收标准**：第 5 次失败后锁定、15 分钟后解锁（时间可注入）；过期 access 被拒、可用 refresh 换新；第 4 个会话登录后最早会话失效；登出后旧令牌被拒；离职/停用用户登录被拒。

### FW-D02 钉钉 SSO 登录（适配层）
- **目标**：支持钉钉扫码/免登换发 IMS 令牌。
- **范围**：state 生成与校验（Redis，防重放）、回调换取钉钉身份、映射到 IMS 用户；未映射用户的处理（拒绝 + 提示）；钉钉客户端走 FW-H04 外部集成适配层（测试用 stub）。
- **依据**：【PRD】AUTH-001、§9 NFR（SSO 可用性 > 99.5%）；【共享规范】§8.4 钉钉；【ADR-009】。
- **✅ 已决策 D-06**：钉钉使用真实环境（测试企业/应用凭据由运维提供），单测仍用 stub。
- **单测验收标准**：state 只能用一次；state 过期被拒；钉钉 userid 未映射 → 明确错误码而非 500；stub 下完整走通“回调 → 签发令牌”。

### FW-D03 功能权限（菜单 / 按钮 / 功能点 R·W·D）
- **目标**：后端接口按**权限码**鉴权，前端按权限码显隐；**任何代码不得按角色名称判断**。
- **范围**：接口声明所需权限码（装饰器/依赖注入，而非旧代码的 URL 前缀规则表，见【评估】`perm.py API_RULES`）；功能点 R/W/D 判定；多角色权限取并集；空权限 / PENDING_CONFIG 角色 / 未配置 → 1008（fail-closed）；当前用户权限集合接口（供前端菜单与按钮显隐）。
- **依据**：【ADR-008】；【SYS】P2、P2A 第 4 条；【全局规范】错误码 1008；【评估】“157 处硬编码角色判断”；【裁定】BUG-080（只读角色写按钮隐藏且后端拒绝）、C086（只读预览不得 403，显示自身数据范围数据）。
- **单测验收标准**：
  1. 每个业务路由必须声明权限码或登记为认证级白名单，否则启动失败；
  2. 只有 R 权限的用户调用写接口 → 1008（或约定的无权码），调用读接口成功；
  3. 角色 PENDING_CONFIG 的用户调用任何业务接口 → 1008；
  4. 代码静态检查：出现按角色名/角色 key 字符串比较的分支（如 `== "R1"`、`"admin" in roles`）→ 失败；
  5. 权限变更后，用户权限缓存在 5 分钟内生效（【PRD】§9 权限同步 < 5 min）。

### FW-D04 数据范围（BR-305）
- **目标**：角色配置数据范围，FW-C02 统一执行。
- **范围**：四级 ALL / DEPT（本部门，不含下级）/ IP_GROUP（所属 IP 组）/ SELF；多角色取最大并集；未配置视为无权。
- **依据**：【PRD】§1.4 BR-305；【SYS】P2 第 3 条、P2A 第 2 条。
- **单测验收标准**：同 FW-C02 第 2、3 条；未配置数据范围的角色 → 无数据（非全部数据）。

### FW-D05 岗位 → 角色自动供给（ADR-008 护栏 G1–G7）
- **目标**：钉钉岗位变化时按规则自动给用户授予/回收角色，且默认安全。
- **范围**：供给规则（岗位 → 角色，1:1）及版本；新岗位自动建 PENDING_CONFIG 空权限角色并给 R1（系统管理员角色的权限码持有者）发待办；来源标记 DINGTALK_AUTO / MANUAL（页面文案“钉钉自动 / 手工”，【裁定】BUG-060）；幂等；规则归档。
- **依据**：【ADR-008】；【PRD】§4.2.1 G1–G7；【AUTH】P3 岗位-角色供给规则；【SYS】P2「一键从岗位生成角色」。
- **单测验收标准**：G1 fail-closed（新岗位用户无任何权限）；同一事件重复投递结果不变（幂等）；手工授予的角色不会被自动回收；岗位变更后旧自动角色被回收、新角色授予；生成 R1 待办（经 FW-G02）。

### FW-D06 前端路由与按钮权限守卫（接口侧支撑）
- **目标**：为前端提供“我的菜单树 + 权限码集合 + 数据范围说明”，支撑侧栏渲染与按钮显隐。
- **范围**：当前用户菜单树（按租户套餐 ∩ 角色菜单过滤）、权限码集合、个人信息；页面「统计范围：全部 / 本部门 …」文案所需的数据范围中文说明（【裁定】B025）。

### FW-D07 钉钉组织同步引擎（部门 + 人员）
- **目标**：把钉钉组织（部门、人员、岗位）同步到 IMS，且与本地维护的部门共存。
- **范围**：
  1. 同步方式：钉钉事件订阅（入职 / 调岗 / 离职 / 部门变更）实时处理 + 全量对账（手动触发；建议每日凌晨定时一次，FW-H01）；失败重试与死信、重放（【AUTH 规格】P2 `OrgSyncStatus`：待处理 / 成功 / 失败重试 / 死信）；
  2. **冲突规则（✅ zhang wu 已定）**：以钉钉为准——`source=DINGTALK` 的部门，钉钉同步会覆盖 IMS 本地对同一部门的修改（名称、上级、排序、负责人）；被覆盖的本地修改写入变更日志（FW-F02）便于追溯；
  3. 钉钉新增部门 → 新建 `source=DINGTALK` 部门；钉钉删除部门 → IMS 将该部门停用并逻辑删除；其下人员按钉钉最新归属更新，若人员在钉钉中已无任何部门（或为未绑定钉钉的本地用户），移入「待分配」系统部门并给持有用户管理权限码者发待办（FW-G02）；
  4. `source=LOCAL` 的本地部门：同步不删除、不改名、不移动；其父部门被钉钉删除时的处理见 04 清单 A-22（✅ zhang wu 已同意：挂到最近的存活祖先部门，标记 `local_orphan`，发待办确认）；
  5. 人员：按钉钉 userid / 手机号匹配本地用户（【PRD】§5.1 第 2 条），新增人员自动开通并触发岗位→角色供给（FW-D05）；离职 → 用户状态离职、会话失效、触发离职归还（ACCT-003）；
  6. 同步结果与对账报告供 M01「组织架构同步」页展示；同步延迟指标（BR-001 < 5 分钟）。
- **依据**：【PRD】§3A AUTH-002、§5.1、§6.1；【AUTH 规格】P2；zhang wu 2026-10-12 部门冲突规则；OPS `PRD-M9-系统管理.md` ADR-013（手动同步部门、同步人员）。
- **单测验收标准**（钉钉适配器用 stub）：
  1. 钉钉改名 / 移动一个 IMS 本地改过名的 DINGTALK 部门 → 同步后为钉钉值，变更日志记录被覆盖的本地值；
  2. 钉钉删除部门 → IMS 部门停用 + 逻辑删除，原成员按钉钉新归属更新，无归属者进入「待分配」并生成待办；
  3. LOCAL 部门在全量对账后名称、上级、成员不变；其父 DINGTALK 部门被删 → 按 A-22 规则挂到最近存活祖先并标记、生成待办；
  4. 同一事件重复投递结果不变（幂等）；乱序事件以钉钉事件时间为准；
  5. 失败事件进入重试，超过上限进入死信，可重放；
  6. 离职事件 → 用户不可登录、已有令牌失效。

### FW-H07 钉钉考勤集成（独立钉钉应用）　✅ 已决策 D-07
- **目标**：为日报「应提交天数」提供请假数据；考勤所在钉钉应用与 IMS 的钉钉应用不是同一个，按独立应用对接。
- **范围**：
  1. **独立配置**：考勤应用单独一组配置项——AppKey、AppSecret、接口地址、超时、是否启用、模式（真实 / 模拟）；与 IMS 钉钉应用配置（FW-D02）互不复用；AppSecret 加密存储，页面与日志只显示脱敏值；修改配置记审计日志；访问令牌单独获取与缓存；
  2. **适配器**：`DingtalkAttendanceClient`（只读：按人员、日期区间取请假记录），经 FW-H04 适配层，带超时与重试；**开发阶段默认模拟接口**，模拟数据覆盖：无请假、整天请假、半天请假、跨月请假、接口超时、接口报错；
  3. **工作日历**：IMS 内维护工作日历（法定节假日与调休上班日，按年由种子脚本导入、管理员可修改），供应提交天数计算；
  4. **应提交天数计算**：考勤未启用（权限开通前）时，应提交天数 = 当月工作日 − 节假日（调休上班日计入工作日），**不扣请假**；考勤启用后 = 上述结果 − 当月请假天数（半天按 0.5 计，以考勤接口返回的时长为准）；考勤接口失败时退回“不扣请假”的算法，并在月度统计页顶部提示“应交天数暂按当月工作日计算，考勤数据延迟同步”（【MEET 规格】第 542 行原文口径）；
  5. 每日由 Worker 拉取前一日请假数据写入 IMS 表（FW-H01），月度统计只读 IMS 表，不在查询时实时调钉钉。
- **依据**：zhang wu 2026-10-12 决策 D-07；`产品PRD/IMS第二期PRD-V2.md` MEE-S-R1；【MEET 契约】§2.3.2 `shouldDays`；【MEET 规格】第 40、381、542 行。
- **单测验收标准**：
  1. 考勤未启用：给定某月工作日、1 天节假日与 1 天调休上班日，应提交天数计算正确且不扣请假；
  2. 考勤启用（模拟）：整天请假扣 1、半天请假扣 0.5、跨月请假只扣本月部分；
  3. 考勤接口超时 → 退回不扣请假的算法，并返回降级标记供前端显示提示；
  4. 考勤配置与 IMS 钉钉应用配置分开：修改其中一组不影响另一组；AppSecret 在接口响应与日志中均为脱敏值；
  5. 切换真实 / 模拟只改配置；模拟模式下不发出任何外部网络请求；
  6. 每日拉取任务重复执行不产生重复请假记录。
