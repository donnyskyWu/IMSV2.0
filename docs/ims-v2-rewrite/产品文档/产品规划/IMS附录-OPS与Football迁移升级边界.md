# IMS 附录：OPS / Football → 一体化管理系统 迁移与升级边界

> **文档用途**：作为《IMS 产品规划（整体版）》的配套附录，回答三件事——要从 Football、OPS **迁什么 / 留什么**，升级期 **怎么过渡**，对现有一体化规划 **改哪些口径**。  
> **读者**：管理层、产品、架构。不含接口字段级设计。  
> **依据**：IMS 整体版 v4、IMS V1 PRD、架构复核意见、运营数据平台 PRD v9.2；**ADR-IMS-001（双轨共享 OPS 业务库）**。  
> **版本**：v1.2 ｜ 2026-09-29 ｜ 状态：与完整 PRD v2.1 对齐

---

## 0. 一句话结论

**IMS 是独立应用与独立闭环，不是独立再复制一份业务库。** 现网 Football、OPS 继续跑；IMS 上线后 **双轨共用 `oa_*` 等现网业务表**，系统管理自管。IMS 稳定后 **停 OPS**；**Football 长期保留**，只用 HTTP WebAPI。禁止 RPC / Feign / 直连 Football 库。业务表 **只加列/加表，不搬数来回同步**。

---

## 1. 建设铁律（已确认，后续设计不得违反）

| # | 铁律 | 落地含义 |
|---|------|----------|
| **L1** | IMS 独立系统 | 独立部署、独立网关。**不**与 Football 同进程、不直连 Football 业务库。**业务数据源 = 现网 OPS 库（双轨共享）**。 |
| **L2** | 对 Football **只用 HTTP API** | **优先 WebAPI**：复用 Football 已有 `/admin-api/**`。仅当现网覆盖不到时再补 **OpenAPI**。 |
| **L3** | **禁止** | Football ↔ IMS：**RPC、Dubbo、OpenFeign、消息当主链路、`@DS` 直连 member/pay/match/system 库**。过渡期也不开例外。 |
| **L4** | 切流停 OPS | 功能在 IMS 内实现。**禁止调 OPS 服务。** IMS 验收通过后停 OPS 进程。 |
| **L5** | 业务表 **只扩展、不复制** | 原表名/列/主键不变；IMS 加列、加从表、加 `ims_*`。禁止第二份业务库双向同步。 |
| **L6** | 功能完备 + 用户共用权参分管 | 运营用户一张表；角色菜单字典参数 IMS 自管。Football 仅外部数据。 |

```
                    ┌─ HTTP WebAPI（优先） / OpenAPI ─┐
  Football 各服务 ──┤  方案 / 订单 / 比赛 / 作者…      ├──►  IMS（完备运营后台）
  （独立集群）      └─ 禁止 RPC / Feign / 直连库 ─────┘      │
                                                             │ 现网 OPS 业务库（与 OPS 进程双轨共享）
                                                             │ + IMS SYS + ims_ 新表
```

## 2. 三套系统目标定位（建设后）

| 系统 | 现在实际承担 | 进入 IMS 后定位 |
|------|----------------|-----------------|
| **Football** | 登录/用户/角色/菜单；会员作者、方案、比赛、支付、营销 IM、部分直播房间 | **独立业务系统**。对 IMS 只暴露 WebAPI。C 端/交易/方案分发仍在 Football。 |
| **OPS** | IP 组、账号资产、SOP/任务/内容、采集、指标、监测、账号成本 | **双轨期继续运行**；IMS 稳定后下线。业务表留给 IMS 独占写 |
| **IMS** | 规划 20 模块 + 原 OPS 全量 | **独立完备管理后台**：原 OPS 能力 + 钉钉 SSO、领用归还、直播场次、培训会议、工作流、场次财务、穿透、AI 中台、系统管理 |

## 3. 模块对照：并入 / 扩展 / 新建 / 外部接入

**图例**：⬆ 并入 IMS（原表扩展）｜ ＋ 新建 `ims_*` ｜ 🌐 仅 WebAPI 读/写 Football ｜ ⊘ Football 内留下、IMS 不搬表

### 3.1 OPS → IMS（必须并入，运行时不再调用 OPS）

| IMS 模块 | 现网 OPS | 动作 | 结构策略 | 数据 |
|----------|----------|------|----------|------|
| **06 证件** | M4 实名人 | ⬆ | 实名人表原列保留；加档案索引、到期、水印相关列/从表 | 全量迁 |
| **07 资产** | M4 公司/手机/手机卡 | ⬆ | 原表保留；加穿透冗余列或关系从表 | 全量迁 |
| **08 账号** | M4 平台/个人账号 | ⬆ | 原账号表保留；**加**领用/流转/归还/冲话费从表（不改原账号主键） | 账号及关联 **V1 必迁** |
| **19 IP 组** | M1 | ⬆ | `oa_ip_group` 等原表迁入 IMS 库（可同名）；加钉钉部门映射列 | 组与成员全量迁 |
| **16 采集** | M8/M10 | ⬆ | 采集配置、任务、登录信息 **随 OPS 并入 IMS 库**（原表扩展）。作品明细若在 OPS/采集库：**迁入 IMS 或 IMS 自有采集库**，不依赖 OPS 进程 | 配置+任务必迁；明细平滑迁（同结构） |
| **18 监测** | M7 | ⬆ | 阈值/规则原表扩展 | 规则迁；明细跟采集库 |
| **17 分析** | M6 | ⬆ | 指标、自定义查询原表保留；V3 报表/下钻新建表 | 定义与模板迁 |
| **15 内容** | M2 | ⬆ | SOP/任务/内容原表保留，加执行标准/交付物/质量清单列或从表；ComfyUI 为新从表 | 全量迁 |
| **05 绩效** | M3 | ⬆ | 考核模板/结果原表保留；考试等新建从表 | 模板迁；历史归档 |
| **账号财务** | M5 | ⬆ | 成本表原结构迁入；ROI 计算在 IMS | 采购/过程成本迁入作期初 |
| **11 场次财务** | 无 | ＋ | 新 `ims_*` 场次成本/分成；**不改** M5 账号成本表 | 场次账从 0 记 |
| **13 预警** | 监测+通知 | ⬆＋ | 通知/去重表扩展；规则中心可新建 | 新事件进 IMS |
| **系统管理** | M9 + 部分 Football 菜单 | ⬆ | 用户/角色/菜单/字典/参数：**能迁则原表扩展**；登录改为 IMS 钉钉 SSO 后用户表加钉钉列，**保留原 userId 列便于 FK** | 见 §4 |
| **20 AIR** | AI 模型/提示词 | ⬆（V2） | 原配置表扩展为连接器；技能/知识新建 | 配置迁 |
| **首页/计划/任务** | M0/M2 | ⬆ | 原表扩展 | 全量迁 |

**采集库说明（相对 v1.0 修订）**：采集属于 OPS 功能，必须并入 IMS，**不能长期「IMS 挂 OPS 库」**。迁数时表结构保持不变，仅切换数据源到 IMS。若部分作品数据实际在 Football，则 IMS **用 WebAPI 拉取/对账**，不直连库。

### 3.2 Football → IMS（只 API，不搬交易库）

| 能力 | 动作 | 接入方式 | 说明 |
|------|------|----------|------|
| 方案 `author_article` | 🌐 | **WebAPI** 创建/更新/查询/状态变更（现网 member 写接口若已是 HTTP 管理 API 则直接调） | 表留在 Football；IMS 内容表保留 `author_article_id` 扩展列 |
| 比赛/选赛 | 🌐 | WebAPI 查询赛程 | 不迁 match 库 |
| 订单/营收（ROI 用） | 🌐 | WebAPI 查询订单/流水汇总 | 不迁 pay 库；IMS 可落本地汇总缓存表（扩展，非 Football 原表） |
| 作者/会员只读 | 🌐 | WebAPI | 不迁 member 用户体系 |
| 直播房间 | 🌐 可选 | WebAPI 查询 | 与 IMS 场次不是同一对象；场次表加 `football_room_id` 可空列 |
| 用户/角色/菜单（历史） | ⬆ 一次性迁数 | **不是运行时 RPC** | 把运营后台需要的用户角色菜单 **导入 IMS 自有权限表**（结构对齐 Football system 表便于迁）；之后 IMS 自管，钉钉同步增量 |

运营人员 **日常不登录 Football 后台做 OPS 的事**。Football 管理端只保留其原业务（会员、方案前台、支付等）。

### 3.3 IMS 纯新建（现网没有的，可用新表）

| 模块 | 结构 |
|------|------|
| **01 权限** SSO / 组织同步 / 岗位模板 / 工作台 | 用户表在「Football system 表结构迁入 + 加钉钉列」上扩展；岗位模板、SSO 会话为新表 |
| **10 直播场次** | 新表；FK 指向 **并入后的账号表原主键** |
| **02 / 03 / 09** 培训、会议日报、数据上报 | 新 `ims_*` |
| **14 工作流** | 新引擎表；内容域仍用并入的 SOP 表，待办统一视图 |
| **12 数据中心** | 新查询/预计算表；维度 ID 用并入后的账号/IP 组/实名人原 ID |

## 4. 系统管理（用户表共用，权参分管）

| 能力 | 目标态 | 结构 |
|------|--------|------|
| 用户 | **与 OPS 同一张运营用户表**（OPS 库） | 主键 = 业务 `assignee_id`；钉钉 userid 优先、否则手机号对齐；两边同步幂等 upsert |
| 角色 / 菜单 | IMS 自有 | 不写 Football 角色菜单 |
| 字典 / 参数 | IMS 自管表 | dictValue 兼容现网；同 key 参数改则两边一起改 |
| 日志 / 消息 | IMS 新写 | 可不迁历史 |

禁止 JDBC 将 Football `system_users` 当运行时用户 SSOT。存量 FK 若已是历史 Football id，共用表主键对齐这些 id，只补钉钉列。

## 5. 内容与 Football 方案（WebAPI 同步）

现网 OPS 双写方案、删除不同步。IMS 内实现同步客户端（HTTP），规则建议：

| 动作 | 默认 |
|------|------|
| 创建/更新 IMS 内容 | 调 Football **WebAPI** 写草稿/更新（复用现网 HTTP，不新开 RPC） |
| IMS 删草稿 | 调 WebAPI 删除或下架；失败记补偿任务，不阻塞 IMS 逻辑删 |
| 映射 | 内容表保留 `author_article_id`（原扩展列），不改 Football 表 |

## 6. 双轨与 cutover（不搬业务库）

### 6.1 结构原则

1. **列兼容**：原 `NOT NULL`/默认值/枚举尽量不变；新列可空或有默认，保证 OPS 旧代码仍跑。  
2. **业务主键不变**：账号、IP 组、任务、内容沿用现网 ID。IMS 登录用户是另一套 ID。  
3. **先共享后加列**：IMS 指向现网库 → 回归 OPS → 再 ALTER。  
4. **禁止**再建同构副本 + ETL 当主路径。

### 6.2 范围

| 类别 | 内容 |
|------|------|
| **共用、不复制** | 资产、账号、实名人、IP 组、SOP/任务/内容、采集配置与明细、指标/查询、监测、账号成本 |
| **IMS 自建** | SYS、钉钉映射、直播/培训等 `ims_*` |
| **Football 不连库** | 方案/订单/比赛/会员；WebAPI |
| **不迁** | 历史场次利润/分成 |

### 6.3 过渡

```
阶段 A  IMS 连接现网 OPS 业务库（只读灰度）+ 自建 SYS + 人员映射
阶段 B  兼容加列 / 新 ims_* 表；IMS 写业务表；OPS 仍可写（双轨）
阶段 C  IMS 稳定 → OPS 停写停机；Football 继续
```

- **没有**「IMS 调 OPS、OPS 调 IMS」的目标态。  
- 进行中任务不换主键，两侧看见同一行。
