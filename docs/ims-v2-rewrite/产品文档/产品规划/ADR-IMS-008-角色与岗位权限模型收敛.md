# ADR-IMS-008：角色与岗位权限模型收敛（角色 = 权限唯一载体）

> **状态**：**已确认**（2026-10-04 · 用户拍板）
> **关联**：ADR-IMS-002（Go + 轻量 Vue）、ADR-IMS-003（OPS 并入交互）、ADR-IMS-006（范围冻结）、完整 PRD §4 / §01、`AUTH-权限管理-页面规格.md`（AUTH-003）、`SYS-系统管理-页面规格.md`（SYS-002）、`AUTH-权限管理-API契约.md`、`SYS-系统管理-API契约.md`
> **取代**：原 AUTH-003「岗位模板 = 独立权限模板（`permDetail` 功能点 R/W/D + `dataScope` 自成一套矩阵）」的定位；原 PRD §4.1「岗位模板 AUTH-003 与 OPS 岗位码对齐，避免任务派发失效」中隐含的**双权限矩阵并列**语义。

---

## 1. 背景与问题

原模型存在**两套并行的权限勾选矩阵**：

| 载体 | 勾选对象 | 定位 |
|------|----------|------|
| **SYS-002 角色** | 菜单 / 按钮**权限码**（兼容 `ops:*`） | 权限职责集合 |
| **AUTH-003 岗位模板** | **功能点 × R/W/D** + `dataScope` | 岗位 × 权限固化成套 |

同一份「谁能干什么」被维护两遍：改一个功能点权限要**同时改角色与岗位模板**，且两者边界含糊（ADR-IMS-003 已登记「仍无独立数据权限 L3（岗位模板 dataScope + 角色菜单）」）。这与 ADR-IMS-002「轻量、少框架魔法、快启动」的取向冲突——轻量系统不应长期维护双权限模型。

**核心澄清**：需要收敛的是「**权限明细的载体**」，不是「**岗位**」这个概念本身。岗位（钉钉同步的组织岗位）与角色（权限职责）在基数、来源、版本、触发方式上均不同（见 §3），不可简单等价。

---

## 2. 决策

1. **角色（SYS-002）成为权限的**唯一载体**。角色吸收原岗位模板的权限明细：
   - `permDetail`：功能点 / 菜单**权限码** + **R/W/D**（合并原两套勾选模型为一份）；
   - `dataScope`：数据范围（`ALL` / `DEPT` / `IP_GROUP` / `SELF` = 全部 / 本部门 / IP 组 / 仅本人，**与 BR-305 对齐**；「本部门」不含下级。替代原 ADR-IMS-003 所述「无独立数据权限 L3」）；
   - `dingtalkPosition`：**可选**的钉钉岗位绑定，**唯一**（一个钉钉岗位至多绑定一个角色，沿用原 POS-R1）。
2. **岗位模板（AUTH-003）从「权限模板」降级为「岗位 → 角色 自动供给规则」**：
   - 不再自带独立权限明细，改为声明「某钉钉岗位 → 授予某角色（+ 可选附加角色）」；
   - **保留版本管理与审计**（原 POS-R2：变更生成新版本、已套用用户不自动变更），用于供给规则的灰度与可追溯；
   - 页面语义由「配权限矩阵」改为「配供给规则」。
3. **钉钉同步岗位 → 无对应角色则自动建角色**（用户提议，采纳并加护栏，见 §4）。
4. **用户权限判定只走角色并集**（沿用 OPS FR-M9-001 多角色 `roleIds` 并集语义），不再有第二套矩阵参与判定。
5. **岗位编码仍为外部契约，不得改名或废弃**：`dingtalkPosition` / `positionCode` 继续与 `dict_position`、OPS `IPG-002` 对齐，供培训域「岗位资料库 / 按岗位指派」当 SSOT 引用（PRD §02 禁止手输岗位编码）。

---

## 3. 为什么「岗位」不能等同于「角色」

| 维度 | 角色（SYS-002） | 岗位（钉钉同步） | 结论 |
|------|----------------|-----------------|------|
| 本质 | 权限职责集合 | 组织人事属性 | 不可等价 |
| 来源 | IMS 自建 | 钉钉同步 | 不同 |
| 基数 | 用户可挂**多角色**，权限取并集 | 用户可身兼**多岗**；同岗可不同权 | 不可 1:1 |
| 版本 | 无版本 | 供给规则需版本（POS-R2） | 角色需补 |
| 触发 | 手工分配 | 入职 / 调岗事件自动套用 | 角色无此概念 |
| 外部契约 | 无 | `dict_position` / `IPG-002` / `positionCode` | 岗位不可动 |

**示例（反证）**：同在「直播运营」岗位，A 承担审核、B 不承担。若岗位＝角色，则无法表达同岗不同权。故保留岗位作为**供给触发键**，权限仍由角色承担。

---

## 4. 自动建角色护栏（fail-closed）

钉钉同步到「无对应角色」的岗位时，自动建角色**必须**满足：

| # | 护栏 | 规则 |
|---|------|------|
| G1 | **fail-closed** | 自动创建的角色权限为**空集**；系统**绝不**因「找不到角色」而放行任何权限；默认拒绝 |
| G2 | **来源标记** | `source = DINGTALK_AUTO`，与手工角色（`source = MANUAL`）区分；UI 展示来源角标 |
| G3 | **待配置状态** | `status = PENDING_CONFIG`（待配置）；配置权限后方转 `ENABLED` |
| G4 | **进待办** | 推「新岗位 X 已自动建角色，请配置权限」到 **AUTH-004 待办中心**（R1 收件） |
| G5 | **1:1 唯一** | 一个钉钉岗位 → 至多一个自动角色（沿用 POS-R1 唯一性） |
| G6 | **幂等** | 以 `dingtalkPosition` 为唯一键 upsert；重复同步不重复建、不覆盖已配置权限 |
| G7 | **回收** | 岗位消失且角色无在用用户 → 归档（沿用 POS-R3：删除前须确认无在用用户） |
| G8 | **审计** | 自动创建/自动挂载均写 IMS 操作日志（SYS-006） |

> **反面模式（禁止）**：`if (无角色) { 放行 }` —— 任何形式的「无角色即放行」一律禁止。

## 5. 数据模型

| 表 | 变更 | 说明 |
|----|------|------|
| `ims_sys_role`（角色） | **加列** | `data_scope`、`dingtalk_position`（可空唯一）、`source`（MANUAL / DINGTALK_AUTO）、`status`（ENABLED / PENDING_CONFIG） |
| `ims_sys_role_menu`（角色-菜单） | 沿用 | 权限码集合（原 SYS-002 语义不变） |
| `ims_role_perm_detail`（新增） | 新建 | 功能点 × R/W/D 明细，FK → 角色（承接原 `ims_position_template_perm` 的**权限明细**语义） |
| `ims_position_template`（供给规则） | **语义收敛** | 由「权限模板」→「岗位→角色 供给规则」：保留 `template_name` / `dingtalk_position` / `version` / `status`；新增 `grant_role_ids`（授予角色，1..n）；**移除** `perm_detail`（迁至角色侧） |
| `ims_position_template_perm`（原） | **废弃/迁移** | 权限明细迁移至 `ims_role_perm_detail`；本表在切片中标注 **DEPRECATED**（不物理删列，沿用只加列铁律） |

**迁移顺序**（一次性，见 §7）：先建角色侧明细 → 回填历史岗位模板权限到对应角色 → 供给规则改挂角色 → 原表置 DEPRECATED。

## 6. 权限与页面影响

| 页面 | 变更 |
|------|------|
| **SYS-002 角色**（`/ims/system/role`） | 权限配置区吸收**功能点 R/W/D** + **数据范围** + **钉钉岗位绑定**；展示 `source` 角标与 `PENDING_CONFIG` 状态；新增「一键从岗位模板生成角色」 |
| **AUTH-003 岗位模板**（`/ims/auth/position`） | 重定义为「岗位-角色供给规则」列表：模板名 / 钉钉岗位 / 授予角色 / 版本 / 状态 / 套用人数；抽屉改为选角色而非勾权限矩阵 |
| AUTH-004 工作台 | 待办来源新增「岗位自动建角色待配置」（G4） |
| 权限码 | 沿用 `ims:auth:position:*`（供给规则）、`ims:sys:role:*`（角色）；**不新增**独立数据权限菜单（数据范围并入角色，ADR-IMS-003 相应条订正） |

---

## 7. 迁移与验收

- **迁移脚本**：角色侧建 `data_scope` / `dingtalk_position` / `source` / `status`；`ims_role_perm_detail` 建表；按 `dingtalk_position` 回填历史岗位模板权限到同名角色（无角色则按 G1~G8 自动建）；供给规则表新增 `grant_role_ids` 并回填；原 `ims_position_template_perm` 置 DEPRECATED。脚本须可在 OPS 仍运行时执行（可空/默认值，ADR-IMS-001）。
- **验收**：① 角色页可配 R/W/D + dataScope + 钉钉岗位；② 岗位模板页改为供给规则、可授予角色；③ 新钉钉岗位同步 → 自动建 `PENDING_CONFIG` 空权限角色 + 进 R1 待办；④ 无角色用户访问受限功能**被拒**（fail-closed）；⑤ 重复同步幂等；⑥ 版本变更不自动影响已套用用户（POS-R2）。
- **回归**：现有 `US-AUTH-02`（岗位模板与权限预览）、`US-SYS-02`（配置角色菜单）用例须按新语义更新。

---

## 8. 明确不做

| 不做 | 说明 |
|------|------|
| 删除「岗位」概念 / 废弃 `dict_position` | 岗位是外部契约（§2.5） |
| 「无角色即放行」 | 违反 §4 G1 |
| 为自动角色预置默认权限 | 自动角色恒为空权限，待 R1 配置 |
| 物理删除 `ims_position_template_perm` | 只加列铁律（ADR-IMS-001），置 DEPRECATED |
| 另立「数据权限」独立菜单 | 数据范围并入角色（§6） |
