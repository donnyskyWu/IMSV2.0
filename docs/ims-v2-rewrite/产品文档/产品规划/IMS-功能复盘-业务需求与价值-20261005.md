## 0. 复盘结论速览

| 维度 | 结论 |
|------|------|
| **产品定位** | IMS = 神鱼体育**唯一运营与一体化管理后台**；管理层一屏可溯（人岗权 / 资产账号 / 直播场次 / 成本利润 / 人效），运营·内容·财务日常全在 IMS 完成，不再进 OPS |
| **功能完备性** | 覆盖 **28 模块 / 约 160 功能点**，8 大导航域（工作台 · 日常运营 · 公司资产 · 财务 · 协同与成长 · 数据决策 · AI 资源中心 · 系统与权限）；业务闭环**不依赖 Football 后台**（IR-05） |
| **本期边界（已收敛）** | ① **AIR 知识库 = 文件管理**（v2.6.34：语义检索整体移出范围、不部署 RAGFlow，`KbProvider=LOCAL`）；② **内容生产 = 7 子菜单**（v2.6.33：SOP 审核整体移除、模板免审；「全部任务」并入「我的任务」页内 Tab）；③ **LIVE 直播数据改读 `live_room` 只读（v2.6.34）** |
| **分期** | V1 基座+OPS 并入（1～14 周）→ V2 管理闭环（15～27 周）→ V3 决策层（28～42 周） |
| **架构铁律** | 独立应用 `/admin-api/ims/`；业务数据源 = 现网 OPS 库不搬库；Football **仅 HTTP WebAPI**；验收后**停 OPS**；现网表只加列 |
| **主要待决** | CONTENT 端到端联调 · Football 直播 metrics HTTP · 部分并入域 API 缺 DTO · 三处 IA 兼容 BLOCKED（详见 §5） |

> **一句话总纲**：IMS 把「**人的管理**（组织/权限/绩效/培训）」+「**货的管理**（账号/资产/证件/成本）」+「**场的管理**（直播场次/内容/采集/监测）」+「**数的管理**（指标/报表/查询/预警/穿透）」+「**智的管理**（AIR 技能/专家/知识/模型）」收进一个后台，让运营全链路的**动作、数据、成本、效果**在同一条链上可追溯、可结算、可优化。

### 域 1 · 工作台

#### 模块 00 首页工作台（HOME）

| 功能点 | 一句话·可实现的业务需求 |
|--------|--------------------------|
| HOME-001 运营仪表盘 | 按 IP 组筛选，把核心指标、图表、待办、快捷入口聚合到首屏，让管理者**打开就知道今天运营盘面如何**。 |
| AUTH-004 个人工作台 | 汇聚「我的待办 + 我的消息」（各预览 10 条、可进二级列表），让每个人**只看与自己有关的事**。 |

- **业务流程**：钉钉/手机登录 → 运营看板（HOME-001）看 IP 组盘面 → 切个人工作台（AUTH-004）处理待办 → 从待办跳转到具体业务页（审核 / 任务执行 / 审批）。
- **业务价值**：把「每天先到处翻系统找事」变成「一屏接收任务」，是全部业务模块的**统一入口与统一待办总线**；待办卡片本身是各业务队列的聚合出口。

### 域 2 · 日常运营

#### 模块 19a IP 组（IPG）

| 功能点 | 一句话·可实现的业务需求 |
|--------|--------------------------|
| IPG-001 IP 组树 CRUD | 用「大组→小组」两级树 + 左树右详情维护组织化作业单元（基本信息/成员/作者/统计）。 |
| IPG-002 成员与岗位分配 | 把人员和岗位（`dict_position`）挂进 IP 组，明确**谁在哪个组、干什么岗**。 |
| IPG-003 账号绑定 IP 组 | 让每个平台账号归属到具体**小组**，作为数据权限与作业分配的最小单元。 |
| IPG-004 作者管理 | 维护内容作者档案并与 IP 组关联，为内容归因、人效与 ROI 提供主数据。 |
| IPG-005 账号/粉丝/作品/内容分析 | 在组内直接看账号、粉丝、作品与内部内容的经营分析（支持补录）。 |

- **业务流程**：建大组 → 建小组 → 分配成员与岗位 → 绑定账号 → 关联作者 → 组内经营分析；后续内容/采集/成本/人效均**以 IP 组为过滤维度**贯穿。
- **业务价值**：IP 组是全系统的**经营单元与数据权限轴**（BR-305 四级权限中的「IP 组」级），把「公司→人→账号→内容→收入」串成可归因的组织结构。

#### 模块 10 直播管理（LIVE · 场次中心）

| 功能点 | 一句话·可实现的业务需求 |
|--------|--------------------------|
| LIVE-001 风控登记 | 开播前对账号/证件/设备等五类风险做检查与放行审批留痕，**未放行不得开播**。 |
| LIVE-002 下播与督办 | 录入下播九项指标（含 GMV），并对待录入场次形成督办队列，保证数据不漏填。 |
| LIVE-003 风险告警 | 对直播过程风险出告警并联动处置，把「出事才发现」变成「实时可见」。 |
| LIVE-004 台账导出/历史补录 | 导出场次台账、补录历史场次（标注「系统前数据」），形成完整场次档案。 |

- **业务流程**（场次中心 IA）：**场次列表 → 单场详情**（Tab：基本信息｜直播数据｜风控登记｜下播与 GMV｜关联资产/告警）→ 风控放行 → 开播 → 下播录入 → 48h 内进 FIN 成本核算 → 利润反查。
- **业务价值**：把直播从「散点台账」升级为**以场次为主维度**的经营管理对象；单场 GMV 直供场次财务，风控留痕让**开播合规可审计**；Football 房间信息只读 `live_room` 保证数据一致性。

#### 模块 15 内容生产（CONTENT · 本期 7 子菜单）

| 功能点 | 子菜单 | 一句话·可实现的业务需求 |
|--------|--------|--------------------------|
| CONTENT-100 / 001 SOP 模板 | SOP管理 | 用 DAG/并行/节点类型定义内容生产标准流程，节点挂交付物与质量清单，**模板保存即生效（免审）**。 |
| CONTENT-102 计划管理 | 计划管理 | 用计划向导/列表编排一段周期内的内容生产计划（**营销计划为 SOP 属性**，不在此维护）。 |
| CONTENT-104/105 工作任务登记 | 工作任务登记 | 登记赛事/营销计划/直播任务，按 SOP 出任务，参数控制是否自动建草稿（jingcai 开关）。 |
| CONTENT-103 我的任务 | 我的任务 | 领取并执行自己的任务，**完成受内容审核门禁控制**；「全部任务」为页内 Tab 可见全量。 |
| CONTENT-106 内容管理 | 内容管理 | 完成内容 CRUD、玩法（matchScheme）、AI 脚本/成片（内嵌）、提交审核的**内容主工作区**。 |
| CONTENT-107 公推模板库 | 公推模板库 | 沉淀可复用的公推排版模板，一键套用实现**内容样式标准化**。 |
| CONTENT-005 内容审核 | 内容审核 | 按可配置级数对内容做在线审核（通过/驳回+意见），**审核结果驱动任务完成门禁**。 |
| （内嵌）CONTENT-003/004 AI 脚本·成片 | 内容管理内 | 在内容页内用 AI 生成视频脚本与短视频成片，提升内容产能。 |
| （内嵌）CONTENT-109/110 方案同步 | 内容管理内 | 保存内容后经 WebAPI 同步 Football 方案；删除草稿时同步下架/删除并进补偿队列。 |

- **业务流程**：工作任务登记（赛事/计划/直播）→（矩阵）**确认出任务** →（我的任务）**执行** → 全页填写并关联内容 → **提交审核** →（内容审核）**通过** → 任务**完成** → WebAPI 同步 Football 方案 → 发布归档 → 采集效果回收。
- **业务价值**：把内容生产从「人盯人」变成 **SOP 驱动的流水线**：计划→任务→执行→审核→发布→效果 全链可追溯；免审 SOP 缩短模板迭代；审核门禁保证**未经审核的内容不能发布**；Football 方案同步让内容与交易侧打通。

| COLLECT-002 采集日志 | 采集日志 | 用类型化结果追溯采集过程（含 PARTIAL 部分成功），定位失败原因。 |

- **业务价值**：数据是分析决策的**唯一上游**；统一阈值避免「一处改多处忘」；凭证铁律（ADR-047）把平台 Cookie 收敛到账号详情采集 Tab，**降低账号安全风险**。

#### 模块 18 作品监测（MON）+ 内部分析 + 竞品分析

| 功能点 | 子菜单 | 一句话·可实现的业务需求 |
|--------|--------|--------------------------|
| 作品监测 | 作品监测 | 仅按「IP 主题 / 行业」维度看内外部作品监测（阈值只读引用采集配置）。 |
| 内部作品 / 内部账号 | 内部分析 | 看我方作品（全部/爆款/低分）与账号（全部/高粉/低粉）的**经营表现**。 |
| 竞品作品 / 竞品账号 | 竞品分析 | 看竞品作品（全部/爆款/低分）与账号（全部/高粉/低粉）的**对标表现**。 |

- **业务价值**：把「我们 vs 对手」的差距**可视化、常态化**；竞品资产库让对手情报**结构化沉淀**而非散落在人脑；监测/分析/资产三层职责清晰、API 不混用。

| MASTER-005/006 平台/个人账号 | 账号管理 | 按平台（公众号/视频号/抖音/快手/小红书）维护账号，强关联公司/实名人/手机/IP 组。 |
| ASSET-001/002 正/反向穿透 | 设备管理/资产 | 从资产反查账号、从账号反查资产，**双向穿透定位归属**。 |

- **业务流程**：公司 → 资源（手机/卡/实名人/证件）→ 平台账号绑定（强关联选择器）→ 领用（ACCT-001）→ 采集登录配置（凭证铁律：仅在账号详情采集 Tab）→ 成本录入 → 归还/流转。
- **业务价值**：把公司的账号、设备、证件做成**可盘点、可穿透、可追责的资产池**；证件到期预警与分级水印**降低合规与泄露风险**；账号全生命周期留痕让「账号在谁手里」永远是已知数。

### 域 4 · 财务

#### 模块 08b 账号财务（COST）

| 功能点 | 一句话·可实现的业务需求 |
|--------|--------------------------|
| COST-001 采购/过程成本 | 记录账号的采购成本与过程成本（一条购买 + 多条过程）。 |
| COST-002 账号/IP组/公司/人员 ROI | 用「营收（Football 订单 WebAPI）÷ 成本」算出账号、IP 组、公司、人员的 ROI。 |

- **业务流程**：录入成本 → 拉取 Football 订单营收（按 authorId）→ 落 IMS 日汇总 → 出 ROI；Football 不可用时营收显示「数据延迟」**不写脏**。
- **业务价值**：让「这个账号值不值得养」有**数字答案**；ROI 是资源再分配的决策依据。

#### 模块 11 场次财务（FIN）

| 功能点 | 一句话·可实现的业务需求 |
|--------|--------------------------|
| FIN-001～005 成本/利润核算 | 按场次核算成本、利润与分成，与账号 ROI **分菜单标注**（场次 vs 账号）。 |
| DC-002 利润反查 | 从利润出发反查其构成的场次与成本明细，定位利润异常。 |

- **业务流程**：下播录入 GMV → 48h 内录入场次成本 → 计算利润与分成 → 利润反查下钻 → 报表标注「场次」口径。
- **业务价值**：直播是**按场计费**的生意，FIN 让每一场的盈亏可结算、可反查；与 COST 分账避免口径混淆（BR-302）。

| 功能点 | 一句话·可实现的业务需求 |
|--------|--------------------------|

## 4. 业务价值总账

### 4.1 按角色看价值

| 角色 | 在 IMS 中获得的直接价值 |
|------|--------------------------|
| **管理层** | 一屏可溯：人岗权、资产账号、场次、成本利润、人效；决策层 BI/穿透/预警支撑「看数—查数—定责」 |
| **运营（IP 组/内容）** | 任务—内容—审核—发布闭环在 IMS 内完成，SOP 流水线提效，效果回收闭环 |
| **内容/审核** | 模板免审加快迭代；内容门禁保证合规；AI 脚本/成片提升产能 |
| **财务** | 账号 ROI 与场次利润**双口径分账**，成本利润可结算、可反查 |
| **数据/分析** | 指标口径统一、报表自助搭建、查询模板可发布复用、穿透一次到位 |
| **系统/HR** | 钉钉同步 + 角色唯一载体 + 租户隔离，权限治理有唯一权威源 |

### 4.2 按能力看价值（可量化锚点）

| 能力 | 价值锚点 |
|------|----------|
| SSO / 权限同步 | SSO 成功率 > 99.5%，权限同步 < 5 分钟 |
| 穿透查询 | P95 < 3 秒（BR-205，>3000ms 橙色提示） |
| 报表 | 10 万行 < 30 秒或异步导出 |
| 采集 | 采集及时率 > 95% |
| 内容 | 未审核内容不可发布；删除草稿同步下架 + 补偿队列 |
| 财务 | 营收「数据延迟」不写脏（Football 不可用时降级不污染） |
| 合规 | 证件到期 T-30/T-7/T-0 预警 + 分级水印 + AES-256 敏感加密 |

### 4.3 一句话价值收口

> **IMS 的价值 = 把「运营全链路」从多系统拼接到一个后台，让每一个动作都可归因、每一份数据都可追溯、每一笔成本都可结算、每一项能力都可复用。**
