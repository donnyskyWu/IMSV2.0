## 0. 处置总纲

### 0.1 四种处置模式（先分型，再动手）

| 模式 | 含义 | 适用断点 | 代价 |
|------|------|----------|------|
| **M1 改变交付方式** | 断点无法"补"，只能改**怎么做交付**（改粒度/改顺序） | B1、B5 | 高（重排计划） |
| **M2 拍板落 ADR** | 缺的是**决策**而非能力；一次会议 + 一份 ADR 冻结即可解除 | B4、B3、B8 | 中（依赖决策） |
| **M3 降级设计** | 不补齐也能上，只要**显式降级**（空态/占位/延迟）且不写脏 | B2、B6、B7、B11 | 低 |
| **M4 一致性基建** | 横切规则统一在**一处**实现，避免每个模块各写一套 | B9、B10 | 中（一次性投入） |

### 0.2 四条处置底线（防线不可破）

1. **降级不写脏**：数据源不可用时，宁可显示「数据延迟 / —」，**禁止**写入猜测值（BR-307 / 营收口径）。
2. **空态不假 CRUD**：能力未就绪的页面，显示空态或 BLOCKED 说明，**禁止**用 toast 冒充可操作。
3. **fail-closed**：权限/门禁缺省即拒绝（空权限≠放行，ADR-IMS-008 G1 护栏），**禁止**缺省放行。
4. **提示不倒退**：并入域错误码保持 1500~1504 语义或映射 5xxx，前端提示不退化（BR-307）。

## 2. 逐条处置方案

### B1 · CONTENT 端到端不可整链验收（高 · M1）

**根因**：OPS 内容轨（计划→作者×赛事矩阵→出任务→执行→玩法→审核级数→Football 同步）与原 IMS 短视频轨曾叠 13 Tab，状态不互通；矩阵/执行/审核闭环在原型未串通（走查阻断 2026-09-29 §2）。**不是缺代码，是缺"可验收的最小闭环单元"**。

**处置策略**
1. **改交付粒度**：正式承认「整系统全量开写不可行」，CONTENT 按 **5 个切片**推进，每片独立 Gate：

| 切片 | 范围 | 关键产物 | Gate 判据 |
|------|------|----------|-----------|
| **S1** | SOP（100）+ 计划（102） | 页面规格 + API 契约 | 规格评审通过 + 原型闭环 |
| **S2** | 工作任务登记（104/105）+ 矩阵确认出任务 | 作者×赛事矩阵 UI + 出任务接口 | 矩阵可操作、能生成任务 |
| **S3** | 我的任务（103）+ 内容主工作区（106 玩法/AI/排版） | 执行→内容抽屉→玩法 | 任务可执行、内容可存 |
| **S4** | 内容审核（005 级数可配）+ 发布归档（006） | **审核门禁 G1** | 未审内容不可发布（可独立验收） |
| **S5** | Football 方案同步（109/110）+ 补偿 | WebAPI + 补偿队列 | 同步成功 / 失败进队列 |

2. **规格先行**：按 **ADR-IMS-003** 以 OPS `UX-M2` 为 SSOT 修订《CONTENT-OPS并入补充-页面规格 / API契约》，映射 `P-M2-*`，**不发明未写控件**。
3. **门禁可先落**：S4 的 **G1（内容审核门禁）** 不依赖 Football，可独立先行验收；这是整链最高频阻断点，优先解除。

**前置条件**：S1 规格评审通过。
**验收标准**：每片 Slice Gate 全绿（规格 + 原型 + 契约 + 联调四项）；**不以整链验收为 Gate**。
**兜底**：未开片的模块在导航中可见但页面标「建设中」，不接业务入口。

### B2 · 直播 metrics 无 OpenAPI（中 · **已解决**）

**根因**：Football 侧无 room 级 metrics REST，原计划依赖 OpenAPI。

**处置（已落地 · v2.6.34）**：**直接使用直播数据本身的数据结构** —— 单场「直播数据」Tab 全部取 **`live_room` DB 只读**（ADR-IMS-001 共用业务库）：
- **房间**：`id`、`author_id`（昵称 / 头像）、外部直播间号 `live_id`、名称、封面、**状态（1 未开始 / 2 直播中 / 3 已结束 / 4 过期 / 5 暂停）**、横竖屏、公开 / 付费 / 加密、开始与结束时间、观看 / 回放 / 推流地址；
- **计数**：预约人数、点赞数、**观看人数 `viewer_count`**；
- **GMV / 峰值在线 / 涨粉 / 退款 / 投放成本** 仍由 **下播录入（LIVE-002）** 承载，不在本 Tab 显示「—」占位。

**落地范围**：`IMS完整产品需求文档.md`（§5.4 / §3A LIVE）、`LIVE-直播管理-API契约.md`（`LiveFootballRoomBasicVO` 扩字段、`metricsOutOfScope` → `metricsByManualEntry`）、`LIVE-直播管理-页面规格.md`、`FB-Football-WebAPI适配.md`、原型「直播数据」Tab。

**验收标准**：Tab 房间与计数无「—」占位；GMV 由下播录入进 FIN；无假数据。
**兜底**：Football 若后续提供 OpenAPI，仅作补充，不改变本 SSOT。

### B3 · 部分并入域缺 DTO（中 · M2 · 已定范式）

**根因**：部分并入域（如 REPORT 作者→账号级联）曾担心缺专用聚合接口，接口形态未定。

**处置（2026-10-05 决议：统一 IP 组级联范式）**
1. **已解**：REPORT 的「作者→账号」级联**已于 2026-10-01 冻结**为统一范式——选作者 → 读作者 `ipGroupId` → `GET /admin-api/ims/ip-group/{groupId}/accounts` 过滤 `AccountSelect`；并**明令禁止**新增 `GET …/authors/{id}/accounts` 聚合接口（见 `REPORT-数据上报-页面规格.md` §级联 / `REPORT-数据上报-API契约.md` §2.2.1）。共池失败返回 **1127**。
2. **全系统统一范式**：凡「实体 → 账号」级联（REPORT / ACCT / IPG 等）一律**复用 IP 组账号池端点**，不再为每种实体新造专用聚合 API。
3. **残余排查**：逐域审查是否仍有同类级联缺口；未冻结处前端可级联过滤兜底（拉全量 → 前端按 ID 过滤），但必须标 `TODO(DTO-BLOCKED)` 并登记，切片末统一替换。

**验收标准**：级联可用；每个级联场景在契约中有 canonical 定义且**不重复造接口**。
**兜底**：兜底实现标 `TODO(DTO-BLOCKED)`，切片末统一替换。

> **订正（2026-10-05）**：本节原引「冻结 `GET /report/authors/{id}/accounts`」与 REPORT 契约（明令禁止该接口）冲突，依用户决议订正为「**统一 IP 组级联范式**」。

### B5 · IR-03 停 OPS，禁止 OPS HTTP（高 · M1）

**根因**：架构铁律——IMS 业务数据源 = 现网 OPS 库（**同库非同服务**），验收后停 OPS。若实现期残留 OPS HTTP 依赖，切流即全断。

**处置策略**
1. **架构约束**：并入域（内容/采集/指标/监测）全部**直连 `oa_*`**，**禁止** OPS HTTP Client。
2. **CI 硬门禁**：静态扫描代码中不得出现 OPS host / `ops.` base-url（白名单仅 Football WebAPI）。
3. **切流纪律**：验收前 OPS 继续跑（双跑）；**验收通过 → 停 OPS**；禁止长期双写。
4. **数据一致性**：同库直连天然一致，无需同步作业。

**验收标准**：CI 扫描零 OPS host；切流演练通过（关 OPS 后 IMS 全功能可用）。
**兜底**：若发现遗漏依赖，登记为**切流前必修项**，不得带入验收。

### B6 · 知识语义检索（中 · **已决 · 整体移除**）

**根因与决策**：用户明确「**去掉语义检索对应的功能，保持现有的范围**」——语义检索**不再作为"延后"**，而是**移出范围**。

**处置（已落地 · v2.6.34）**
1. **移除**：`KNOW-003` 知识检索（含 `knowledge.search` / `knowledge.get`）、`KB-001` RAGFlow 底座（含 `ragflow-check` / `ragflow-health`、底座健康卡 / 巡检）、`experts.assemble` 的 `knowledge_context` 字段、系统错误码 **5007 / 5008**（号位作废）。
2. **保留范围**：知识库 = 库 / 分类 / 条目元数据 / 入库审批 / 授权 / 系统资料转入 / 手动上传（文件·URL·文本）；`KbProvider` **只有 `LOCAL`**（IMS 本地对象存储）；`McpToolName` **固定四工具**；状态机 PENDING→PUBLISHED（无 `PARSING`）。
3. **抽象保留**：`KnowledgeProvider`（KB-002）保留供未来扩展，**当前不引入任何检索底座**。

**落地范围**：`IMS完整产品需求文档.md`（§20、FR-AIR-017/020）、`全局开发规范.md`（`KbProvider` / `McpToolName` / 5007-5008 / §3.2 AIR 段）、`错误码映射表-附录.md`、AIR 页面规格 / API 契约、用户故事 F 分册、delivery AIR 包、原型 AIR 页。

**验收标准**：规格中不再出现"检索期恢复"；知识库文件管理可用；组装接口不含 `knowledge_context`。

### B7 · CORP 设备分页 API 部分 BLOCKED（低 · M3）

**处置策略**：办公/直播设备分页 API 未就绪期间，页面**显示空态 + BLOCKED 说明**，**禁止**假 CRUD toast；关联入口（流程② `MASTER-003/004 → LIVE`）显示「暂不可选」。
**补充（用户要求）**：**页面必须保留分页组件**——即便当前为空态，页脚「共 N 条 · 每页 X 条 · 页码」照常渲染（接口就绪后直接生效）。
**验收标准**：无假成功提示；分页组件在位；数据就绪后接口即插即用。

### B8 · PERF 状态机 BLOCKED（中 · M2 · ADR 已冻结）

**根因**：OPS 单条 `oa_perf_record.status`、IMS 周期 `ims_perf_result.resultStatus`、现网执行页 Tag **三套来源**。

**处置策略**（**ADR-IMS-005 已冻结，照做即可**）
1. P2 执行考核：API 响应 `status` = **大写 canonical**（`dict_perf_status`），前端 Tag 按 §3 映射（`calculated ← CALCULATED|REVIEWED`）。
2. P3 考核结果：OPS 结果走 7 态 `DictLabel`；IMS 批量走 `resultStatus` 四态独立 Tag。
3. **禁止**：`calculated→PENDING_APPROVE`、`confirmed→PUBLISHED`、合并 `record/confirm` 与 `calc/{period}/approve`。
4. 落地 ADR-IMS-005 §4 实现检查清单（4 项勾选）。

**验收标准**：PRD 时序图与前端 Tag 一致；状态机非法转移报错。

### B9 · 租户 + 四级数据范围横切（中 · M4）

**处置策略**
1. **权限中间件统一实现**：全业务表 `tenant_id` 行级隔离 + BR-305 四级数据范围（全部/部门/IP 组/本人）在**一处**生效，模块不各写。
2. **发布/分享双重过滤**：`创建者范围 ∩ 查看者范围`（BR-212），防越权分享。
3. IP 组作为数据权限轴与钉钉部门映射后仍生效（BR-305）。

**验收标准**：跨租户返回 1504；同一报表下不同角色看到不同行数。
**兜底**：单测覆盖"他人链接访问被过滤"用例。

### B10 · 版本-引用影响面（低 · M4）

**处置策略**：`AUTH-003` 岗位供给规则升级**生成新版本、已套用用户不自动变更**（POS-R2）；`17b` 已发布报表走**版本快照**，报表下线后菜单自动置灰；全量审计。
**验收标准**：升级不回溯影响已实例化对象；下线报表菜单同步置灰。

---

### B11 · WebAPI 补偿链（低 · M3）

**处置策略**（BR-303）：内容保存成功即返回成功，**同步异步化**；失败进**补偿队列**，幂等键 + 重试≤3 + 全量审计；`CONTENT-110` 删草稿须调 Football 删除/下架，已上架/有订单则下架并审计。
**验收标准**：Football 宕机时内容仍可保存，队列可重放且不重复上架。

## 6. 一页纸执行摘要

1. **两条 P0 立决**：CONTENT 拆切片交付（B1）；立"禁 OPS HTTP"硬门禁（B5）。
2. **三类拍板**：走查 #8 收口 ADR（B4）；级联 DTO 清单（B3）；PERF 按 ADR-IMS-005（B8，已冻结）。
3. **两处降级**：设备空态（B7）、WebAPI 补偿（B11）——**降级但不断链、不写脏、不假 CRUD**；**B2 已用 `live_room` 只读转正、B6 已整体移除**，不再降级。
4. **一处基建**：租户 + 四级数据范围在权限中间件统一实现（B9）。
5. **一条全局规范**：**所有管理 / 列表页必须有分页组件**（《全局开发规范》§2.5，原型共用 `tbl()` 统一注入）。

> **一句话**：B1/B5 是"改交付方式"，B3/B4/B8 是"拍板落 ADR"，B7/B11 是"显式降级"，B9/B10 是"统一基建"；**B2 改用 `live_room` 直接解决、B6 整体移除**——**没有一个是靠"再写点代码"能解的**。
