## 2. 理由

完整原型把 OPS 能力收成「少 Tab + toast」，与现网可运营作业不是同一产品。按该原型实现会导致：指标无法出表、内容无法从工作任务走到审核、抖音/快手无法完成凭证绑定与任务调度。

## 3. 实现约束

- 切片前必须 `@` 对应 OPS UX/PRD/API；IMS `BI0`/`CONTENT-OPS`/`COLLECT` 规格与 OPS **冲突时停写代码**，先改 IMS 规格对齐 OPS（不得用行业惯例补控件）。
- COLLECT 页面规格已对齐 ADR-047（2026-10-01）：Cookie/bind 在 **账号采集 Tab**；P2a 竞品账号配置为 **外部 Channel-D only**（见《COLLECT-数据采集-页面规格.md》）。
- 完整原型未改完前，**不得**宣称 OPS 并入域「原型已可走查验收」。

## 4. 下一步（文档，非本 ADR 发明 API）

1. 修订 IMS `BI0`/`CONTENT-OPS`/`COLLECT`/`ACCT` 页面规格，逐页映射 OPS `P-M*`。  
2. 按 OPS 闭环重做完整原型中 `bi0` / `content*` 子菜单 / `collect` / 账号采集 Tab；`content` 13 Tab 已拆除；`ipg` 主路径已对齐，补 **账号绑定 Tab** 后与 UX §3.1 五 Tab 完全一致。  
3. 再开 AUTH 之后的并入域切片。
