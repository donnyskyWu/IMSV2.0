### 1.3 测试优先级分级（P0/P1/P2）

- **P0（必须全过，一票否决）**：66 条 BR 全覆盖；钉钉 SSO 与事件同步；场次 ID 生成器；账号-资产-实名人-场次-成本-利润数据链路；AIR 安全链路（Key 验签/离职 403/机密拦截 100%/审计）；FIN 分成引擎精度；BR-015 离职闭环。
- **P1（必须达标）**：398 端点接口全量；47 枚举值域与状态机流转；错误码段位正确性；性能基线（4.1 表全部指标）；数据权限（数据可见域）。
- **P2（尽力覆盖）**：UI 交互细节、异常网络重试、导出体验、报表美化、兼容性矩阵边缘项。

## 2. 测试策略：四层金字塔 + IMS 特化

### 2.1 分层模型

```
        ▲ 系统测试（ST）      少量 · 端到端 · 非功能
       ▲▲ E2E（ET）           跨模块业务闭环场景（12 主线场景）
      ▲▲▲ 集成测试（IT）      模块间接口 + 外部系统（钉钉/ComfyUI/服务端文件目录/Redis）
     ▲▲▲▲ 接口测试（AT）      398 端点全量（自动化）
    ▲▲▲▲▲ 单元测试（UT）      BR 分支 + 引擎计算 + 枚举错误码（自动化，占比最大）
```

- **自动化目标**：单元 ≥ 80% 行覆盖（P0 Service ≥ 90% 分支覆盖）；接口测试 100% 端点覆盖（正向 + 至少 1 条错误码反向）；E2E 12 主线场景全部自动化。
- **分层准入**：下层不达标不进入上层冒烟——单层失败即阻断提测。

### 2.2 IMS 特化测试策略

1. **数据链路主线优先**：「账号-资产-实名人-场次-成本-利润」六层数据模型是 V1 落地的命脉（关键约束 1/2/3），所有测试设计围绕此主轴展开；V1 收口必须冻结场次数据口径。
2. **外部依赖桩分级**：
   - 钉钉：单元层全 Mock；集成层用钉钉沙箱/测试企业；E2E 用真实测试企业（2~3 个测试账号含离职流程专用号）。
   - ComfyUI/GPU 池：集成层用 Docker Compose 测试栈；性能测试用压测数据集；不依赖外部 SaaS。
   - Redis/本地文件目录：测试环境全真部署，验证降级路径（Redis 不可用→DB 行锁降级 V1-E4）。
3. **安全链路专项**（AIR + CERT + 权限）：独立安全测试组，覆盖机密拦截、水印、脱敏、审计、动态鉴权 60s 缓存时效。
4. **批次化交付对齐**：AIR-P0（第 19~20 周）先行验收、AIR-P1 补齐验收；FIN 先行批次（第 28~33 周）单列验收门，之后再验 12/19 依赖项。
5. **数仓双时态**：V3 DC 的 ODS/聚合层同步延迟 > 1h 告警（V3-A2），集成测试含 15 分钟增量 + binlog 两条通道验证。

### 2.3 测试阶段与节奏（按周次对齐交付计划）

| 阶段 | 周次 | 内容 | 准出 |
|------|------|------|------|
| V1 单测/接口 | 第 4~13 周滚动 | 随开发迭代，每模块 API 契约冻结即写用例 | 覆盖率达标 |
| V1 集成/E2E/系统 | 第 12~14 周 | 六模块联调 + 离职闭环 + 场次链路 + 性能初压 | 冒烟 100% 过 |
| V2（含 2.2 批次） | 第 16~27 周 | AIR-P0 第 19~20 周专项验收；V2.3 后全模块回归 | 同上 |
| V3 先行 FIN | 第 28~33 周 | FIN 验收单列门（分成引擎精度、结账锁定） | FIN 专项全过 |
| V3 全量 | 第 33~42 周 | DC/BI/EFF + BR-204/205 性能压测 + 全量回归 | 全部准出 |

## 3. 环境矩阵

| 环境 | 用途 | 数据 | 外部依赖 |
|------|------|------|----------|
| 本地开发环境 | 单元测试 | Mock 全量（钉钉/ComfyUI/Redis 全 Mock） | 无真实外联 |
| 集成测试环境（CI） | 接口+集成 | 契约化种子数据（47 表基线数据集 + 场次 ID 冒烟数据） | Docker Compose 测试栈（MySQL/Redis + 文件目录卷）+ 钉钉测试企业 |
| E2E 测试环境 | 端到端场景 | 剧本化数据（含离职测试账号、机密知识样例、分成规则样例） | 钉钉真实测试企业 + GPU 节点（显存 ≥ 48GB 共用池） |
| 预发环境 | 系统测试/性能/验收 | 生产同构（脱敏） | 全真实依赖 + 压测数据集（10 万行级报表数据集、50 万场次穿透数据集） |
| 生产环境 | 灰度 + 线上监控 | 生产数据 | 生产依赖（只读验证 + 监控） |

**环境管理规则**：
- 三套数据集统一版本化管理（Git + Flyway/Liquibase 种子脚本），测试环境每日重建。
- 压测只在预发执行；每日自动压测（V3-C3：预置 10 条典型穿透用例，P95 超标自动告警）接入 13 预警中心。
- GPU 算力池测试约束：ComfyUI 固定显存预留 + 向量化独立队列优先级验证（V2-F2）必须在 E2E 环境实测。

## 4. 准入准出标准

### 4.1 提测准入（Development → Test）

1. 代码合并主干、CI 绿灯（编译 + 静态检查 + 单元测试全过）。
2. 单元测试：新增/变更代码行覆盖 ≥ 80%，P0 Service（权限同步/分成计算/场次 ID/风控评分/机密拦截）分支覆盖 ≥ 90%。
3. 接口测试：本模块 API 契约声明端点正向用例 100% 编写并执行通过。
4. 自测报告（含变更影响面清单 + 已知问题清单）。
5. AIR 批次（文件管理期）：P0 验收含 IMS 服务端文件目录自验记录；原 RAGFlow 部署与 5007/5008 健康监控已于 v2.6.34 移出范围。

### 4.2 测试准出（Test → Release）

1. 用例执行率 100%；P0 用例通过率 100%；P1 通过率 ≥ 98% 且遗留项均有规避方案；P2 遗留不阻塞。
2. 缺陷收敛：P0 缺陷 0 遗留、P1 缺陷 ≤ 2 且有排期、致命/严重缺陷修复后回归通过。
3. BR 覆盖：66 条 BR 100% 有对应用例且执行通过（BR 映射矩阵见各层 Checklist 附录）。
4. 性能验收：当期基线指标全过（V1/V2/V3 4.1 表 + BR-204/205 + AIR 指标）。
5. 无契约漂移：自动化契约校验（端点/错误码/枚举与文档一致性扫描）零差异。
6. 分期收口专项：V1 收口冻结场次数据口径检查表；FIN 先行批次分成计算抽样对账（人工财务复算 ≥ 3 组样例误差为零）。

### 4.3 上线准出

1. 预发全量回归通过 + 生产灰度验证（核心冒烟 20 条）。
2. 回滚方案演练一次通过（含 DB 回滚脚本）。
3. 监控告警接入验证（4.3 基线三级告警通道真实触达）。

## 5. 缺陷分级与流程

| 级别 | 定义 | 响应/修复 SLA |
|------|------|---------------|
| P0 致命 | BR 被违反、数据错误/丢失、安全漏洞（机密外泄/越权）、核心链路不可用、分成算错 | 立即响应，24h 内修复 |
| P1 严重 | 功能不可用但链路可绕行、性能未达标、错误码/状态机错误 | 24h 响应，3 天内修复 |
| P2 一般 | 交互缺陷、非核心字段显示、校验提示不友好 | 迭代内修复 |
| P3 轻微 | 文案/样式 | 排期修复 |

流程：提交（复现步骤+环境+截图/日志）→ 定级 → 修复 → 回归 → 关闭。缺陷须关联功能编号（如 ACCT-002）与 BR 编号（如 BR-015），供 BR 覆盖矩阵自动统计。

### 6.2 主要测试风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 钉钉测试企业与生产行为差异（限流策略/事件顺序） | 同步类缺陷漏测 | 集成层增加事件乱序/重复/延迟注入用例；预发用真实流量回放 |
