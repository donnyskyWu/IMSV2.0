## 1. 逻辑一致性审查

### 1.1 一致的部分（已对齐）

| 维度 | 事实（含出处） |
|------|----------------|
| **统一元模型** | 方案 §3.4 分层图：`COLLECT P4m / DWS 宽表 → FLAT/DRILL/TraceTemplate → QueryPlan → 统一结果壳`；QT §0.1、API 契约 §2.1、BI 附录 A-7、DC 附录 A-2 均引用同一分层。 |
| **COLLECT 元数据 SSOT** | QT §0.1（只读 `entity/{code}/fields`）· BI0 P4 · DC 三方一致，1261 未映射规则统一。 |
| **服务端权限** | QT §3.2（artifact 级 perm）+ BI BR-212（行级双重过滤）+ DC 脱敏（R7/R9 null→"—"），三者均「服务端校验、前端不判权限」。 |
| **8 个分析叶** | QT §0.1、BI §0.1、PRD §17 表三处 IA 均为：查询工具 · 自定义查询 · 预览与下钻 · 穿透查询 · 组织人效，一致。 |
| **错误码不撞** | QT 用 1261/1263/1264/1265；BI P2 用 1194/1195/1008；DC 用 1181/1182。互不冲突。 |
| **结果壳统一** | QT §2.4 `QueryResult` ≈ BI `BiReportQueryResp` ≈ DC `DcTraceGraphResp`，均含 `columns/rows/queryCostMs`。 |

### 1.2 不一致的部分（须收敛）

| # | 不一致点 | 双方证据 | 严重度 |
|---|----------|----------|--------|
| **C1** | **DRILL 与 BI P2 下钻语义双轨** | 方案 §5.2 明确 DRILL=模板级多层探索（DrillPlan），BI P2=已发布报表维度下钻（ReportPlan），**结论是不合并 L3**；但两者都提供「维度逐层下钻 + 面包屑」，**用户可见口径重叠**，且 QT §0.1 未写明「若用户想要报表式下钻应去 BI P2」。 | 文档一致性 |
| **C2** | **TRACE 运行时双通道未收敛** | QT §3.2 编排表：TRACE **服务端 for 循环一次 run**；而 QT **API 契约 §2.2 仍写**「前端逐层下钻仍为重复调用 `POST /dc/trace/query`」。同文件内两处口径冲突（B2 更新了 §3.2，但 §2.2 未同步）。 | 文档一致性 |
| **C3** | **"绕过 DC" 措辞** | 方案 §1-4 一句话建议写「P0 仍走 DC-001」；QT API 契约 §3.2 写「QT TRACE run **在服务端代行**」——与 §3.3 「P0 TRACE 走 DC」措辞不一致，易误读为另建通道。 | 文档一致性 |

> **C2 补充**：这是三处里最实质的一条。若按 §2.2 落地，会退化为「前端多步 POST + 前端轮询」，违背 B2 拍板的「同步一次 run」；若按 §3.2，§2.2 的「重复调用」描述即过时。

## 2. 功能完整性审查

### 2.1 完整的部分

- **IA/导航**：三 L3 均有路由、权限码建议、分期表（QT §6 / BI P2 / DC §0.1）。
- **交互细则**：QT U1–U10、BI P2 §4 核心操作、DC P1 §4 核心操作均已写全（含面包屑、chip 下钻、末层禁用）。
- **BR 覆盖**：三方均有 §9 BR 落点总表（QT 未单列，BI BIQ-R1~R3，DC BR-205/209/210/DC-T-R1~R4）。
- **TRACE/穿透配置 UI**：QT 原型已实现 `pathSteps[]` 配置表（实体▾ + 关联边▾ + 下一层只读 + 增删层），符合 §3「配置载荷」。
- **DRILL 配置 UI**：QT 原型已实现 `levels[]` 配置表（实体▾ + Join 至下层▾ + 关联键▾ + 展示列 chip + ≤5 层约束 + 根层过滤）。

### 2.2 不完整的部分（功能缺口）

| # | 缺口 | 现状证据 | 严重度 |
|---|------|----------|--------|
| **D1** | **QT DRILL 多层执行的载体未 grounding** | API 契约 §3.2 只写「调用 **与 M6 同形的实体查询执行**（COLLECT 元数据 + BI custom-query 执行链）」，**未给出 endpoint**。DRILL 需要「多层 JOIN + 层级参数绑定」，而现网 `metricSchema.ts` 仅 **单层**（方案 §4.2 已承认「DRILL 多层 JOIN + 参数传递 **未实现**」）。→ DRILL 模板**无法在 P0 真正 run**。 | **P0 · 执行** |
| **D2** | **DC `DcTraceQueryReq` 不含 `pathSteps`** | DC 契约 §3 请求体 = `{entryType, entryId, mode, pageNo, pageSize, dateRange}`，**无** `pathSteps`。跨层穿透只能靠「前端逐节点重调」，与「一次 run 服务端 for 循环」冲突（呼应 C2）。→ **跨层穿透缺数据通路**。 | **P0 · 执行** |
| **D3** | **QT DRILL 未定义 allowlist 维度树** | DRILL「加层」若自由选任意实体，可能配出**无意义/无逻辑的 Join 链**。QT 未定义「允许的下钻维度链」（BI 有预定义：平台→账号→场次；部门→团队→人；年→月→日）。 | P1 · 数据 |
| **D4** | **QT TRACE 用户可配链 vs DC 固定 entry** | 方案 Q3 标 **BLOCKED · P3**。当前 TRACE「可配 pathSteps」可能是**原型先行、规格未授权**——P0 实际只允许 seed 只读链。 | P3 · 已登记 |
| **D5** | **TRACE `queryCostMs` 聚合口径未定义** | 当服务端一次 run 逐步 DC trace，QT §3.2 写「聚合 `queryCostMs`（**各步相加**）」，但 DC `queryCostMs` 是单次查询耗时；**相加**会让 TRACE 超 **BR-205 P95<3s** 失真。 | P1 · 性能 |
| **D6** | **跨模块路由前缀不统一** | BI P2 路由 `/bi/report/view/{id}`、DC 路由 `/dc/trace`（均**无** `/ims` 前缀）；QT 路由 `/ims/analysis/query-tool`（**有** `/ims` 前缀）。网关铁律 IR-01 = `/admin-api/ims/`，前端路由宜统一 `/ims/...`。 | P1 · 一致性 |

> **D5 补充**：QT §5 U5 写「TRACE >3000ms 橙色（BR-205）」，但 BR-205 是 **P95** 指标而非**单次**阈值，且 DC 契约 §3.2 又是「各步相加」。三处口径需统一为「取最后一步单次耗时」或「定义 TRACE 专属 SLA」。

## 3. 能否用查询工具配置出下钻与穿透？

### 3.1 结论：**能配出**（配置能力已具备）

| 目标能力 | QT 承载模式 | 配置路径（用户操作） | 载荷 |
|----------|-------------|----------------------|------|
| **下钻查询** | **DRILL 模式** | 查询配置 Tab → 选模式 DRILL → 选根实体（COLLECT 已映射）→ L1 选展示列 → 「+ 添加层级」→ 每层选实体 + Join 至下层 + 关联键 → 保存草稿/发布 → 执行 | `DrillTemplate.levels[]`（`levelIndex / label / dataSource / displayFields / drillToNext{leftKey,rightKey}`） |
| **穿透查询** | **TRACE 模式** | 查询配置 Tab → 选模式 TRACE → `pathSteps[]` 表逐层配「实体 + 关联边→下一层」→ 选入口类型（6 种）+ 关键词 → 选根层源头 → 执行 | `TraceTemplate.pathSteps[]`（`entity` + `relationToNext`）+ `entryProfile` |

**原型已实现**（`IMS-完整系统-UI原型.html` `.page-query-tool`）：
- DRILL：L1~Ln 层级配置表（实体▾ + Join 至下一层▾ + 关联键▾ + 展示列 chip），「+ 添加层级」按钮，≤5 层约束，「已配置 N/5 层」提示，点击 L 标签切换结果预览层。
- TRACE：`pathSteps[]` 配置表（实体▾ + 关联边▾ + 下一层只读 + 移除），「+ 添加穿透层」，路径预览 chip 链，入口类型 pills，源头选择表，「下一层」逐层穿透按钮，分栏/关系图/明细表三视图。

### 3.2 但「能配」≠「能跑」——落地前必须补齐

配置能力（L1 模板层）**已经完备且可演示**；执行能力（L2 运行时）存在上述 **D1/D2** 两个 P0 硬缺口：

```
用户配置（已具备）          →    执行（订正后口径）
─────────────────────────────────────────────────────────
DRILL  levels[]             →    ✅ P0 仅配置+规格，run 依赖 P2 多层 JOIN（降级单层 stub）
TRACE  pathSteps[]          →    ✅ QT 服务端一次 run 内 for 循环代行 DC Service（DC 不扩参）
                                 ✅ 前端只调一次 run，不逐步 POST、不轮询
```
