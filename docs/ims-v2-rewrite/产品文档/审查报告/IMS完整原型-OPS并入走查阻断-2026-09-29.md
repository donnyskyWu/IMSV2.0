# IMS 完整原型 vs OPS：并入域走查阻断（2026-09-29）

> 触发：产品确认完整 UI 原型中 OPS 并入功能「差很多、无法完整操作和闭环」；特别点名 **指标报表、内容生产、账号采集配置 + 采集任务**。  
> 结论：**属实。** 并入域交互 SSOT 见 [ADR-IMS-003](../产品规划/ADR-IMS-003-OPS并入交互以OPS-UX为准.md)。  
> 原型文件：`UI原型/IMS-完整系统-UI原型.html`

完整 PRD 要求 M2/M6/M8/M10 **功能并入且可运营**；原型把它们收成示意 Tab + `toast`，**不能**作为实现蓝本。

## 0. 总判

| 模块 | 相对 OPS | 原型能否走通作业闭环 | 开发前 |
|------|----------|----------------------|--------|
| 17a 指标报表 | 信息架构压缩 + 8 张报表名错误 + 无报表页 | **否** | 按 UX-M6 重做规格与原型 |
| 15 内容生产 | OPS 轨与原 IMS 短视频轨叠 13 Tab，状态不互通 | **否** | 默认演示 OPS 主路径；矩阵/执行/玩法/审核串起来 |
| 16+08 采集 | 恢复已废弃的「内部配置填 Cookie」；任务无 cron/日志/bind | **否（不可行）** | 凭证回账号采集 Tab（ADR-047）；任务对齐 UX-M10 |

原 LIVE/领用等 IMS 自建页不在本次指控范围。

## 1. 指标报表（OPS M6 vs 原型 `bi0`）

OPS 可操作页（`UX-M6`）：指标管理（含 MetricBuilder + **预览**）、指标分析、报表中心 + **8 张统一布局报表**（IP 组/平台/日期/图/表/**导出**）、漏斗、财务概览、自定义查询（预览→保存→发布→执行）、数据大屏全屏 + **大屏配置**。

原型 `bi0` 仅 5 Tab：

- **指标**：2 行只读表，无新建/预览。
- **8 张标准报表**：卡片名是「账号 ROI、IP 组产出、内容漏斗…」，**不是** OPS 的统一账号视图 / 状态监控 / 短视频产出 / 直播时长 / 成本分摊 / ROI / IP 团队 / 异常预警；点击只有 toast，**没有报表页**。
- **自定义查询**：列表 + 执行 toast，无 QueryBuilder、无结果区、无「我的查询」、无发布。
- **数据大屏**：内嵌 KPI 卡，非全屏、无配置页。
- **指标分析 / 漏斗 / 财务概览 / 大屏配置**：不在 `bi0`。

IMS `BI0` 页面规格本身也只有目录级几行，**不够开发**。V3 模块 `bi`（下钻订阅）**不能替代** M6。

## 2. 内容生产（OPS M2 vs 原型 `content`）

OPS 主路径：计划列表（P-M2-011）→ **作者×赛事矩阵** 登记 → 确认生成全节点任务 → **我的任务/执行** → 内容抽屉（amphipoda **玩法 Tab** + AI + **排版**）→ **提交审核** → 可配置一/二级审核 → 任务完成门禁 → Football 同步。

原型问题：

| OPS 能力 | 原型 |
|----------|------|
| 工作任务矩阵、作者、多选赛程、合并执行组 | 2 行列表；登记赛事为文本；确认只改状态 |
| 任务执行、「进入内容创作」带 taskId | 「任务」Tab 只读，无执行 |
| 玩法区（竞足/传足/北单）+ 确定玩法 | 内容抽屉一个 select |
| 提审 + L1/L2 | 「在线审核」绑短视频三维度，与内容库 ID 不通 |
| AI 排版入口 | 排版模板卡片 toast；编辑器无入口 |
| 计划启动生成任务 | 只读 + toast |

另：原 CONTENT 选题→ComfyUI→发布与 OPS 内容库 **不是同一条记录**，评审会被 13 个 Tab 误导。

## 3. 采集配置与任务（为何「不可行」）

现网 OPS（ADR-047 / 052 / 061）：

1. **抖音/快手 Cookie、扫码、Collector bind** 在 **账号详情「采集」Tab**（M4），不是采集模块里维护「内部配置行」。
2. **任务**在 M10：账号或统一任务成员、cron、立即执行、**采集日志**（含 PARTIAL / typeResults）；失败从日志下钻到账号改凭证。
3. **外部竞品**：配置行不嵌 Cookie；租户级凭账号（ADR-052）。
4. M8「内部采集」平台 Cookie **已退役**；内部页只应剩企微/奥创等例外。

原型 `collect`：

- 「内部配置」= 名称 + IP 组 + 账号 + Cookie（同一 `colCfg` 抽屉）。
- 账号模块详情 **没有采集 Tab**、无 bind/扫码/探活。
- 「任务/质量」= 任务号 + 范围=IP 组 + 行内重试 toast；**无 cron、无成员、无日志抽屉**。
- 外部配置仍行内凭据。

按此实现会出现：配了 Cookie 仍因 **未 bind Collector** 采不到；失败无法按账号排障；外部凭据放错层。IMS `COLLECT` 页面规格 P1 仍写「内部页平台凭据」，与 ADR-047 **冲突**，切片前必须改规格。

---

## 4. 对开发的冻结

1. **禁止**按完整原型的 `bi0` / `content` / `collect` 交互开写 Go/Vue。  
2. **必须**先对齐 OPS UX，并修订 IMS 对应页面规格（映射 `P-M*`，不发明未写控件）。  
3. 完整原型这三块未按 OPS 闭环重做前，**不得** Gate「OPS 并入可走查」。
