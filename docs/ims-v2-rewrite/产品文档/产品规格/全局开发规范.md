## 1. 字段命名强制规则

### 1.1 基本约定

| 层 | 命名风格 | 示例 |
|----|----------|------|
| TypeScript 接口 / API 请求与响应 / 前端组件 state、props | **camelCase** | `sessionCode`、`ipGroupId`、`verifiedPersonId` |
| 数据库列（MySQL） | **snake_case** | `ims_live_session.session_code` |
| 表名 | `ims_` 前缀 + snake_case | `ims_account_charge` |
| TypeScript 类型/接口/枚举名 | **PascalCase** | `LiveSessionVO`、`PlatformType` |
| 常量 | **UPPER_SNAKE_CASE** | `API_PREFIX` |
| 布尔语义字段 | `is`/`has` 前缀 camelCase | `isSupplement`、`hasVoucher` |

### 1.2 snake_case → camelCase 映射约定

- 映射是**机械式**的：下划线分段逐段首字母大写拼接，无缩写特例（`ip_group_id → ipGroupId`，**不是** `ipGroupID`；`id_card → idCard`，**不是** `IDCard`）。
- 唯一约定俗成的缩写保留：`Id`、`Url`、`No`（单号）、`Json`（仅在类型名中，如 `EventDetailJson`）。**禁止** `ID`、`URL`、`NO`、`JSON` 全大写形式出现在字段名中。
- 后端 Python 用 Pydantic 模型把 snake_case 列映射为 camelCase 接口字段（`serialization_alias`），**禁止**在接口契约中出现 snake_case 字段。
- 所有三层规格文档（全局规范/页面规格/API 契约）中的字段名一律 camelCase，与接口契约严格一致，**文档即契约**。

### 1.3 常见映射对照表（权威，禁止自行变体）

| 数据库字段（snake_case） | 接口字段（camelCase） | 所属表 |

| session_id | sessionId | ims_live_session / 各挂场次表 |

## 2. 分页参数统一规范

### 2.1 请求（分页查询接口，Query 参数）

```typescript
interface PageParam {
  pageNo: number;    // 页码，从 1 起，默认 1
  pageSize: number;  // 每页条数，默认 10，最大 100
}
```

**禁止**出现 `page`、`size`、`pageNum`、`limit`、`offset` 等变体。分页接口的其余筛选参数平铺在 Query 上（camelCase），如 `?pageNo=1&pageSize=20&platform=DYS&status=ENABLED`。

### 2.2 响应（分页包裹结构）

```typescript
interface PageResult<T> {
  list: T[];        // 当前页数据
  total: number;    // 总条数
  pageNo: number;   // 回显页码
  pageSize: number; // 回显每页条数
}
```

非分页查询返回 `T` 或 `T[]` 原样放 `data`；禁止给非分页接口套分页壳。

### 2.3 通用响应包裹（三期所有接口统一）

```typescript
interface CommonResult<T> {
  code: number;     // 0=成功，非 0=失败（见第 3 章错误码）
  msg: string;      // "success" 或错误描述
  data: T | null;   // 业务数据，失败时可为 null
}
```

前端请求封装统一拦截：`code !== 0` 抛业务异常并提示 `msg`；HTTP 层 401 跳登录、403 提示无权限。

### 2.4 列表接口风格约定

- **分页列表**：请求 `PageParam` + 筛选参数，响应 `PageResult<T>`（路径语义用 `/list` 或 `/page`，以各模块 API 契约为准）。
- **全量下拉/字典列表**（数量有限，如平台码、SOP 启用列表）：不分页，直接返回 `T[]`。
- 筛选参数值使用**权威枚举字符串**（见第 4 章），禁止传数字状态码。

### 2.5 前端分页组件（强制）

- **所有"管理 / 列表类"页面必须提供分页组件**（列表 + 总数 + 页码 + 每页条数切换），**不得**以"原型省略""数据少""示意页"为由省略。
- 分页组件与接口 `PageParam` / `PageResult` 严格对齐：`pageNo` 从 1 起，`pageSize` 默认 10，可选 10/20/50，上限 100。
- 页脚固定展示「**共 N 条 · 每页 X 条 · 页码**」；切换页码或每页条数须**回服务端重新查询**，禁止前端假分页掩盖总量。
- **例外**（须在页面规格中显式标注"不分页"）：① 抽屉 / 弹窗内的**明细子表**；② 全量下拉 / 字典列表（见 §2.4）；③ 非列表型详情页。

## 4. 权威枚举定义（三期共用）

**规则**：全部使用**字符串枚举**，禁止数字枚举/魔法数字。枚举值与 PRD 各功能点数据结构对齐；各模块 API 契约与页面规格**引用**本节，不重复定义。TypeScript 定义统一置于 `src/enums/index.ts`。

```typescript
/** 平台类型（直播/账号/发布平台，3 位码与场次 ID 平台码字典一致） */
type PlatformType = 'DYS' | 'KS' | 'WX' | 'TM' | 'JD' | 'OTA';

/** 账号状态（ims_account_ledger.status） */
type AccountStatus = 'IN_POOL' | 'IN_USE' | 'FROZEN' | 'RETURNED' | 'CANCELLED';
// IN_POOL=账号池可领用  IN_USE=在用  FROZEN=冻结（收回/离职未闭环）  RETURNED=已归还  CANCELLED=已注销

/** 资产状态（ims_asset_ledger.status，反向穿透三态扩展） */
type AssetStatus = 'IN_USE' | 'RETURNED' | 'SCRAPPED' | 'PENDING_REVIEW';
// 登记 PENDING_REVIEW → 领用 IN_USE → 使用（仍 IN_USE）→ 归还 RETURNED → 报废 SCRAPPED
// ASSET-B-R1：反向查询区分 在用/已归还/已报废

/** 账号流程类型（ims_account_flow.flow_type） */
type FlowType = 'APPLY' | 'TRANSFER' | 'RETURN';
// APPLY=领用  TRANSFER=流转（含收回）  RETURN=归还

/** 证件状态（ims_cert_archive.status，映射 PRD 5.13.2 TINYINT 0~4） */
type CertStatus = 'PENDING_REVIEW' | 'EFFECTIVE' | 'EXPIRING' | 'EXPIRED' | 'RECYCLED';
```

**枚举使用约定**：
1. 后端 Java 枚举 `@JsonValue` 序列化为字符串；DB 存储仍可用 TINYINT（后端转换），但**接口层只出字符串**。
2. 前端下拉/筛选/表格列渲染统一引用上述定义，禁止硬编码 `'0'`/`'1'`。
3. 新增枚举值时先修订本规范再使用（三期共用唯一枚举源）。

5. **并存枚举区分**：`PerfGradeLevel`（EXCELLENT/QUALIFIED/IMPROVE，85/60 分数分档）与 `PerfGrade`（S/A/B/C/D，绩效等级）为两个不同维度枚举，前者用于成绩单分档、后者用于绩效评定，禁止混用。
6. **粒度区分**：`TrainTaskStatus`（任务）vs `TrainStatus`（学习记录）；`FlowNodeStatus`（任务节点）vs `FlowInstanceStatus`（流程实例）；`AlertPushStatus`（单次投递）vs `AlertEventStatus`（事件全生命周期）。成对枚举在契约中引用时须注明粒度。
7. **域级映射备注（LIVE 风险告警）**：V1 LIVE 模块风险告警页的告警处理状态为本地枚举 `AlarmHandleStatus = 'UNHANDLED' | 'CONFIRMED' | 'HANDLED' | 'FALSE_ALARM'`，与全局 `AlertEventStatus`（OPEN/CONFIRMED/RESOLVED/FALSE_ALARM）语义映射：`UNHANDLED ≡ OPEN`、`HANDLED ≡ RESOLVED`。LIVE 契约传输层使用 AlarmHandleStatus 本值域；V2 ALERT 预警中心统一使用 `AlertEventStatus`。两域前端渲染可共用同一 StatusTag 色板。
8. **AIR 域级约定（V2.2 批次）**：①`AirAuditStatus`（技能/知识共用）不新建模块级变体；②专家包启停复用 `EnableStatus`，不定义 ExpertStatus；③`KnowledgeSecretLevel` 的拦截口径：CONFIDENTIAL 与 TOP_SECRET 在 MCP 网关层同口径处理（仅标题+摘要），但页面展示色板区分（橙/红）；④`McpToolName` 枚举值含点号，为 MCP 协议原生工具名，DB 存储时点号保留；⑤AIR 模块报错走共享技术规范 8.2 错误码段（**5007/5008 已随语义检索移出范围（v2.6.34），不启用**）。

## 5. TypeScript 编码规范

### 5.1 类型纪律

- **禁止 `any`**：不确定类型一律 `unknown` + 类型守卫（`typeof` / `in` / 自定义 `is` 断言函数）收窄；
- **禁止 magic number**：所有状态/级别/类型值一律使用第 4 章字符串枚举；
- 接口字段全部显式类型标注，公共 API 契约类型文件按模块拆分：`src/api/types/{module}.ts`；
- `strict: true`，`noImplicitAny`、`exactOptionalPropertyTypes` 开启。

### 5.2 敏感字段规范（加密传输 + 脱敏显示）

| 字段类别 | 传输 | 前端显示 | 示例脱敏格式 |
|----------|------|----------|--------------|
| 身份证号 `idCard` | 请求/响应均密文或哈希摘要；明文仅 L3 级签名 URL 场景 | 默认脱敏 | `110***********5678`（前 3 后 4） |
| 手机号 `phone` | 密文存储（AES-256），接口返回脱敏值；完整号码仅特定授权接口 | 默认脱敏 | `138****5678`（前 3 后 4） |
| Token `accessToken` / `refreshToken` | 仅登录/刷新响应出现，`HttpOnly` 优先；禁止 localStorage 明文长期存 | 不显示 | — |
| apiKey / 上传回执 | 上传文件由**服务端落盘**，仅回执 `fileKey`；**不回显**物理路径（见 §6.3） | 不显示 | — |
| 银行卡/证件原图 URL | 60 秒签名 URL，过期自动失效 | 图片预览（L2 叠水印） | — |
| 成本/利润金额（R9 数据分析师视角） | 正常返回，**接口按角色脱敏**返回 `"***"` | `***` | R9 查看成本字段时 |

**脱敏实现约定**：脱敏由**后端按角色**完成（`@Desensitize` 注解 + 权限上下文），前端不做"假脱敏"（拿到明文再遮盖 = 泄露）；前端仅负责兜底显示格式。

### 5.3 命名与结构

- API 请求类型 `{Module}{Action}Req`，响应 VO `{Module}{Entity}VO` / `{Module}{Action}Resp`（如 `LiveSessionCreateReq`、`AccountApplyVO`）；
- 时间字段一律 ISO 8601 字符串（`yyyy-MM-dd'T'HH:mm:ssXXX`），日期字段 `yyyy-MM-dd`，前端以 dayjs 统一解析，禁止时间戳数字；
- 金额字段 `number`（单位元、两位小数），前端展示统一 `toFixed(2)` + 千分位。

1. **列表 → 抽屉详情**：表格行点击/操作列按钮打开 `DetailDrawer`，不路由跳转；仅台账类大屏聚合页（LIVE-004）保留独立页面。

### 6.3 文件存储口径（本期铁律：**不上对象存储** · 2026-10-05 拍板）

> **决策**：IMS 本期**不引入对象存储（OSS/MinIO/S3）**，**所有上传 / 产物 / 导出文件一律落 IMS 服务端文件目录**。

1. **落盘**：根目录由配置 `ims.file.storage.root` 指定（容器化时挂载持久卷；默认 `./data/ims-files`），按 `{scene}/{tenantId}/{yyyyMM}/{uuid}.{ext}` 归档。
2. **引用**：DB 存**相对路径** `fileKey`（如 `content/0/202610/8f3a….mp4`），**禁止**存绝对路径或主机名；对外**永不**暴露物理路径。
3. **读链**：统一 `GET /admin-api/ims/file/{fileKey}`（鉴权 + 租户校验 + 逻辑删除校验）返回文件流；复用 `ims_file` 元数据表（fileName/fileKey/fileSize/contentType/scene/sha256）。
4. **抽象保留**：后端 `StorageProvider` 接口 + 本期实现 `LocalStorageProvider`；未来切 OSS/S3 只换实现，**契约以 `fileKey` 定型、不绑定存储介质**（与 AIR `KbProvider` 保留抽象同法）。
5. **禁止**：① 前端直传 OSS 的"凭证模式"；② 契约/代码中出现 `oss_key`/`ossKey`/`ossUrl` 作为**本期**字段；③ IMS 写 OPS 本地盘或跨机共享盘。
6. **命名迁移**：凡历史文档写 `oss_key`/`ossKeys` 者，**本期语义一律为 `fileKey`（服务端相对路径）**、按 `file_key` 落库；`fileUrl` 为下载链接（指向第 3 点读链），**非**外链。

**错误码**：`5005` 语义同步调整为「**文件上传 / 落盘失败**」（号位不变）。

| 认证 | 钉钉 SSO（OAuth2 授权码）→ IMS JWT Bearer Token |
| 部署 | 容器化（前端 Nginx 静态 + 后端服务） |

### 7.2 请求约定

- **统一前缀**：`/admin-api/ims/`；移动端 `/app-api/ims/`（V1 不建设）；
- Axios 封装 `src/utils/request.ts`：自动携带 `Authorization: Bearer {token}`；响应拦截按 `CommonResult<T>` 解包；
- **幂等**：关键写接口（场次创建、冲话费登记）请求头携带 `clientToken`（UUID，重试复用同值），后端按 token 去重；
- 认证失败（401）统一跳 `GET /admin-api/ims/auth/sso/redirect` 重新发起钉钉授权。

### 7.3 工程约定

- 前端目录：`src/{api,enums,components,views,stores,utils}`；`src/api/types/{module}.ts` 与各模块 API 契约文档一一对应；
- 后端按域分包（auth/asset/account/cert/live/content/…），`cmd/api` 与 `cmd/worker` 入口分离；数据访问仅 sqlc，禁止 AutoMigrate 改现网表；
- 代码规范：前端 ESLint + Prettier（camelCase 强制），后端 `gofmt` / `go test`；调试用 Delve；
- Git 分支：`main`（受保护）/ `feature/{module}-{task}`，MR 评审合并。

### 7.4 数据约定（后端）

- 表名 `ims_` 前缀，主键 Snowflake BIGINT `id`，业务编码列唯一索引；
- 逻辑删除 `deleted` BIT(1)，全部业务表含六审计字段（creator/create_time/updater/update_time/deleted/tenant_id）；
- 多主体预留：`tenant_id` V1 恒 0 且接口不透出；
- 金额 DECIMAL(12,2)（单位元）；时间 DATETIME + ISO 8601 出参；
- 场次 ID 编码（V1 定死）：`IMS + yyyyMMdd + 3 位平台码 + 4 位当日序列`（如 `IMS20250401DYS0042`），Redis `INCR` 序列 + DB 唯一索引兜底 + `clientToken` 幂等（详见各 LIVE API 契约）。

## 7A. CI 硬门禁（B5 · 禁 OPS HTTP）

> **决策口径（用户 2026-10-05 拍板，本期落地）**：并入域（内容 / 采集 / 指标 / 监测）**直连 `oa_*` 同库**，**禁止**通过 OPS HTTP Client 调用；本规范以 **CI 硬门禁**强制该铁律（IR-02 / IR-03）。

### 7A.1 静态扫描规则（CI 必跑，失败即阻断合并）

- **扫描对象**：IMS 前后端全部源码与配置（含 `src/**`、后端 Go 包、`*.yml`/`*.yaml`/`*.properties`/环境变量模板）。
- **禁项一 · OPS host**：源码/配置中**不得**出现 OPS 服务的 host、域名或 IP（如 `ops.` 前缀域名、OPS 网关地址、OPS 服务名）。
- **禁项二 · `ops.` base-url**：**不得**出现任何指向 OPS 的 base-url / 前缀配置（如 `ops.base-url`、`*.ops.*` 域名端点、OPS HTTP Client 依赖）。
- **禁项三 · OPS HTTP 调用**：禁止新增 OPS HTTP Client / OpenFeign / RPC 调用 OPS 服务；并入域必须走**同库 `oa_*` 直连**（IR-01）。
- **外部 HTTP 白名单（三类 · 2026-10-05 修订）**：**仅**下列三类宿主目录可发起外部 HTTP，**其余外部 host 一律视为违规**（白名单制不变、其余一律阻断）：
  1. **Football WebAPI** —— 宿主**仅** `internal/pkg/football/**`（`FootballWebApiClient`），配置键 `football.webapi.*`（见《全局开发规范-完整版补充》§3 与 `产品规格/V1/FB-Football-WebAPI适配.md`）；
  2. **钉钉开放平台** —— 宿主**仅** `internal/pkg/dingtalk/**`，配置键 `dingtalk.*`（SSO 换票 + 组织事件订阅/增量同步**必需**，AUTH-001/AUTH-002；见《全局开发规范-完整版补充》§3.1）；
  3. **ComfyUI / jingcai** —— 宿主**仅** `internal/pkg/comfyui/**`、`internal/pkg/jingcai/**`，配置键 `comfy.*` / `jingcai.*`（§7.1 技术栈已列的**旁路进程**；见《全局开发规范-完整版补充》§3.1）。
- **变更注记（2026-10-05）**：原表述将外部 HTTP 白名单限为 **单一个 Football WebAPI**（并声明除此之外无其他外部 HTTP 依赖）——**不准确** —— §7.1 技术栈已含 `ComfyUI/jingcai HTTP`，且 AUTH-001/AUTH-002 依赖**钉钉开放平台**（SSO 换票 / 事件订阅），按原文会被 CI **误判阻断**。据 B5 口径**扩为三类**，与 §7.1 技术栈表、《全局开发规范-完整版补充》§3/§7 对齐；白名单制与「其余一律阻断」不变。
- **扫描结果处理**：命中任一禁项 → CI **红灯阻断 MR 合并**，不允许 `--no-verify`、跳过扫描或加豁免注释绕过；确需例外（如适配层集中封装）须经 ADR 评审登记后方可加入白名单。

### 7A.2 切流纪律（IR-03）

1. **验收通过后即停 OPS**：IMS 对应域验收通过后**停止 OPS 服务**，**禁止长期双写**（禁止 IMS 与 OPS 并行写同一业务库的过渡期常态化）。
2. **发现遗漏依赖 → 登记为「切流前必修项」**：扫描或联调中发现仍依赖 OPS 的点位，登记为**切流前必修项**，**不得带入验收**；必修项清零后方可执行停 OPS。
3. **本门禁与 IR-02/IR-03 绑定**：本 §7A 是 IR-02/IR-03 在工程侧的强制落地手段，规则冲突时以铁律为准。
