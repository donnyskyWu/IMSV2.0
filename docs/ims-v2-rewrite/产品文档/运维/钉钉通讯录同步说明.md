# 钉钉通讯录全量同步（PO 清单）

## 现象与 errcode

| 现象 | 含义 |
|------|------|
| **50004** | 请求的 **部门 id 不在「通讯录授权范围」内**（与开放平台「接口权限 / 通讯录只读」不是同一项） |
| 只同步 **1 个部门、少量用户** | 多为 **部分员工 / 指定部门** 授权，BFS 只能覆盖授权根下的子树 |
| 换 **Client ID（新应用）** 后失败 | 新应用的 **授权范围、发布状态** 需单独配置，不能沿用旧应用 |

IMS 同步入口：`POST /admin-api/ims/auth/org/sync-from-dingtalk`（R1）· 脚本 `ims-backend/scripts/run_dingtalk_org_sync.ps1` · 组织页「手动对账」。

## PO 配置清单（开放平台）

1. **接口权限**：通讯录相关只读权限已开通（部门、用户查询等）。
2. **通讯录授权范围**：建议 **全部员工**；若选「部分员工」，须包含需同步的 **根部门**（不必假设企业根为 `1`，以 `topapi/auth/scopes` 返回的 `authed_dept` 为准）。
3. **发布应用**：修改权限或授权范围后 **重新发布** 到企业。
4. **系统参数**（系统管理 → 系统参数，勿提交 git）：`dingtalk.clientId`、`dingtalk.clientSecret`、`dingtalk.corpId`、`dingtalk.agentId`、`dingtalk.appId` 与当前应用一致；Secret 轮换后仅在 UI 更新。

## 代码行为（#31 增强）

1. 同步前调用 **`topapi/auth/scopes`**，以 `authed_dept` 作为 BFS 起点（若该接口暂不可用如 **errcode 15**，自动回退探测 **`dept_id=1`**）。
2. 探测 **1** 仍 **50004** 时在 API 响应 `data.authScopeHint` 中返回运维提示。
3. BFS 子部门：先 **`v2/department/listsubid`**（`dept_id_list`），空则 **`v2/department/listsub`**（部门对象数组）；对 **50004** **跳过并记录**，不整批失败。
4. 响应诊断：`departmentsFetched` / `listsubCalls` / `subDepartmentIdsDiscovered` / `rootSubDeptIdCount`（授权根仅 1 个时）/ `firstApiError` / `partialScope`。若 **listsub 已调用** 且 **rootSubDeptIdCount=0**、无 50004，多为 **授权范围仅含根部门** 或组织下确实无子部门；若 **rootSubDeptIdCount>0** 但 **departmentsFetched** 仍很小，查 50004 跳过记录。

```powershell
powershell -NoProfile -File .\scripts\start_api.ps1 -KillPort

```
