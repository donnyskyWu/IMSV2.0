## 1. 概述

运营数据平台（OPS）挂在 Football 管理端侧栏 **「运营数据」** 下。本手册覆盖侧栏 **全部业务菜单**（含绩效、财务、配置、消息等）；数据采集菜单仅说明边界（第 17 章）。

日常主用途：

1. 按 **SOP 模板 + 赛事 + IP 组** 排期内容生产计划  
2. 执行人完成 **我的任务**，产出内容并提交审核  
3. 审核人完成 **内容审核**；运营执行 **平台发布** / **Football 上架**（两套状态，见第 6 章）  
4. 维护 **IP 组 / 账号资产**，做监测与人效/绩效/成本分析，接收 **钉钉 / 站内** 通知  

### 1.1 推荐主链路（日常）

```text
配置 SOP 节点（含 needReview）
    → 计划管理：选多 IP 组 + 赛事 → 启动计划
    → 我的任务：执行（内容生成节点须先提交内容审核）
    → 内容审核：一/二级通过 → 待发布
    → 内容管理：发布到平台账号；需要时再 Football 上架
```

### 1.2 角色速览（与菜单权限相关）

| 角色倾向 | 常见入口 |
|----------|----------|
| 执行人 | `/ops/production/task` 我的任务 |
| IP 组长 | `/ops/production/content/review` 一级审核；`/ops/operations/ip-group` |
| 运营经理 / 审核角色 | 二级审核、计划启停、系统参数 |
| 租户管理员 | 全菜单；系统参数 |

具体权限以登录后侧栏菜单与按钮为准（菜单权限来自库，非前端写死）。

## 3. 内容生产 · 计划管理

**入口路径**：侧栏 **运营数据 → 内容生产 → 计划管理**  
**URL**：`/ops/production/plan`

### 3.1 页面能做什么

| 操作 | 结果 / 状态 |
|------|-------------|
| 新建计划（草稿） | 计划 `DRAFT`；任务 `PLAN_DRAFT` 且不出现在「我的任务」列表 |
| 预览任务 | 按 **IP 组 × 节点 × 赛事** 预览，不写库 |
| 启动计划 | 计划 `IN_PROGRESS`；任务变 `PENDING`，出现在执行人「我的任务」 |
| 申请终止 | `TERMINATE_PENDING`（需具备终止审批岗位的人审批） |
| 删除 | **仅草稿**可删 |

### 3.2 新建计划（多 IP 组）

> 行为依据 ADR-070：一次计划可选 **多个 IP 组**，各组共用同一 SOP 模板与赛事池。

**步骤**：

1. 打开 `/ops/production/plan`，点 **新建**。  
2. 填写计划名称、起止日期；选择 **SOP 模板**（创建后不可改模板）。  
3. **IP 组**：多选（至少一个）。  
   - 保存后 IP 组集合 **锁定**；草稿编辑也不能增删 IP 组，需要换组请删草稿重建。  
4. 从赛事选择器勾选赛事池（展示名会进任务名）。  
5. 为每个 SOP 节点指定执行人（须属于所选 IP 组**并集**的成员或组长）。  
6. 可选：点 **预览任务**，核对将生成的任务行（含各组名）。  
7. **保存** → 得到草稿计划。

**任务命名规则**（系统自动）：

```text
{赛事名称}-{节点名称}
```

例：`英超-曼联 VS 切尔西-2026-06-12 20:00-赛前前瞻文案`。  
若缺赛事名则退化为仅节点名。

**任务数量（步骤模式）**：约 `|IP组| × |赛事| × |节点|`（当前 UI 每节点单执行人）。

### 3.3 启动计划

1. 在列表打开草稿计划详情。  
2. 点 **启动**。  
3. **结果**：执行人收到待办；「我的任务」出现对应任务；钉钉/站内可能推送 `TASK_PENDING`（需已配置钉钉，见第 8 章）。

### 3.4 多 IP 组执行时的 Tab

同一计划、同一节点、同一赛事下，各组会有并行任务。进入某一任务的执行页时，若存在兄弟任务，页面提供 **IP 组 Tab**，可切换查看各组进度与关联内容。

### 3.5 终止计划

1. 进行中计划点 **终止**（可填原因）→ `TERMINATE_PENDING`。  
2. 具备审批资格的用户 **通过** → 计划与关联任务 `TERMINATED`；**驳回** → 回到进行中。

## 4. 内容生产 · 我的任务 / 全部任务

| 页面 | 入口 | URL |
|------|------|-----|
| 我的任务 | 内容生产 → 我的任务 | `/ops/production/task` |
| 全部任务 | 内容生产 → 全部任务 | `/ops/production/task/all` |

### 4.1 任务状态（执行人视角）

| 状态 | 含义 | 执行人可做什么 |
|------|------|----------------|
| `PENDING` | 待开始 | 进入执行（自动变为进行中） |
| `IN_PROGRESS` | 进行中 | 保存交付物、完成任务 |
| `PENDING_REVIEW` | 待任务级审核 | 等待审核人（仅节点 `needReview=1`） |
| `DONE` | 已完成 | 只读 |
| `PLAN_DRAFT` | 计划未启动 | **列表默认不可见** |
| `TERMINATED` | 已终止 | 只读 |

### 4.2 执行任务（内容生成节点）

适用于 SOP 节点类型 = **内容生成**（`CONTENT_GENERATION`）。

**步骤**：

1. 打开 `/ops/production/task`，点任务进入 **执行页**。  
2. 在执行页进入 **内容创作**（系统按任务创建/关联一条内容，带赛事与 IP 组）。  
3. 编辑正文（付费/免费栏等以页面为准）→ **保存**（内容多为草稿）。  
4. 在内容侧点 **提交审核**（进入内容审核流，见第 6 章）。  
5. 回到任务执行页点 **完成**：  
   - **门禁**：关联内容不能仍是 `DRAFT` / `REJECTED`，须已提交审核或之后的状态。  
   - 若任务/节点 `needReview=1` → 任务进入 `PENDING_REVIEW`（任务级审核）。  
   - 若 `needReview=0` → 任务直接 `DONE`。

> **常见卡点**：内容还在草稿就点任务「完成」→ 提示内容未完成/未提交，需先提交内容审核。

### 4.3 普通节点 / 发布类节点

| 节点类型 | 完成时注意 |
|----------|------------|
| 普通节点 `NORMAL` | 按页面填写交付物后完成；无「关联内容」门禁 |
| 内容发布 `CONTENT_PUBLISH` | 按页面指引操作（与内容管理发布配合） |

### 4.4 `needReview` 从哪里来？

- 在 **SOP 管理** 编辑节点时打开「需要审核」，并选择审核岗位。  
- 计划生成任务时会把该标记带到任务上。  
- **仅当 needReview=1** 时，完成任务才会进入 `PENDING_REVIEW`；否则完成即 `DONE`。

## 5. 内容生产 · 内容管理

**入口路径**：侧栏 **运营数据 → 内容生产 → 内容管理**  
**URL**：`/ops/production/content`

### 5.1 列表与筛选

可按状态、IP 组、赛事、标题等筛选（以页面筛选项为准）。  
任务驱动产生的内容带 `taskId` / 赛事快照；也可独立新建内容（无任务时）。

### 5.2 编辑与提交审核

**步骤**：

1. 打开内容（弹窗或编辑页）。  
2. 填写标题、正文、文档类型（文章类）、售卖相关字段等。  
3. **保存** → 仍为草稿类状态。  
4. **提交审核** → 按租户「内容审核」系统参数进入一级/二级待审，或直接到 **待发布**（见第 6、8 章）。

### 5.3 文章排版（文章类 · ARTICLE）

编辑页工具栏提供三种排版能力，**正文文字均不会被系统改写**（仅套版式）：

| 入口 | 是否调用 LLM | 典型场景 |
|------|-------------|----------|
| **一键排版** | 否 | 快速套用竞彩营销/简洁通读/赛事分析/付费引流四套预设 |
| **AI 排版** | 是（需配置 AI 模型） | 语义理解正文结构，自动选决策扫读版或情报分析版 |
| **选择版式模板** | 否 | 从公推模板库选手动维护的版式 |

**一键排版步骤**：

1. 写好标题与正文（付费区/免费区按页面分栏）。  
2. 点 **一键排版** → 选择风格卡片（默认竞彩营销版）→ 等待预览。  
3. 确认 **使用此排版** → 编辑器刷新为富版式 HTML。  
4. **仅免费区有内容** 时，只更新免费栏，付费区不变。

**AI 排版步骤**：

1. 确保 **配置管理 → AI 模型** 中已有 **CONNECTED** 的 Chat 模型（见 §15.1）。  
2. 点 **AI 排版** → **AI 排版预览** → 对比排版前后 → **应用排版**。  
3. 低置信度或部分段落降级映射时，页面会提示，仍可确认应用。

**选择版式模板**：见 §10.4.4；仅免费区有正文时套用目标为免费栏。

### 5.4 玩法与赛程（竞彩方案）

文章编辑页可绑定 **N 场赛程 + 竞彩玩法**（与 Football 发布方案同构）。保存后同步至 Football 方案；**未选玩法** 的草稿仍可保存，Football 侧收到空数组而非报错。

### 5.5 两套「发布」不要混

| 概念 | 存在哪里 | 操作入口 | 效果 |
|------|----------|----------|------|
| OPS 工作流状态 | `oa_production_content.status` | 审核通过 → **待发布** → **发布** | 选平台账号做 OPS 侧发布记录 |
| Football 上架 | `author_article.status`（`shelfStatus`） | 内容详情中的上架/下架 | APP/H5 是否可见 |

审核通过 **不会**自动 Football 上架；需单独上架（ADR-054）。

## 6. 内容生产 · 内容审核与发布/上架

### 6.1 内容审核页

**入口路径**：侧栏 **运营数据 → 内容生产 → 内容审核**  
**URL**：`/ops/production/content/review`  
可带阶段参数：`/ops/production/content/review?stage=FIRST` 或 `stage=SECOND`（钉钉跳转常用）。

**步骤**：

1. 打开审核页，切换 **一级审核 / 二级审核** Tab（随系统参数启用情况显示）。  
2. 打开待审内容，核对正文与审核流程 steps（角色 + 可审人姓名）。  
3. **通过** 或 **驳回**（驳回 → `REJECTED`，流程结束，执行人需改稿后重新提交）。

### 6.2 审核级数怎么决定下一状态？

由系统参数配置（第 8 章），逻辑要点：

| 一级 | 二级 | 提交审核后 | 末级通过后 |
|------|------|------------|------------|
| 开 | 开 | 待一级 | 待二级 → **待发布** |
| 开 | 关 | 待一级 | **待发布** |
| 关 | 开 | 待二级 | **待发布** |
| 关 | 关 | **待发布**（跳过审核） |

> 末级审核通过进入 **待发布（`PENDING_PUBLISH`）**，**不会**自动点「发布」。

### 6.3 一级审核范围（IP 组长）

当一级角色配置为 IP 组长类角色时：审核人只能审 **自己担任组长的 IP 组** 下的内容，而不是全租户所有待审单。

### 6.4 OPS 发布（待发布 → 已发布）

**前提**：内容状态 = `PENDING_PUBLISH`，且账号已开启发布能力。

**步骤**：

1. 在内容管理打开该内容。  
2. 点 **发布**，按提示选择平台与账号（来自可发布账号列表）。  
3. **结果**：全部成功后 OPS 状态变为已发布类状态；每账号有发布记录。

### 6.5 Football 上架 / 下架

**前提**：内容已与 Football 方案同步（详情可见 `authorArticleId` / 同步状态）。

**步骤**：

1. 打开内容详情，查看 **上架状态**（草稿 / 下架 / 已上架）。  
2. 执行 **上架** 或 **下架**。  
3. **结果**：`shelfStatus=1` 时 APP/H5 可见；与 OPS「是否已点发布」相互独立。

## 7. 运营管理

侧栏目录：**运营数据 → 运营管理**。含 IP 组维护与内部账号/粉丝/作品/人效分析。

### 7.1 IP 组管理

**入口路径**：运营管理 → **IP组管理**  
**URL**：`/ops/operations/ip-group`

**用途**：维护大组/小组树；指定组长与成员岗位；关联账号/作者；作为计划、任务范围与一级审核范围的基础。

**新建大组 / 小组**：

1. 打开 IP 组管理。  
2. **新建大组**，或选中大组后 **新建小组**。  
3. 填写名称、等级等 → 保存。  
4. 在 **成员** Tab 添加成员并设岗位；指定组长。  
5. **结果**：组进入计划多选与数据权限范围。

**与计划**：计划可多选 IP 组；执行人须在所选组并集内；组长视作该组成员。

### 7.2 账号分析

**URL**：`/ops/operations/account-analysis`

**步骤**：切换平台 Tab → 设 IP 组/时间等筛选 → 查询 → 看汇总与表格 → 需要时 **导出**。  
**结果**：内部账号维度的粉丝/表现等列表（空数据表示周期内无统计）。

### 7.3 粉丝分析

**URL**：`/ops/operations/fans-analysis`

**步骤**：选 IP 组、平台、时间维度与日期 → 查询 → 看趋势/明细 → **导出**。  
**结果**：粉丝增减与结构视图；依赖内部账号粉丝日统计。

### 7.4 内部作品分析

**URL**：`/ops/operations/internal-content`

**步骤**：筛选平台/IP/日期 → 查询列表 → 点行进详情（若有）。  
**结果**：内部已发布/同步作品的数据复盘（与作品监测「外部竞品」视角不同）。

### 7.5 人效盘点

**URL**：`/ops/operations/efficiency`

**步骤**：

## 9. 常见问题

### Q1. 计划保存了，我的任务里没有？

- 计划仍是 **草稿**：先 **启动**。  
- 任务还在 `PLAN_DRAFT` 且列表隐藏：启动后应变为 `PENDING`。  
- 当前登录人不是任务执行人：到「全部任务」或换账号查看。

### Q2. 任务完成按钮报错 / 提示内容未完成？

内容生成节点要求：关联内容已 **提交审核**（或已处于审核中/待发布/已发布等非草稿、非驳回状态）。先在内容侧提交审核再完成任务。

### Q3. 为什么任务名是「赛事-节点」？

系统按 `{competitionName}-{nodeName}` 自动生成，便于按赛事检索；无需手填。

### Q4. 多选了几个 IP 组，任务怎么这么多？

步骤模式下每个 IP 组都会为每个「节点×赛事」生成任务。预览任务清单可先确认再保存。

### Q5. 草稿计划想换 IP 组？

编辑 **不能**改 IP 组集合。删除草稿后重建。

### Q6. 审核通过了，APP 还看不见？

审核/OPS 发布只推进 OPS 工作流。请到内容详情检查 **Football 上架状态**，执行上架。

### Q7. 钉钉消息点开 404 或跳错站？

检查 `notification.platform-base-url` 是否为当前前端根 + `/ops`，且 **不要**再拼多余 `#`。本地应为 `http://127.0.0.1:5777/ops` 一类。

### Q8. 一级审核列表是空的，但别人说有待审？

若你是 IP 组长角色：只能看到 **自己组** 的待审。跨组内容需对应组长或具备全量审核角色的账号处理。

### Q9. 数据采集 / 外部 SSO 登录页怎么用？

本期手册 **不覆盖** Phase 2 Out of Scope 能力；请勿按未上线菜单编写操作流程。

### Q10. 计划里选不到 SOP 模板？

模板须为 **启用** 状态。停用模板不会出现在计划可选池（以页面下拉为准）。侧栏「SOP审核」审的是 **任务**（节点 needReview），不是模板启用开关。

### Q11. 内容创作里选不到公推模板？

公推模板须已 **发布/启用**。停用后不可在内容创作中选择；已套用到内容的历史版式不受影响。

### Q12. 爆款 / 监测页一直没数据？

监测页读已入库的外部作品/账号快照。无采集落库或播放量未达阈值时列表为空属正常。本手册不展开 M10 采集配置；有数据后再用第 12 章页面查看。

## 10. 内容生产 · SOP / 知识库 / 公推模板

### 10.1 SOP 管理

**入口路径**：侧栏 **运营数据 → 内容生产 → SOP管理**  
**URL**：`/ops/production/sop`

页面含两个 Tab：**SOP模板列表**、**待审核任务**（节点 needReview 产生的任务审核队列；详见 §10.2）。

#### 10.1.1 新建模板

1. 打开 `/ops/production/sop`，确认在 **SOP模板列表** Tab。  
2. 可按模板名称、内容类型、启用/停用筛选。  
3. 点 **新增模板**，填写模板名称、内容类型、描述 → 确定。  
4. **结果**：列表出现新模板；进入编辑画布配置节点。

#### 10.1.2 编辑画布（节点与边）

**入口**：列表点模板名称 / 编辑 → SOP 编辑页。

**步骤**：

1. 从左侧 **节点库** 拖拽节点到画布（或使用添加入口）。  
2. 选中节点，在右侧属性面板填写：  
   - 节点名称、**节点类型**（内容生成 / 内容发布 / 普通节点）  
   - **执行岗位**（必填）  
   - **是否需要审核**；打开时须选 **审核人岗位**  
   - 可选：前置节点、并行组、SLA 小时、执行说明  
3. 用连线表达先后依赖；可用 **校验 DAG** 检查是否有环。  
4. 点 **保存**（或 Ctrl+S）。  
5. **结果**：Toast「保存成功」；节点/边写回模板。未保存直接返回会丢失本次画布改动。

> **注意**：需要审核却未选审核人岗位时，保存会失败并提示补全。

#### 10.1.3 启用 / 停用模板

1. 在列表状态列切换启用开关（或等价操作）。  
2. **结果**：`启用` 可供计划选择；`停用` 后新计划不应再选用该模板。

#### 10.1.4 删除模板

1. 列表点删除并二次确认。  
2. **结果**：模板删除；已被计划引用的历史数据以系统校验为准（若被占用会提示不可删）。

### 10.2 SOP 审核（任务级，非模板审批）

> 这里审的是：**节点 `needReview=1` 的任务**完成后门禁产生的待审单（见第 4 章），**不是**「SOP 模板本身」的上架审批。  
> 模板能否被计划选用，看模板列表的 **启用/停用**。

**入口路径**（二选一）：

| 入口 | URL / 位置 |
|------|------------|
| SOP 管理 → Tab **待审核任务** | `/ops/production/sop`（推荐，接真实待审 API） |
| 侧栏 **SOP审核** | `/ops/production/sop/review` |

**步骤**：

1. 打开待审队列（优先用 SOP 管理页「待审核任务」Tab）。  
2. 按状态等条件筛选；打开一条 `PENDING` 记录，核对计划名、节点名、提交时间。  
3. 填写意见 → **审核通过** 或 **驳回**。  
4. **结果**：  
   - 通过：关联任务 → `DONE`  
   - 驳回：关联任务回到 `IN_PROGRESS`，执行人按意见返工后再完成  

> **已知缺口**：独立页 `/ops/production/sop/review` 前端仍可能带演示/本地样例数据；以「待审核任务」Tab 的真实队列为准。

**入口路径**：侧栏 **运营数据 → 内容生产 → 内容知识库**  
**URL**：`/ops/production/knowledge`

1. 打开 `/ops/production/knowledge`。  
2. 点 **新增知识**。

#### 10.3.2 查询与维护

1. 按分类、是否公开、关键词筛选。

用途：管理公众号推文 **版式**（非 SOP 流程、非 AI 提示词）。内容创作中「选择版式模板」从此库取已启用模板。

#### 10.4.1 新建模板

2. 填写模板名称、文档子类型（可选）。

**步骤**：

3. 在预览中确认版式；必要时看解析警告。

5. **结果**：生成模板记录；再按列表操作发布/启用后供创作选用。

> 链接抓取若遇微信验证，改用粘贴 HTML 或 MHTML。

#### 10.4.3 发布 / 停用 / 删除

| 预览 | 打开预览 | 只读查看版式 |

#### 10.4.4 在内容中套用

1. 打开内容编辑（文章类）。  
2. 使用 **选择版式模板**（或等价入口）。  
3. 确认套用。  
4. **结果**：版式槽位合并到当前内容；正文文字按产品规则保留（`LayoutMergeFidelityGate` 校验）。仅免费区有正文时只套用免费栏。

## 12. 作品监测 / 数据分析常用页

### 12.1 使用前提（请先读）

| 说明 | 操作含义 |
|------|----------|
| 监测页展示 **已落库** 的外部/竞品数据 | 无数据时先确认是否已有采集入库，而不是反复刷新空表 |
| 爆款默认门槛高 | 播放量未达阈值时爆款页为空，可先看外部账号/作品列表或调高阈值控件（页内允许时） |
| 本章 **不写** M10 采集全流程、外部 SSO 登录 | 避免把未交付能力写成标准操作 |

通用操作模式：选筛选条件 → 查询 → 看汇总卡/图表/表格 → 点行开详情抽屉 → 需要时导出。

## 13. 绩效核算

侧栏目录：**运营数据 → 绩效核算**。  
（**人效盘点**在运营管理菜单，见 §7.5；订单侧 ROI 也可在本模块「订单归因」内查看。）

### 13.1 推荐链路

```text
考核模板（配置指标与权重并启用）
  → 考核执行（创建考核 → 自动计算 → 确认结果）
  → 绩效结果（查询/导出/个人趋势）
订单归因：核对成交与投入 → ROI 分析 Tab
```

### 13.2 考核模板

**URL**：`/ops/performance/perf-template`

**步骤**：

1. 按岗位、名称、生效状态筛选。  
2. **新增模板**：填写模板名称、适用岗位；添加指标（选择指标定义、权重、计算方式、评分标准区间）。  
3. 权重合计建议为 100%；保存。  
4. 点 **启用**：同岗位旧生效模板会自动停用（有确认框）。可再 **停用**。  
5. **结果**：仅「生效」模板出现在「创建考核」的模板下拉中。

### 13.3 考核执行

**URL**：`/ops/performance/perf-execution`

**步骤**：

1. 按 IP 组、考核对象、周期、状态筛选列表。  
2. 点 **创建考核**：选择已生效模板、考核对象、周期等 → **确认创建**。  
3. **结果**：创建成功后系统自动计算指标得分；状态可能为计算中/待确认等（以列表字典为准）。  
4. 打开详情：核对得分；可 **重新计算**；核对无误后 **确认考核结果**（确认后不可再改）。  
5. **结果**：记录进入已确认态，供绩效结果页汇总。

### 13.4 绩效结果

**URL**：`/ops/performance/perf-result`

**步骤**：按人员/周期/IP 等筛选 → 查看得分与等级 → **导出 Excel**；需要时进入个人趋势页。  
**结果**：已确认考核的汇总视图；导出任务创建后按系统提示下载。

### 13.5 订单归因分析

**URL**：`/ops/performance/order-attribution`

**步骤**：

1. 打开页面，查看 ROI 汇总卡（成交、投入成本、ROI=成交/成本 等，以页内文案为准）。  
2. 在订单列表 Tab 按条件筛选订单，点行看详情。  
3. 切换 **ROI分析** Tab：按维度查看投入成本与 ROI；可 **导出**。  
4. **结果**：订单归因明细 + ROI 对比；无订单/成本数据时汇总为 0 或空表属正常。

## 14. 财务管理

**URL**：`/ops/finance/account-cost`

5. **结果**：财务视角的投入产出对比；与订单归因 ROI、账号成本详情互补。

## 15. 配置管理

### 15.1 AI 模型

**URL**：`/ops/config/config-ai-model`

**步骤**：查询列表 → **新增模型**（名称、供应商、endpoint、model 名、API Key 等）→ **测试连接** → 保存 → **启用**。  
**结果**：

| 能力 | 模型来源 | 说明 |
|------|----------|------|
| **AI 内容生成 / 润色** | 默认 jingcai.article（`FOOTBALL_AI_*` 环境变量） | 玩法组包由 OPS 完成；降级时可切 M8 直连 LLM |

生产环境 jingcai 相关变量见 `docs/deploy/ops-greenfield-production/config/env-variables.md`（`FOOTBALL_AI_SCHEME_*`、`FOOTBALL_AI_MODEL`）。

### 15.2 AI 提示词

**URL**：`/ops/config/config-ai-prompt`

**步骤**：

1. 按名称等筛选 → **新增模板**。  
2. 填写模板名称、场景、正文（可用 `{{变量名}}` 占位）、变量说明 → 启用并保存。  
3. 可查看、停用、删除（含批量删除，以按钮权限为准）。  
4. **结果**：内容创作「AI 生成」按文档类型/赛事等匹配提示词。

### 15.3 阈值规则配置

**URL**：`/ops/config/config-threshold`

**步骤**：

1. 切换 Tab：**预警阈值** / **粉丝阈值** / **作品阈值**。  
2. **新增规则**：填写阈值类型与数值；粉丝类填高粉/低粉；作品类填爆款/低分阈值；可勾选通知渠道（如站内消息）。  
3. 保存后 **启用/停用**；账号级覆盖优先于全局（页内说明）。  
4. **结果**：影响监测告警与钉钉/站内阈值类通知（第 8 章）。

### 15.4 元数据维护

**URL**：`/ops/config/config-metadata`

**步骤**：

1. **新增元数据**：从未映射物理表中选择 → 创建并自动导入字段。  
2. 编辑实体说明；进入字段配置，为各字段选择「指标查询条件类别」（枚举须选字典类型）。  
3. **保存字段配置**。  
4. **结果**：指标管理 / 自定义查询可自动渲染对应筛选控件。

### 15.5 内部采集配置

**URL**：`/ops/config/config-internal-collect`

**步骤**：按平台 Tab（公众号/抖音/…/企微/个微）维护账号凭证或奥创配置 → **保存** / 新增账号绑定。

### 15.6 外部采集配置

2. **关键词** Tab：新增监测关键词 → 启用。  
3. 公众号外部采集若需 Cookie，按页内提示到系统参数「采集配置」或凭账号维护（以页面 Alert 为准）。  
4. **结果**：外部账号/关键词进入配置库，供监测数据落库链路使用（执行层见附录 B）。

### 15.7 外部数据配置

**URL**：`/ops/config/config-external-data`

**步骤**：查询 → **新增数据源**（名称、类型、连接/映射字段等，以表单为准）→ 启用/停用。  
**结果**：外部数据源登记完成，供约定的数据接入使用。
