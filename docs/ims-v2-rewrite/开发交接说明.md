## 4. 工作方法

- **螺旋迭代**：阶段评审通过即提测（交小红/小蓝），开发并行开下一模块；阻塞修复优先于新开发；门槛不降；函数体只有 `pass` 的空壳、只做字符串匹配的用例不算通过。
- **一个模块（一个阶段）一个 PR**；修复类走单独小 PR；**永不直接推 main**。
- **测试**：E2E 全部用 Playwright，必须全过；覆盖率 总行 ≥80%、P0 Service 分支 ≥90%（CI 强制 P0 分支门槛）；接口层 pytest + FastAPI TestClient。
- **流程**：代码评审（只对照 PR diff + 工作包/文档）→ 小红功能验收 + 小蓝 CI/覆盖率验收 → squash 合并。
- 非阻塞项三关通过后可自主合入；阻塞项和产品裁决上报 who kong。
- 决定写进仓库文档（ADR/工作包/看板），群里只发一句"已更新 xx 文件"。Spec 未写明的停下列阻塞问题，不推断。
- 看板：完成一项就在同一个 PR 里改自己那一行。

## 5. 本地开发指南（Cursor）

```bash
git clone https://github.com/donnyskyWu/IMSV2.0 && cd IMSV2.0   # 已有则：git checkout main && git pull
git checkout -b cursor/<批次>-<简述>        # 现有惯例如 cursor/b1-login-password-frontend-6702；文档用 docs/<简述>
```

后端（`ims-backend/`，需 MySQL 8 + Redis 7，连接串只放环境变量 `IMS_DB_URL`、`IMS_REDIS_URL`）：
```bash
make install                 # pip install -e ".[dev]"
make lint                    # ruff + mypy
pytest tests/ --cov=app --cov-branch     # 覆盖率
python -m tools.seed --env e2e           # 种子数据
```

前端（`ims-web/`）：
```bash
npm ci
npm run dev                  # Vite；后端地址用 VITE_API_PROXY_TARGET
npm run lint
npx playwright install --with-deps chromium webkit
npx playwright test --project=desktop-chromium --project=mobile-390-chromium --project=mobile-390-webkit --project=prod-build
npm run test:live-proxy      # 真实后端联通
```

提 PR：推分支后在 GitHub 向 `main` 开 PR，正文写清对应工作包功能点/用例编号与覆盖率口径；同 PR 更新看板自己那一行；等评审 + 小红 + 小蓝通过后 squash 合并。
