## 1. 批次顺序总览

顺序：**框架（B0a）→ 前端基础层（B0b）→ 模块批次 B1～B29 → UAT 系统测试**。B0a、B0b 合起来就是 03 清单的 B0，模块批次编号与 03 清单的 B1～B29 一一对应。批次**严格串行**：一个批次只交给一个编码会话，不多路并行（见第 3 节）。**已采用重叠方案（zhang wu 2026-10-12）**：下一批的编码可以在本批“回归已登记 bug”期间开始，但任何时刻只有一个编码会话在写代码，前提与 bug 协调办法见第 5.5 节。

每个批次的统一流程：

```
开工关口（功能点清单 + 业务 E2E 用例 → zhang wu 审过）
  → 开发（脚手架生成骨架 → 按功能点实现 → 接口单测 + 路由冒烟）
  → 【提测节点】部署测试环境，Grok Bot 发提测说明
  → 测试工程师 B、C 按业务 E2E 用例执行，只截失败用例、登记 bug
  → 【测试结论节点】Grok Bot 发测试结论
  → 按模块攒批修复 → 部署（每天 1～2 次）→ 只回归已登记的 bug
  → 【部署节点】Grok Bot 发部署说明 → 批次关闭
```

重叠后的衔接（第 5.5 节）：本批攒批修复部署完成 → 下一批编码会话开工（下一批评审须已通过）‖ 本批回归已登记 bug → 本批关闭 → 下一批提测。

**提测节点的统一标准**（每批相同，下表不再重复）：① 本批功能点清单中的功能全部实现；② 接口单测全部通过；③ 路由冒烟通过（本批所有页面路由可打开、主接口返回 200 / 正确业务码、无权限用户看不到菜单）；④ 已部署到测试环境，种子数据与测试账号就绪；⑤ 提测说明写明范围、已知限制、模拟接口清单。

## 4. UAT 系统测试（全部模块完成后）

### 4.1 测试内容
